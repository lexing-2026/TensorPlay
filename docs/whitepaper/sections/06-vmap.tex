\section{向量化映射：批量变换与变换分发}
\label{sec:vmap}

% Coverage: DispatchKey Vmap at offset 9 and priority; PushVmapMode/PopVmapMode level; Vmap->Autocast->Autograd->Backend

Vmap 将为单个样本编写的函数转换为可批量运行的函数，而无需重写其主体。公共入口点是 \texttt{tensorplay.func.vmap}，它委托给 \texttt{tensorplay.\_transforms.vmap.vmap\_impl} 并最终委托给 \texttt{p10} 中的本机层：\texttt{push\_vmap} / \texttt{make\_batched} / \texttt{unwrap\_at\_level}。参与 vmap 的每个运算符都有一个在 \texttt{Vmap*} 调度键下注册的每个后端批处理规则，没有规则的运算符在生成的代码中会快速失败。 vmap 的调度键优先于所有其他键，因此 \texttt{TransformDispatch} 在 \texttt{Autocast} 或 \texttt{Autograd} 看到操作数之前展开。

\subsection{偏移量 9 处的调度密钥和优先级}
\label{sec:vmapkey}

定义了 13 个具有固定数值的键。 vmap族被放置在offset~9处：

\begin{lstlisting}[caption={13 keys, Vmap at offset~9.}, label=lst:vmapkeys]
enum class DispatchKey : uint8_t {
  CPU=0, CUDA=1, Vulkan=2,
  AutogradCPU=3, AutogradCUDA=4, AutogradVulkan=5,
  AutocastCPU=6, AutocastCUDA=7, AutocastVulkan=8,
  VmapCPU=9, VmapCUDA=10, VmapVulkan=11,
  Composite=12, EndOfKeys=13
};
constexpr size_t kBackendKeyCount=3, kAutogradKeyOffset=3, kAutocastKeyOffset=6, kVmapKeyOffset=9;
\end{lstlisting}

助手 \texttt{toVmapKey}、\texttt{is\_vmap\_key} 和 \texttt{toBackendKey} 是 \texttt{constexpr}。 \texttt{DispatchKeySet} 是一个 \texttt{uint32\_t} 位掩码，具有 \texttt{has} 和 \texttt{highest\_priority\_key}，从最高有效设置位向下扫描；因为 vmap 占据 9--11，所以它总是胜过 autocast (6--8)、autograd (3--5) 和 backend (0--2)。 Table~\ref{tab:vmappriority} 使排序更加明确。

将 \texttt{is\_vmap\_key} 定义为半开区间 \texttt{[kVmapKeyOffset, kVmapKeyOffset+kBackendKeyCount)}； \texttt{toVmapKey(backend) = backend + 9} 和 \texttt{toBackendKey(vmap) = vmap - 9}。 \texttt{DispatchKeySet::remove\_vmap} 准确地清除这三个位，在 vmap 层下方重新调度时使用。 \texttt{DispatchTable} 有 \texttt{array<atomic<void*>,13>} 插槽，因此每个 vmap 键都有自己的列； \texttt{OperatorHandle::getKernel} 仅针对后端键咨询 \texttt{Composite}，而不是针对 vmap 键，因此缺少 vmap 内核是一次严重失误，而不是静默回退。

\subsection{TensorImpl 批处理状态：\texttt{transform\_value\_} 包装器}
\label{sec:batchstate}

批处理状态作为三个字段存在于 \texttt{TensorImpl} 中，与存储、版本和稀疏元数据分开：

\begin{lstlisting}[caption={batching fields.}, label=lst:batchfields]
std::shared_ptr<TensorImpl> transform_value_;
int64_t transform_batch_dim_ = -1;
int64_t transform_level_ = -1;
bool is_batched() const { return transform_value_ != nullptr; }
int64_t batch_dim() const { return transform_batch_dim_; }
int64_t batch_level() const { return transform_level_; }
int64_t batch_size() const {
  return is_batched() ? transform_value_->size(static_cast<size_t>(transform_batch_dim_)) : 0;
}
\end{lstlisting}

包装构造函数采用物理 \texttt{shared\_ptr<TensorImpl> value} 加上逻辑 \texttt{strides}：

\begin{lstlisting}[caption={wrapper construction.}, label=lst:wrapperctor]
TensorImpl::TensorImpl(std::shared_ptr<TensorImpl> transform_value,
                       const std::vector<int64_t>& sizes,
                       const std::vector<int64_t>& strides)
  : storage_offset_(0), sizes_and_strides_(sizes, strides),
    dtype_(transform_value ? transform_value->dtype() : DType::Undefined),
    device_(transform_value ? transform_value->device() : Device(DeviceType::CPU)),
    is_contiguous_(sizes_and_strides_.is_contiguous()),
    transform_value_(std::move(transform_value)) {
  shared_state_ = std::make_shared<SharedState>();
}
\end{lstlisting}

公共形状是逻辑形状（没有批量维度）；物理形状位于 \texttt{transform\_value\_} 中。视图和副本保留了区别：\texttt{TensorImpl(const TensorImpl\& other)} 复制 \texttt{level\_}，而 \texttt{share\_version\_counter} 是批处理包装器共享的 \emph{not}——批处理与版本控制正交。逻辑 \texttt{sizes\_and\_strides\_} 根据批处理规则的结果重新计算；物理张量永远不会被别名为公共张量。

\texttt{TensorImpl::key\_set} 动态计算调度键并通过提前返回赋予 vmap 优先级：

\begin{lstlisting}[caption={computed key set, vmap first.}, label=lst:keysetvmap]
DispatchKeySet key_set() const {
  DispatchKey backend = computeDispatchKey(device_);
  DispatchKeySet ks;
  if (is_batched()) {
    ks.add(toVmapKey(backend));
    return ks;
  }
  ks.add(backend);
  if (!inference_tensor_) {
    ks.add(toAutogradKey(backend));
  }
  return ks;
}
\end{lstlisting}

当 \texttt{is\_batched} 集合仅包含 \texttt{Vmap*} 位时，因此如果任何参数被批处理，则 \texttt{dispatchKeyForTensorArgs} 将选择 vmap 键，无论存在多少个未批处理的参数。表~\ref{tab:batchfields} 总结了字段语义。

\subsection{变换堆栈：推入/弹出和级别}
\label{sec:transformstack}

嵌套 vmap 通过每线程级别堆栈消除歧义：

\begin{lstlisting}[caption={layer stack.}, label=lst:layerstack]
enum class Randomness : uint8_t { Error=0, Same=1, Different=2 };
enum class Kind : uint8_t { Vmap=0, Grad=1, Jvp=2, Functionalize=3 };
struct Layer {
  Kind kind = Kind::Vmap;
  int64_t level = -1;
  int64_t batch_size = 0;
  Randomness randomness = Randomness::Error;
  bool previous_grad_mode = true;
  bool previous_forward_grad_mode = true;
  bool add_back_views = false;
};
P10_API int64_t push_vmap(int64_t batch_size, Randomness randomness);
P10_API Layer pop_layer();
P10_API std::optional<Layer> current_layer();
P10_API std::vector<Layer> layer_stack();
\end{lstlisting}

该实现是一个线程局部向量加上一个单调计数器：

\begin{lstlisting}[caption={stack and levels.}, label=lst:pushpop]
namespace { thread_local std::vector<Layer> layers; thread_local int64_t next_level = 0; }

int64_t push_vmap(int64_t batch_size, Randomness randomness) {
  if (batch_size < 0) TP_THROW(ValueError, "vmap batch size must be non-negative");
  Layer layer; layer.kind = Kind::Vmap; layer.level = next_level++;
  layer.batch_size = batch_size; layer.randomness = randomness;
  layers.push_back(layer); return layer.level;
}
Layer pop_layer() {
  if (layers.empty()) TP_THROW(RuntimeError, "cannot pop an empty transform stack");
  Layer layer = layers.back(); layers.pop_back(); return layer;
}
\end{lstlisting}

级别永远不会在线程内重用：即使在 \texttt{pop\_layer} 之后，\texttt{next\_level} 也会不断递增。当批量张量超过其层的寿命（例如，在闭包中捕获）时，这可以防止 ABA 混淆。 \texttt{is\_batched\_at\_level(value, level)} 检查指针和确切级别，因此外部 vmap 的张量对于内部 vmap 的规则是不可见的。

Python 保护 \texttt{vmap\_increment\_nesting} 压入、产生级别，然后弹出 \texttt{finally} 块，该块还恢复 \texttt{ContextVar} 深度计数器。任务描述中的名称\texttt{PushVmapMode}/\texttt{PopVmapMode}映射到代码中的\texttt{push\_vmap}/\texttt{pop\_layer}； “模式”措辞反映了 RAII 保护 \texttt{vmap\_increment\_nesting} 推送和弹出模式，而本机符号是普通函数。 C++ 绑定直接公开 \texttt{\_transform\_push\_vmap} / \texttt{\_transform\_pop} / \texttt{\_transform\_current} ，并通过字符串到枚举解析实现随机性。除了 C++ 堆栈之外，不需要 Python 级别的模式标志；堆栈本身就是基本事实。

操作不变量：
\begin{enumerate}[leftmargin=1.2em]
\item \texttt{push\_vmap} 返回一个新的级别； \texttt{make\_batched(value, dim, level)} 用该级别标记包装器。
\item 仅当 \texttt{value.batch\_level==level} 时，\texttt{unwrap\_at\_level(value, level)} 返回 \texttt{(physical, bdim)}；否则返回 \texttt{(value, nullopt)} 不变。
\item 当 vmap 层位于堆栈顶部时，\texttt{dispatch\_key\_for\_random(backend)} 恰好返回 \texttt{toVmapKey(backend)}，因此 vmap 内的随机工厂会通过 vmap 键重新调度，即使它们没有张量参数来携带它。
\end{enumerate}

\subsection{TransformDispatch 展开逻辑}
\label{sec:unwrap}

\texttt{TransformDispatch} 提供批处理规则用于检查和重建批处理张量的原语：

\begin{lstlisting}[caption={make and unwrap.}, label=lst:makeunwrap]
Tensor make_batched(const Tensor& value, int64_t dim, int64_t level) {
  if (!value.defined()) TP_THROW(ValueError, "cannot batch an undefined tensor");
  const int64_t bdim = normalize_dim(dim, value.dim());
  const auto sizes = static_cast<std::vector<int64_t>>(value.shape());
  const auto strides = value.strides();
  std::vector<int64_t> logical_sizes, logical_strides;
  for (int64_t d = 0; d < (int64_t)sizes.size(); ++d) if (d != bdim) {
    logical_sizes.push_back(sizes[d]); logical_strides.push_back(strides[d]);
  }
  auto impl = std::make_shared<TensorImpl>(value.unsafeGetTensorImpl(),
                                           logical_sizes, logical_strides);
  impl->set_transform_value(value.unsafeGetTensorImpl(), bdim, level);
  return Tensor(std::move(impl));
}
std::tuple<Tensor, std::optional<int64_t>> unwrap_at_level(const Tensor& value, int64_t level) {
  if (!value.defined() || !value.is_batched() || value.batch_level() != level)
    return {value, std::nullopt};
  return {value.transform_value(), value.batch_dim()};
}
Tensor move_batch_dim(const Tensor& value, int64_t dim) {
  if (!value.is_batched()) return value;
  const int64_t from = normalize_dim(value.batch_dim(), value.dim()+1);
  const int64_t to = normalize_dim(dim, value.dim()+1);
  if (from == to) return value;
  std::vector<int64_t> perm; // build permutation that moves from->to
  // ... permute physical tensor
  return value.transform_value().permute(perm);
}
\end{lstlisting}

\texttt{actual\_dim} 通过跳过批位置：\texttt{actual = public -> bdim ? public: public+1} 将公共维度（逻辑）映射到物理维度。每个采用维参数（排列、转置、挤压、求和等）的批处理规则都会在调用底层内核之前应用此转换，然后调整结果的 \texttt{bdim} 以反映在批处理位置之前插入或删除的维。

解包合约在 \texttt{BatchingKernels.cpp} 上是统一的：每个规则调用 \texttt{unwrap\_operand} ，它断言操作数的级别通过 \texttt{layer\_for(level)} 与活动层匹配，然后分派到 \texttt{unwrap\_at\_level} 。如果没有操作数批量处理当前级别，则规则抛出 \texttt{RuntimeError}——调度程序不应该路由到那里。这种快速失败行为会立即捕获代码生成不匹配的情况。

\subsection{BatchingKernels：每操作手写规则与循环回退}
\label{sec:batchingkernels}

\texttt{BatchingKernels.cpp}是1229行批量规则，分别注册在\texttt{VmapCPU}和\texttt{VmapCUDA}下：

\begin{lstlisting}[caption={dual registration.}, label=lst:batchreg]
TENSORPLAY_LIBRARY_IMPL(VmapCPU, NativeBatchRulesCPU) { register_batch_rules(m); }
TENSORPLAY_LIBRARY_IMPL(VmapCUDA, NativeBatchRulesCUDA) { register_batch_rules(m); }
\end{lstlisting}

\texttt{register\_batch\_rules} 绑定约 70 个操作。该文件没有通用的每切片循环回退；每个受支持的 \ac{op} 都有一个保留矢量化的手写规则。不支持的操作不会静默循环——生成的 \texttt{Tensor} 方法检查 \texttt{getKernel(vmap\_key)} 并在不存在的情况下抛出 \texttt{No native batch rule registered} (--)，这对于隐式循环会隐藏性能悬崖的教学框架来说是正确的快速失败。

\subsubsection{规则模板}

三个模板涵盖了大多数操作：

\begin{lstlisting}[caption={unary / binary templates.}, label=lst:templates]
template <typename Function> Tensor unary_impl(const Tensor& input, Function&& call) {
  Operand operand = unwrap_operand(input);
  if (!operand.bdim.has_value()) TP_THROW(RuntimeError, "unary batch rule received an unbatched operand");
  Tensor result = call(operand.value);
  return make_batched(result, *operand.bdim, operand.level);
}
template <typename Function> Tensor binary_impl(const Tensor& left, const Tensor& right, Function&& call) {
  Operand left_operand = unwrap_operand(left); Operand right_operand = unwrap_operand(right);
  int64_t level = -1; auto values = aligned_values(left_operand, right_operand, level);
  Tensor result = call(values.first, values.second);
  return make_batched(result, 0, level);
}
Tensor unary(const char* op, const Tensor& input) {
  return unary_impl(input, [&](const Tensor& v){ return call_next<Tensor,const Tensor&>(op, v, v); });
}
Tensor binary(const char* op, const Tensor& left, const Tensor& right) {
  return binary_impl(left, right, [&](const Tensor& a, const Tensor& b){
    return call_next<Tensor,const Tensor&,const Tensor&>(op, a, a, b); });
}
\end{lstlisting}

\texttt{call\_next} 通过 \texttt{DispatchStub::call} 使用从解包张量派生的后端密钥重新调度 vmap 层下方，因此底层 CPU/CUDA 内核在连续的物理内存上运行。 \texttt{call\_device} 是通过显式 \texttt{Device} 调度的工厂变体。

关键帮手：
\begin{itemize}[leftmargin=1.2em]
\item \texttt{move\_to\_front(value, dim)} 将批处理维排列为 0，使单个批处理内核能够处理任何 \texttt{bdim}。
\item \texttt{expand\_unbatched(value, batch\_size, target\_shape)} 通过 \texttt{unsqueeze(0).expand([B,...])} 广播未批处理的操作数，因此二进制操作不需要在计算内核中的混合批处理/未批处理上分支。
\item \texttt{aligned\_values(left, right, level)} 将批处理的输入移动到前面并扩展未批处理的输入，返回两个张量，其 dim~0 是批处理。结果始终包裹在 dim~0 处。
\item \texttt{logical\_shape(operand)} 从物理形状中删除批处理维，用于尺寸扩展。
\end{itemize}

具体的维调整出现在每个形状规则中。例如，\texttt{sum\_dim}：

\begin{lstlisting}[caption={sum adjusts batch dim.}, label=lst:sumdim]
Tensor sum_dim(const Tensor& input, const std::vector<int64_t>& dims, bool keepdim, DType dtype) {
  Operand operand = unwrap_operand(input);
  const int64_t old_bdim = *operand.bdim; const int64_t level = operand.level;
  std::vector<int64_t> actual_dims;
  for (int64_t dim : dims) {
    const int64_t public_dim = normalize_dim(dim, input.dim());
    const int64_t actual = public_dim < old_bdim ? public_dim : public_dim + 1;
    actual_dims.push_back(actual);
  }
  Tensor result = call_next<Tensor,const Tensor&,const std::vector<int64_t>&,bool,DType>(
    "sum.dim_IntList", operand.value, operand.value, actual_dims, keepdim, dtype);
  int64_t result_bdim = old_bdim;
  if (!keepdim) result_bdim -= count_if(actual_dims.begin(), actual_dims.end(),
                                        [&](int64_t d){ return d < old_bdim; });
  return make_batched(result, result_bdim, level);
}
\end{lstlisting}

\texttt{permute} 构建一个物理排列，将批处理维交错在其原始位置，然后在物理张量上调用 \texttt{permute} 并在 \texttt{new\_bdim} 处重新包装。 \texttt{cat} 通过 \texttt{align\_tensor\_list} 对齐列表，将每个批处理输入的 \texttt{bdim} 移动到 0 并扩展未批处理的输入，然后在 \texttt{public\_dim+1} 处调用 \texttt{cat} 并在 0 处换行。 \texttt{mm} 先对齐再调用 \texttt{bmm}，因此一批矩阵乘法成为单个批处理内核而不是循环。

没有规则会退回到每切片循环。这是故意的：循环是正确的，但会破坏批处理内核的目的（一次启动与\ $B$ 启动），并且会隐藏丢失的覆盖范围。当操作缺少规则时，生成的包装器会立即抛出异常，解决方法是按照 \texttt{unary}/\texttt{binary} 模式向 \texttt{BatchingKernels.cpp} 添加规则。

\subsection{Python 表面：\texttt{tensorplay.func.vmap}}
\label{sec:pythonsurface}

Python API 是本机堆栈上的精简验证器。是公共 \texttt{vmap}：

\begin{lstlisting}[caption={public \texttt{vmap} surface.}, label=lst:pyvmapapi, style=pystyle]
def vmap(func, in_dims=0, out_dims=0, randomness="error", *, chunk_size=None):
    if not callable(func): raise TypeError(f"vmap expected a callable, got {type(func)!r}")
    _check_randomness_arg(randomness)
    @functools.wraps(func)
    def wrapped(*args, **kwargs):
        return vmap_impl(func, in_dims, out_dims, randomness, chunk_size, *args, **kwargs)
    return wrapped
\end{lstlisting}

验证、展平 args 的 pytree、推送本机层、包装输入、调用用户函数并解开输出：

\begin{lstlisting}[caption={\texttt{vmap\_impl} and nesting.}, label=lst:vmapimpl, style=pystyle]
def vmap_impl(func, in_dims, out_dims, randomness, chunk_size, *args, **kwargs):
    _check_randomness_arg(randomness)
    batch_size, flat_in_dims, flat_args, args_spec = _process_batched_inputs(in_dims, args, func)
    if chunk_size is not None:
        return _chunked_vmap(func, flat_in_dims,
            _get_chunked_inputs(flat_args, flat_in_dims, batch_size, chunk_size),
            args_spec, out_dims, randomness, **kwargs)
    return _flat_vmap(func, batch_size, flat_in_dims, flat_args, args_spec, out_dims, randomness, **kwargs)

def _flat_vmap(func, batch_size, flat_in_dims, flat_args, args_spec, out_dims, randomness, **kwargs):
    with vmap_increment_nesting(batch_size, randomness) as level:
        batched_args = _create_batched_inputs(flat_in_dims, flat_args, level, args_spec)
        outputs = func(*batched_args, **kwargs)
        return _unwrap_batched(outputs, out_dims, level, batch_size, func)

@contextlib.contextmanager
def vmap_increment_nesting(batch_size, randomness):
    level = tensorplay._C._transform_push_vmap(batch_size, randomness)
    token = _vmap_depth.set(_vmap_depth.get() + 1)
    try: yield level
    finally:
        try: tensorplay._C._transform_pop()
        finally: _vmap_depth.reset(token)
\end{lstlisting}

\texttt{\_process\_batched\_inputs} 通过 \texttt{tree\_flatten} / \texttt{\_broadcast\_to\_and\_flatten} 展平 \texttt{args} 和 \texttt{in\_dims}，标准化负维号，检查每个 \texttt{in\_dim != None} 是否对应于 \texttt{Tensor}，并验证所有映射张量共享相同的批量大小。 \texttt{\_create\_batched\_inputs} 为每个映射的叶子调用 \texttt{tensorplay.\_C.\_transform\_make\_batched(arg, dim, level)} ，而未映射的叶子保持不变。

输出处理遵循输入侧：它展平输出，检查 \texttt{out\_dims} 兼容性，使用 \texttt{\_transform\_unwrap(output, level)} 解包每个张量叶，并通过 \texttt{tensorplay.movedim(unwrapped, batch\_dim, target\_dim)} 将物理批维移动到请求的公共位置。非张量叶子必须有\texttt{out\_dim=None}；否则会引发 \texttt{ValueError} 。

三个分块实用程序限制大批量的峰值内存：
\begin{itemize}[leftmargin=1.2em]
\item \texttt{chunk\_vmap} 和 \texttt{vmap(..., chunk\_size=N)} 通过 \texttt{get\_chunked\_inputs} 将批处理分成多个部分，\texttt{get\_chunked\_inputs} 使用 \texttt{tensor\_split} 沿着映射的维，为每个块运行独立的本机层，并沿着 \texttt{out\_dim} 与 \texttt{cat} 重新连接。
\item \texttt{restore\_vmap} 和 \texttt{ unwrap\_batched} 公开相同的原语用于测试和 \texttt{jvp} ，需要重新进入调整大小的层。
\end{itemize}

C++ 绑定有六个函数：\texttt{\_transform\_push\_vmap}、\texttt{\_transform\_pop}、\texttt{\_transform\_current}、\texttt{\_transform\_make\_batched}、\texttt{\_transform\_unwrap} 和 \texttt{\_transform\_unwrap\_all}。每个都是通过 pybind11 类型转换直接转发到 \texttt{tensorplay::transform::*} ，并且没有额外的簿记。

\subsection{随机性处理}
\label{sec:randomness}

vmap 内的随机操作不明确：每个样本应该独立绘制还是应该批次共享一次绘制？ TensorPlay 要求调用者通过 \texttt{randomness} 显式选择：

\begin{table}[H]
\centering
\caption{随机模式。每个随机工厂都会参考活动层的 \texttt{randomness}。}
\label{tab:randomness}
\small
\begin{tabular}{lll}
\toprule
Mode & 细绳 & \texttt{BatchingKernels.cpp} 中的工厂行为 \\
\midrule
\texttt{Error} & \texttt{"error"} & \texttt{check\_randomness} 抛出 \\
\texttt{Same} & \texttt{"same"} & 绘制一次，\texttt{unsqueeze(0).expand([B,...])} 并包裹 \\
\texttt{Different} & \texttt{"different"} & 使用预置的批处理维 \texttt{[B,...shape]} 进行绘制并在 0 处换行 \\
\bottomrule
\end{tabular}
\end{table}

工厂实施这种分支。对于基于形状的工厂：

\begin{lstlisting}[caption={random factory.}, label=lst:randfactory]
Tensor random_factory(const char* op, const std::vector<int64_t>& shape,
                      std::optional<DType> dtype, std::optional<Device> device) {
  const Layer layer = current_vmap_layer(); check_randomness(layer);
  const Device target = resolve_random_device(device);
  if (layer.randomness == Randomness::Different) {
    Tensor result = call_device<Tensor,const std::vector<int64_t>&,
                                std::optional<DType>,std::optional<Device>>(
      op, target, prepend_batch_size(shape, layer.batch_size), dtype, device);
    return make_batched(result, 0, layer.level);
  }
  Tensor sample = call_device<Tensor,const std::vector<int64_t>&,
                              std::optional<DType>,std::optional<Device>>(
    op, target, shape, dtype, device);
  return expand_same_random(std::move(sample), layer);
}
\end{lstlisting}

\texttt{prepend\_batch\_size} 在 dim~0 处插入 $B$； \texttt{expand\_same\_random} 执行 \texttt{sample.unsqueeze(0).expand([B,...shape])} 因此每个样本共享相同的随机值，但下游操作仍然看到正确的批次。 \texttt{randperm} 很特殊：使用 \texttt{Different} 时，它会循环 $B$ 次并堆栈，因为单个 \texttt{randperm([B,n])} 不会产生 $B$ 独立排列。

对于 \texttt{rand\_like} 变体，输入本身可以批量处理活动级别。使用 \texttt{Different}，工厂在物理值上调用底层 \texttt{rand\_like} 并重新包装相同的 \texttt{bdim}；使用 \texttt{Same} 时，它会选择一个切片（\texttt{select.int} 位于 \texttt{bdim}，索引 0），从该切片进行绘制，然后沿 \texttt{bdim} 向后扩展。 \texttt{Same} 下的非批量输入共享一次抽取，扩展到 \texttt{[B,...]}；在 \texttt{Different} 下，他们创建一个模板 \texttt{unsqueeze(0).expand} 物理张量并在那里绘制。

为随机操作生成的调度密钥使用 \texttt{dispatch\_key\_for\_random(computeDispatchKey(device))} 而不是 \texttt{dispatchKeyForTensorArgs}，因此即使没有张量参数携带 vmap 键，它也会被注入。因此，在 Python 层，\texttt{vmap(func, randomness="different")(randn([3]))} 通过 \texttt{VmapCPU} 路由 \texttt{randn}，无需任何批量输入。使用默认的 \texttt{"error"} ，vmap 内的任何随机操作都会立即抛出一条命名约束的消息，因此静默错误批次随机性是不可能的。

\subsection{与 Autograd 和重新调度订单交互}
\label{sec:autogradinteract}

Vmap 的数字优先级是正确性的承载：vmap 必须在 autograd 记录历史之前查看操作数。 \texttt{TensorImpl::key\_set} 在批处理时仅返回 \texttt{Vmap*}，而 \texttt{highest\_priority\_key} 更喜欢更高的数字键，共同保证 \texttt{vmap(grad(f))} 和 \texttt{grad(vmap(f))} 是不同的并且都是正确的。

生成的 \texttt{Tensor} 方法对顺序进行编码 Vmap $\rightarrow$ Autocast $\rightarrow$ Autograd $\rightarrow$ Backend：

\begin{lstlisting}[caption={redispatch order in every Tensor method.}, label=lst:redispatchorder]
{
  DispatchKey __tp_key = dispatchKeyForTensorArgs(*this, other);
  if (is_vmap_key(__tp_key)) {
    static const OperatorHandle __tp_handle = Dispatcher::singleton().findHandle("add");
    if (!__tp_handle || !__tp_handle.getKernel(__tp_key))
      TP_THROW(NotImplementedError, "No native batch rule registered for add");
    return DispatchStub<...>::call(__tp_handle, __tp_key, *this, other);
  }
}
{
  static const OperatorHandle __ac_handle = Dispatcher::singleton().findHandle("add");
  DispatchKey __ac_key = toAutocastKey(computeDispatchKey(device()));
  if (autocast::is_enabled(__ac_key) && __ac_handle && __ac_handle.getKernel(__ac_key))
    return DispatchStub<...>::call(__ac_handle, __ac_key, *this, other);
}
if (GradMode::is_enabled()) {
  static const OperatorHandle ag_handle = Dispatcher::singleton().findHandle("add");
  DispatchKey ag_key = toAutogradKey(computeDispatchKey(device()));
  if (ag_handle && ag_handle.getKernel(ag_key))
    return DispatchStub<...>::call(ag_handle, ag_key, *this, other);
}
return detail::redispatch_add(*this, other);
\end{lstlisting}

因为 vmap 首先运行，所以 \texttt{vmap(f)} 内的 \texttt{add} 被分派到 \texttt{batch\_add}，后者解包到物理张量，在它们上调用 \texttt{add} （重新输入分派后端键），并重新包装结果。因此，Autograd 将 $B$ 批处理值视为单个批处理结果，并记录批处理 \texttt{Node}；批处理 \texttt{Node} 的向后本身就是批处理的，因此 \texttt{Engine::evaluate\_function} 不需要特定于 vmap 的更改。相反，\texttt{grad(vmap(f))} 在 vmap 之外运行梯度变换：前向记录中间张量被批处理的图，后向以相同的批处理规则重播。

复合材料强化了排序：

\begin{lstlisting}[caption={composites reject active transforms.}, label=lst:composites]
inline bool under_active_transform(const Tensor& t){ return t.unsafeGetTensorImpl() && t.unsafeGetTensorImpl()->is_batched(); }
inline void reject_active_transform(const Tensor& t, const char* op){
  if (under_active_transform(t)) TP_THROW(NotImplementedError, std::string(op),
    " is not supported for tensors inside an active transform (vmap/grad) layer");
}
template <typename Return, typename... Args>
Return redispatch_below_transform(const char* op, Args... args){
  DispatchKey key = dispatchKeyForTensorArgs(args...);
  TP_CHECK(is_vmap_key(key), op, ": expected an active transform key");
  return DispatchStub<Return, Args...>::call(std::string(op), key, std::forward<Args>(args)...);
}
\end{lstlisting}

普通复合材料调用 \texttt{reject\_active\_transform} 因为在包装器上运行后端内核会默默地破坏批处理。分解式复合调用 \texttt{redispatch\_below\_transform} 有意通过 vmap 层进行路由，以便内部操作符合其批处理规则。两条路径都保持不变，即任何接触批处理张量的操作必须要么是批处理规则本身，要么明确选择通过一个批处理规则重新调度。

嵌套 vmap 由堆叠级别组成：内部 \texttt{push\_vmap} 分配一个新级别，其输入是双重包装的（外部包装器围绕内部包装器），并且每个规则的 \texttt{unwrap\_at\_level} 仅剥离其拥有的级别。在执行内部规则时，外部批处理维保持不变，然后在返回到外层之前重新包装内部结果。除了水平检查之外，不需要特殊的嵌套套管。

\subsection{端到端示例和成本说明}
\label{sec:vmapcost}

考虑 \texttt{f(x)= (x*2).sum} 映射到形状 \texttt{[3]} 的 4 个样本上：

\begin{lstlisting}[caption={Vmap example: one function, batched execution.}, label=lst:vmapexample, style=pystyle]
import tensorplay as tp
def f(x): return (x * 2).sum()
batched = tp.func.vmap(f)(tp.randn([4, 3]))   # in_dims=0, out_dims=0
assert batched.shape == tp.Size([4])
# equivalent to: tp.stack([f(tp.randn([3])) for _ in range(4)]) but one kernel launch per op
\end{lstlisting}

本机运行的内容：
\begin{enumerate}[leftmargin=1.2em]
\item \texttt{vmap\_impl} 验证批量大小 4，使用 $B{=}4$ 推送级别 $L$，使用 \texttt{bdim=0, level=L} 将 \texttt{[4,3]} 张量包装到批处理的 \texttt{[3]} 中。
\item \texttt{x*2} 是 \texttt{mul.Scalar}，带有一个批处理操作数：\texttt{batch\_mul\_scalar} 解包到物理 \texttt{[4,3]}，在其上调用 \texttt{mul.Scalar}（一个内核），在 0 $\to$ 批处理 \texttt{[3]} 处重新包装到 dim~0。
\item \texttt{sum} 是 \texttt{sum.dim\_IntList}：\texttt{batch\_sum} 展开，在物理 \texttt{[4,3]} 上的非批量调暗上调用 \texttt{sum}，获取 \texttt{[4]}，在 0 $\to$ 批处理 \texttt{[]}（每个样本的标量）处重新包装，在输出 \texttt{movedim} 后具有逻辑形状 \texttt{[4]}。
\item 弹出$L$，将批处理维移动到\texttt{out\_dims=0}（已经在那里），返回\texttt{[4]}。
\end{enumerate}

成本：每个操作支付 1 个 \texttt{unwrap\_at\_level} + 1 个 \texttt{make\_batched} + 1 个底层内核。没有每个样本的 Python 循环，没有超出包装器 \texttt{TensorImpl}（几十个字节）的额外分配。对于一批 $B$ 样本，$N$ 操作启动 $N$ 内核而不是 $N{\times}B$。分块 vmap (\texttt{chunk\_size}) 通过将 $B$ 分割成多个片段并连接结果来将其换回有限内存。

\begin{tpinsight}[Insight: One Physical Kernel per Op, Not per Sample]
批量密钥设计将 \emph{multiplication} 转换为 \emph{constant}：批量大小为 $B$ 的 \texttt{vmap(f)(xs)} 的简单实现为 $N$-op 函数启动 $N{\times}B$ 内核；偏移量~9 处的变换键恰好启动 $N$。诀窍在于，批处理规则 \emph{moves the batch dimension into the tensor} 在内核运行之前： \texttt{batch\_mul\_scalar} 将逻辑 \texttt{[3]} 与 \texttt{bdim=0} 解包到物理 \texttt{[4,3]}，因此普通 \texttt{mul} 内核自己的广播机制可以在一次启动中处理所有 $B$ 样本。因此，Vmap 是一个 \emph{dispatch-layer rewrite}，而不是内核层重写——这也是它存在于一个库（\texttt{p10} 的转换堆栈）中的原因，该库永远不需要知道任何单个内核是如何实现的。
\end{tpinsight}
