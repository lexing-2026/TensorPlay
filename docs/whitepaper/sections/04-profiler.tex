\section{Profiler Subsystem: OpRecord, GpuTimerPair, and Backend Stack}
\label{sec:profiler}

\subsection{Goals and Placement}

The profiler must satisfy three conflicting goals: (i) near-zero overhead when disabled, (ii) accurate CPU+GPU timing when enabled, and (iii) pluggability of backends (CPU tracing, CUDA CUPTI activity, NVTX ranges, ITT tasks). TensorPlay places the core in \texttt{p10} so both \texttt{tpx} (Engine) and kernels can instrument without depending on Python. The Python layer (\texttt{tensorplay.profiler}) merely toggles atomics and drains buffers. Placement follows the dependency rule: \texttt{Profiler.h} is the single header; \texttt{tpx} and \texttt{\_C} include it, never the reverse.

The hot path is one \texttt{std::atomic<bool>} load per dispatched op plus, when shape or site capture is requested, one further load each. This matches the class of guard already emitted around every call for \texttt{GradMode} and \texttt{InferenceMode}. All other work (shape copy, name arena push, GPU event record) sits behind that branch.

\subsubsection{Event fields}

\begin{lstlisting}[caption={Event layout.}, label=lst:eventfields, style=cppstyle]
struct Event {
  const char* name;        // borrowed for kOp (static literal), arena-owned for kUser/kBackward
  uint64_t start_ns;       // CLOCK_MONOTONIC (steady_clock)
  uint64_t end_ns;
  uint64_t tid;            // hashed std::this_thread::get_id()
  EventKind kind;          // kOp='o', kUser='u', kBackward='b' (Profiler.h:43)
  std::shared_ptr<const ShapeVec> shapes; // record_shapes only
  std::shared_ptr<const DtypeVec> dtypes;
  uint32_t site_id = kNoSite;   // Python call site (with_stack)
  uint32_t stack_id = kNoSite;  // full frame chain (with_stack)
  void* gpu_start = nullptr;    // opaque cudaEvent_t pair (USE_CUDA)
  void* gpu_end = nullptr;
  float gpu_ms = -1.f;          // filled by gpu_resolve_all or summed kernel time in gpu_trace
  int32_t kernel_count = 0;     // correlated kernel count in gpu_trace mode
  int64_t out_bytes = -1;       // numel * itemsize for Tensor-returning ops
};
\end{lstlisting}

\texttt{EventKind} at distinguishes dispatched operators (\texttt{kOp}), user annotations via \texttt{record\_function} (\texttt{kUser}), and the autograd engine's \texttt{\_\_backward\_\_} span (\texttt{kBackward}). \texttt{site\_id} and \texttt{stack\_id} resolve through \texttt{site\_string} and \texttt{stack\_frames} and stay valid until the next \texttt{profiler\_start}.

\texttt{GpuActivity} at adds \texttt{correlation}, \texttt{external\_id}, \texttt{thread\_id}, \texttt{cbid}, \texttt{device}, \texttt{stream}, \texttt{kind}, \texttt{bytes}, \texttt{copy\_kind}, \texttt{value}. \texttt{kNoExt = 0xffffffffffffffff} marks uncorrelated activity.

Lifecycle, concrete path:line trace:

\begin{enumerate}[leftmargin=1.4em]
\item Construction calls \texttt{OpRecord::begin}. First it checks \texttt{g\_emit\_nvtx} and \texttt{g\_emit\_itt} via relaxed loads (so NVTX/ITT ranges can fire without a profiling session for \texttt{kOp}, as noted at). Then it checks \texttt{g\_active}; if false, returns immediately with \texttt{live\_=false}: disabled cost is one acquire-load and a predicted not-taken branch.
\item If active, it does \texttt{g\_inflight.fetch\_add(1)}, snapshots \texttt{now\_ns} ( via \texttt{steady\_clock}), then locks \texttt{g\_mutex}. A second relaxed check of \texttt{g\_active} handles the race where \texttt{profiler\_stop} cleared the flag between the two checks.
\item It builds an \texttt{Event}: \texttt{name} is either the static literal (\texttt{kOp} path,) or an arena copy in \texttt{g\_name\_arena} ( for \texttt{kUser}/\texttt{kBackward}). \texttt{tid} comes from \texttt{this\_thread\_id} (, defined at as a \texttt{thread\_local} hash of \texttt{std::this\_thread::get\_id}). If \texttt{t\_pending\_site.valid} is set, its \texttt{stack\_id} are consumed and cleared so inner composite ops do not inherit the outermost Python site.
\item If \texttt{nvtx\_on || itt\_on}, it calls \texttt{nvtx\_span\_begin(e.name)} and \texttt{itt\_span\_begin(e.name)} and sets \texttt{itt\_open\_}. Then \texttt{g\_events->push\_back(e)} and \texttt{slot\_ = size-1}, \texttt{start\_ns\_ = start}, \texttt{live\_=true}.
\item \texttt{set\_io\_meta} and \texttt{set\_output\_bytes} lock \texttt{g\_mutex} and write into \texttt{(*g\_events)[slot\_]} if \texttt{live\_} and slot is in bounds. \texttt{set\_shapes} is a shapes-only overload for generated dispatchers where dtypes stay unset.
\item Destruction always closes NVTX/ITT first, then if \texttt{!live\_} returns. Otherwise it records \texttt{end = now\_ns}, locks \texttt{g\_mutex}, writes \texttt{(*g\_events)[slot\_].end\_ns = end} if the slot still exists (dropped silently if \texttt{profiler\_stop} already cleared the vector), then calls \texttt{release\_inflight} which does \texttt{g\_inflight.fetch\_sub(1)} and notifies \texttt{g\_inflight\_cv} when the count reaches zero.
\end{enumerate}

The \texttt{g\_inflight} protocol is critical for correctness: \texttt{profiler\_stop} at first stores \texttt{g\_active=false}, then waits on \texttt{g\_inflight\_cv} until \texttt{g\_inflight==0} before taking \texttt{g\_mutex} and moving \texttt{g\_events} out. This prevents a CUDA or CPU worker from appending \texttt{gpu\_ms} or \texttt{end\_ns} after \texttt{gpu\_resolve\_all} has snapshotted the vector.

\subsection{Storage: Append-Only Vector as Logical RingBuffer}

The original design document calls this component \texttt{RingBuffer} (\texttt{RingBuffer.h} in the draft). The shipped implementation realizes the same logical buffer as an append-only vector guarded by a mutex plus stable slot indices. Concrete state in:

\begin{lstlisting}[caption={session storage.}, label=lst:profstorage, style=cppstyle]
std::mutex g_mutex;
std::vector<Event>* g_events = nullptr;              // append-only, slots stable
std::vector<MemEvent>* g_mem_events = nullptr;
std::deque<std::string>* g_name_arena = nullptr;     // owns user/backward names
std::vector<std::pair<std::string,int>>* g_site_table = nullptr;
std::unordered_map<std::string,uint32_t>* g_site_index = nullptr;
std::deque<std::string>* g_frame_arena = nullptr;
std::unordered_map<std::string,uint32_t>* g_frame_index = nullptr;
std::vector<std::vector<uint32_t>>* g_stack_table = nullptr;
std::deque<ProfFrame>* g_frame_store = nullptr;
std::atomic<uint64_t> g_inflight{0};
std::mutex g_inflight_mutex;
std::condition_variable g_inflight_cv;
\end{lstlisting}

Why a vector and not a fixed ring: slots are referenced by \texttt{OpRecord::slot\_} and by \texttt{GpuTimerPair}'s external correlation id (\texttt{slot\_} cast to \texttt{uint64\_t} at) for the entire session. A ring that overwrites would invalidate those indices. The binding layer drains the vector in \texttt{profiler\_stop} via \texttt{std::move(*g\_events)} then \texttt{stable\_sort} by \texttt{start\_ns}. The arena (\texttt{g\_name\_arena}) stays alive until the next \texttt{profiler\_start} because \texttt{Event::name} for user spans is a borrowed pointer into it ( comment).

Pending Python site handling is thread-local at:

\begin{lstlisting}[caption={per-thread pending site.}, label=lst:pendingsite, style=cppstyle]
thread_local struct {
  bool valid = false;
  uint32_t site_id = Event::kNoSite;
  uint32_t stack_id = Event::kNoSite;
} t_pending_site;
\end{lstlisting}

\texttt{set\_python\_site} and \texttt{set\_python\_stack} are called by the binding layer while the GIL is held; they intern through \texttt{intern\_site} and \texttt{intern\_stack} which dedup via \texttt{g\_site\_index} and \texttt{g\_frame\_index}. The next \texttt{OpRecord::begin} on that thread consumes the pending site and clears \texttt{valid}, so inner composite ops record no site instead of repeating the outermost call.

User annotations have their own LIFO stack at (\texttt{thread\_local std::vector<size\_t> t\_user\_stack}) pushed in \texttt{user\_span\_begin} and popped in \texttt{user\_span\_end}. Both manipulate \texttt{g\_events} under \texttt{g\_mutex} and emit NVTX around the push/pop.

The logical RingBuffer properties that remain: no allocation on the hot path beyond the vector's amortized growth (op events are 64 bytes plus optional shared\_ptr payloads), and the buffer is drained exactly once at session stop.

\subsection{GpuTimerPair: cudaEvent vs.\ CUPTI Selection}

 declares \texttt{GpuTimerPair} as a pool-backed \texttt{cudaEvent\_t} pair plus CUPTI correlation bracketing:

\begin{lstlisting}[caption={GpuTimerPair handle.}, label=lst:gputimerpair, style=cppstyle]
struct TENSORPLAY_API GpuTimerPair {
  explicit GpuTimerPair(OpRecord& rec) : rec_(rec) {}
  ~GpuTimerPair();
  void arm(const Device& device);  // records start on a CUDA op's stream
  void close();                    // records the end event
private:
  OpRecord& rec_;
  void* gpu_start_ = nullptr;
  void* gpu_stream_ = nullptr;
  int gpu_device_ = -1;
  bool armed_ = false;
};
\end{lstlisting}

The implementation lives in \texttt{ProfilerGpu.cpp}. For \texttt{!USE\_CUDA} it compiles to no-ops at so generated code links without \texttt{\#ifdef} noise.

\subsubsection{Selection logic in \texttt{arm}}

\begin{lstlisting}[caption={arm() selection.}, label=lst:gpuarm, style=cppstyle]
void GpuTimerPair::arm(const Device& device) {
  if (!rec_.live_ || !device.is_cuda()) return;
  if (g_gpu_trace.load(memory_order_acquire)) {
    rec_.trace_pushed_ = cupti_push_ext(static_cast<uint64_t>(rec_.slot_));
  }
  if (!g_gpu_timing.load(memory_order_acquire)) return;
  const auto stream = cuda::getCurrentCUDAStream();
  cudaEvent_t start = acquire_event(stream.device_index());
  if (!start || cudaEventRecord(start, stream.stream()) != cudaSuccess) {
    if (start) (void)cudaEventDestroy(start);
    return;
  }
  gpu_start_ = start;
  gpu_stream_ = stream.stream();
  gpu_device_ = stream.device_index();
  armed_ = true;
}
\end{lstlisting}

Two orthogonal features interleave:

\begin{itemize}[leftmargin=1.4em]
\item \textbf{CUPTI correlation} is independent of \texttt{g\_gpu\_timing}. If \texttt{g\_gpu\_trace} is set, \texttt{arm} pushes the op's slot as an external correlation id via \texttt{cupti\_push\_ext} onto CUPTI's per-thread stack. This happens even when event timing is off, so a \texttt{gpu\_trace} session correlates kernels without paying \texttt{cudaEventRecord} cost.
\item \textbf{cudaEvent timing} is gated on \texttt{g\_gpu\_timing}. When on, \texttt{arm} acquires a pooled \texttt{cudaEvent\_t} via \texttt{acquire\_event} (, recycles from \texttt{g\_pool} under \texttt{g\_gpu\_mutex} or creates with \texttt{cudaEventCreateWithFlags}), records it on the current stream, and saves device/stream/event.
\end{itemize}

\texttt{close} at follows the same order: first it pops the CUPTI correlation if one was pushed ( via \texttt{cupti\_pop\_ext} at), then if \texttt{armed\_} records the end event via \texttt{acquire\_event} and \texttt{cudaEventRecord}, and appends a \texttt{LivePair\{slot,device,stream,start,end\}} to \texttt{g\_live} under \texttt{g\_gpu\_mutex}. Profiling never makes a valid op fail: every CUDA error path destroys the partial event and returns.

\subsubsection{Resolution at session stop}

\texttt{gpu\_resolve\_all} is called from the binding's \texttt{\_profiler\_stop} at after \texttt{profiler\_stop} but before returning to Python. Key steps:

\begin{enumerate}[leftmargin=1.4em]
\item Swap \texttt{g\_live} out under the mutex so dispatch can continue while resolution runs.
\item Compute a deadline from \texttt{TP\_PROFILER\_GPU\_TIMEOUT\_MS} (default 5000\,ms,).
\item Build \texttt{last\_on\_stream} map: one wait per stream is sufficient because CUDA orders event records on a stream.
\item For each stream's last end event, call \texttt{wait\_event} which polls \texttt{cudaEventQuery} with \texttt{50\,\textmu s} sleeps until success or deadline. This avoids a device-wide synchronize.
\item Resolve each pair via \texttt{cudaEventElapsedTime}. On success, write \texttt{events[slot].gpu\_ms = ms} and invoke the \texttt{emit} callback. Reusable events go to a local \texttt{reusable} vector; failed pairs are destroyed via \texttt{destroy\_event\_pair} which does \texttt{cudaEventDestroy} even for pending events. Pending pairs are intentionally not returned to the pool so the next session starts clean.
\item Return reusable events to \texttt{g\_pool} under one lock and restore the caller's device.
\end{enumerate}

The pool is \texttt{unordered\_map<int, deque<cudaEvent\_t>>} keyed by device index, created with \texttt{cudaEventDefault} (timing on). \texttt{gpu\_drain\_pool} at swaps and destroys all pooled and live events, used by the binding at process teardown.

\subsection{OptionalCUDAGuard: Correct Device for Multi-GPU Timing}

Generated redispatch helpers must record GPU events on the op's target device even when the calling thread's current device is elsewhere. declares:

\begin{lstlisting}[caption={OptionalCUDAGuard.}, label=lst:optionalguard, style=cppstyle]
class P10_API OptionalCUDAGuard {
public:
  explicit OptionalCUDAGuard(const Device& device);
  ~OptionalCUDAGuard();
private:
  std::unique_ptr<CUDAGuard> guard_;
};
\end{lstlisting}

For \texttt{!USE\_CUDA} it is an empty inline. For CUDA builds, the constructor at does \texttt{if (device.is\_cuda) guard\_ = make\_unique<CUDAGuard>(device)}; the destructor restores via \texttt{CUDAGuard}. \texttt{CUDAGuard} itself (at) saves \texttt{cudaGetDevice}, calls \texttt{cudaSetDevice} to the target, and restores on destruction.

Codegen emits the guard immediately after the profiler handles at:

\begin{lstlisting}[caption={device guard emission.}, label=lst:genguard, style=cppstyle]
#ifdef USE_CUDA
    tensorplay::prof::GpuTimerPair __tp_gpu(__tp_prof_rec);
#endif
#ifdef USE_CUDA
    cuda::OptionalCUDAGuard device_guard(weight.device());
#endif
    static const OperatorHandle op_handle = Dispatcher::singleton().findHandle("add");
    DispatchKey dispatch_key = toBackendKey(...);
#ifdef USE_CUDA
    __tp_gpu.arm(weight.device());
#endif
\end{lstlisting}

Placement matters: the guard is constructed before \texttt{arm} so \texttt{acquire\_event} and \texttt{cudaEventRecord} run on the correct device, and \texttt{close} runs before the guard is destroyed (the guard outlives \texttt{\_\_tp\_gpu} only until the function returns, but \texttt{close} is called explicitly after dispatch, before destruction, at). On CPU ops \texttt{device.is\_cuda==false} so the guard is a no-op and \texttt{arm} early-returns.

\subsubsection{ProfilerNVTX}

The NVTX bridge is dlopen'd, not linked. \texttt{ensure\_loaded} at probes \texttt{libnvtx.so}, \texttt{libnvtx\_dynamic.so}, \texttt{libNVToolsExt.so} and \texttt{libroctx64.so} (ROCm twin, exports \texttt{roctxRangePushA} etc.) via \texttt{dlopen} and \texttt{dlsym} for \texttt{nvtxRangePushA}, \texttt{nvtxRangePop}, \texttt{nvtxMarkA}, \texttt{nvtxRangeStartA}, \texttt{nvtxRangeEnd}. If none loads, \texttt{g\_available=false} and every call degrades. Two entry groups exist:

\begin{itemize}[leftmargin=1.4em]
\item Raw passthroughs for \texttt{tensorplay.cuda.nvtx} \texttt{range\_end}. These throw \texttt{RuntimeError} with ``NVTX functions not installed'' when unavailable, preserving the historical contract.
\item Internal no-throw hooks \texttt{end} check \texttt{emitting = g\_emit\_nvtx.load(relaxed) \&\& usable} then call \texttt{ nv\_range\_pop}. \texttt{OpRecord::begin} calls them at only when \texttt{nvtx\_on} is true (which additionally requires \texttt{kind==kOp}), so user annotations do not emit NVTX unless explicitly requested via the binding's \texttt{\_profiler\_emit\_nvtx}.
\end{itemize}

\texttt{g\_emit\_nvtx} is toggled from Python via and from the \texttt{emit\_nvtx} context manager.

\subsubsection{ProfilerItt}

The ITT bridge follows the same dlopen structure as NVTX but targets the Intel VTune/Advisor family. \texttt{ensure\_loaded} at dlopens \texttt{libittnotify.so} then \texttt{libittnotify64.so}, dlsyms \texttt{\_\_itt\_domain\_create}, \texttt{\_\_itt\_string\_handle\_create}, \texttt{\_\_itt\_task\_begin}, \texttt{\_\_itt\_task\_end}, creates domain \texttt{"tensorplay"}. Internal hooks \texttt{end} at check \texttt{g\_emit\_itt.load(relaxed)} then call \texttt{end} which internally does \texttt{fn\_string\_handle\_create} + \texttt{fn\_task\_begin}. Availability is \texttt{itt\_available}.

Both bridges keep no hard link dependency: a CPU-only wheel imports and runs with all profiler calls becoming no-ops.

\subsubsection{CuptiStub}

For HIP builds (and any re-exported \texttt{ProfilerCuptiStub.cpp}) the file provides no-op definitions for \texttt{g\_gpu\_trace}, \texttt{cupti\_available}, \texttt{cupti\_last\_error}, \texttt{cupti\_start}, \texttt{cupti\_stop\_and\_collect}, \texttt{cupti\_push\_ext}, \texttt{cupti\_pop\_ext}, \texttt{cupti\_version}. This lets the extension import under \texttt{RTLD\_NOW} without embedding \texttt{\#ifdef} the ~15 call sites that reference CUPTI symbols (\texttt{ProfilerGpu.cpp}, \texttt{init.cpp}). The CPU build provides the same fallback when \texttt{!USE\_CUDA}.

\subsection{CUPTI in Detail: Subscription, Buffers and correlationId}

\texttt{ProfilerCupti.cpp} is 596 lines for USE\_CUDA and 24 lines for CPU. The design constraint is: \texttt{libcupti} is never a hard dependency; all entry points are dlsym'd from a dlopened handle (, \texttt{108,424--466}) and sessions on machines without the toolkit degrade to \texttt{cupti\_available==false}.

\subsubsection{Entry points and handle}

\texttt{CuptiFns} holds \texttt{GetTimestamp}, \texttt{RegisterCallbacks}, \texttt{Enable}, \texttt{Disable}, \texttt{FlushAll}, \texttt{GetNextRecord}, \texttt{GetNumLostRecords}, \texttt{PushExternalCorrelationId}, \texttt{PopExternalCorrelationId}, \texttt{GetCallbackName}, \texttt{GetVersion}. \texttt{g\_cupti\_lib} is kept for the process lifetime; \texttt{g\_fns} is set-once after the first successful \texttt{cupti\_start}, so \texttt{pop} can read it without locking ( comment).

\texttt{cupti\_available} at probes without enabling: it first checks \texttt{g\_fns!=nullptr}, then tries \texttt{dlopen(..., RTLD\_NOLOAD)} for \texttt{.so}. \texttt{cupti\_version} at dlsyms \texttt{cuptiGetVersion} without enabling any kind, used to stamp trace-export schema metadata.

\subsubsection{Subscription: kinds and callbacks}

\texttt{cupti\_start} at (called from before \texttt{profiler\_start}) does:

\begin{enumerate}[leftmargin=1.4em]
\item Lazily dlopens the library from candidates \texttt{libcupti.so.13,.12,.11,.1,.so} and dlsyms mandatory symbols via macro \texttt{TP\_CUPTI\_DLSYM}; optional symbols \texttt{GetNumLostRecords}, \texttt{GetCallbackName}, \texttt{GetVersion} are null-checked.
\item Calibrates the timebase: \texttt{g\_fns->GetTimestamp(\&cupti\_now)} then \texttt{g\_time\_offset\_ns = steady\_now\_ns - cupti\_now}. Every activity record's \texttt{end} is later offset by this value, mapping CUPTI's epoch onto the op timeline's \texttt{CLOCK\_MONOTONIC}.
\item Registers buffer callbacks \texttt{buffer\_requested} / \texttt{buffer\_completed} via \texttt{RegisterCallbacks}.
\item Enables five kinds:
\begin{lstlisting}[caption={enabled kinds.}, label=lst:cuptiKinds, style=cppstyle]
static const CUpti_ActivityKind kinds[] = {
  CUPTI_ACTIVITY_KIND_MEMCPY,
  CUPTI_ACTIVITY_KIND_MEMSET,
  CUPTI_ACTIVITY_KIND_RUNTIME,
  CUPTI_ACTIVITY_KIND_CONCURRENT_KERNEL,
  CUPTI_ACTIVITY_KIND_EXTERNAL_CORRELATION,
};
for (auto k : kinds) rc = g_fns->Enable(k);
\end{lstlisting}
\end{enumerate}

\texttt{disable\_kinds\_locked} at disables the same set in \texttt{cupti\_stop\_and\_collect}.

Buffer handling uses 1\,MiB pooled buffers at (\texttt{kBufSize = 1<<20}):

\begin{itemize}[leftmargin=1.4em]
\item \texttt{buffer\_requested} pops from \texttt{g\_free\_bufs} under \texttt{g\_cupti\_mutex} or does \texttt{malloc(kBufSize)}. On allocation failure it returns \texttt{0} so CUPTI drops records but profiling continues.
\item \texttt{buffer\_completed} is called by CUPTI on its completion thread; it locks \texttt{g\_cupti\_mutex}, calls \texttt{parse\_buffer\_locked} then pushes the buffer to \texttt{g\_free\_bufs} for recycling.
\item \texttt{parse\_buffer\_locked} iterates via \texttt{GetNextRecord}. For \texttt{CONCURRENT\_KERNEL} it picks the revision alias \texttt{ActivityKernel} (Kernel9 on CUDA 12.8+, Kernel8, or Kernel4,) and pushes a \texttt{GpuActivity\{'k',\dots\}} with name interned via \texttt{intern\_name\_locked}. Memcpy/memset/runtime/driver/external-correlation each map to \texttt{'d'} plus the prefix-field extraction noted at (revisions only append trailing fields). Lost records are surfaced via \texttt{GetNumLostRecords}.
\end{itemize}

\subsubsection{correlationId and external correlation}

The key join is three-way: op $\rightarrow$ runtime API $\rightarrow$ kernel. \texttt{GpuTimerPair::arm} pushes the op's slot as \texttt{uint64\_t} external id; CUPTI emits an \texttt{EXTERNAL\_CORRELATION} record mapping \texttt{correlationId $\rightarrow$ externalId} (, kind \texttt{CUSTOM0}); kernel/memcpy activity records carry the same \texttt{correlationId}. At snapshot time \texttt{cupti\_stop\_and\_collect} flushes via \texttt{FlushAll(0)}, sleeps 5\,ms to absorb the completion thread, then joins \texttt{g\_acts} with \texttt{g\_corr2ext} at:

\begin{tpnote}[Note: Why the Join Is Deferred to Session Stop]
The three-way correlation join (op $\rightarrow$ runtime API $\rightarrow$ kernel) is \emph{not} performed as records arrive. CUPTI's completion thread calls \texttt{buffer\_completed} from a foreign thread with no GIL and no guarantee that the matching \texttt{EXTERNAL\_CORRELATION} record has been seen yet---records for one op can arrive in any order across separate buffers. Doing the join lazily at \texttt{cupti\_stop\_and\_collect} sidesteps ordering entirely: by session stop, both sides of the map are complete, so one pass over \texttt{g\_acts} against \texttt{g\_corr2ext} suffices. The 5\,ms sleep at line~524 is the price: the completion thread must be quiesced before the join, so session teardown carries a fixed $\sim$5\,ms latency. The alternative---joining incrementally with per-record locking---would put a recursive mutex on the collector's hot path and still need a final drain pass for late-arriving correlation records.
\end{tpnote}

\begin{lstlisting}[caption={external-id join.}, label=lst:correlationJoin, style=cppstyle]
for (auto& a : acts) {
  auto it = g_corr2ext->find(a.correlation);
  if (it != g_corr2ext->end()) a.external_id = it->second;
}
\end{lstlisting}

The binding at then folds per-op:

\begin{lstlisting}[caption={per-op kernel aggregation.}, label=lst:foldKernels, style=cppstyle]
for (auto& a : gpu_acts) {
  if (a.kind=='r' || a.kind=='d') continue;
  if (a.external_id==GpuActivity::kNoExt || a.external_id>=events.size()) continue;
  auto& op = events[a.external_id];
  double ms = double(a.end_ns - a.start_ns)/1e6;
  op.gpu_ms = (op.gpu_ms < 0.f ? 0.f : op.gpu_ms) + float(ms);
  op.kernel_count += 1;
}
\end{lstlisting}

\texttt{pop\_ext} are per-thread stack ops on \texttt{CUPTI\_EXTERNAL\_CORRELATION\_KIND\_CUSTOM0}; composite inner ops nest correctly because \texttt{GpuTimerPair} brackets each dispatch. Outside a \texttt{gpu\_trace} session the only per-op cost is the \texttt{g\_gpu\_trace} acquire-load in \texttt{GpuTimerPair::arm} ( comment), same as \texttt{g\_gpu\_timing}.

\subsection{Integration I: Code Generation}

Every dispatched execution passes through exactly one \texttt{detail::redispatch\_*} funnel. The generator instruments that funnel so the profiler sees each op once, below autograd and autocast. At (\texttt{\_emit\_redispatch}):

\begin{lstlisting}[caption={redispatch instrumentation.}, label=lst:genredispatch, style=cppstyle]
namespace detail {
TENSORPLAY_API Tensor redispatch_add(const Tensor& self, const Tensor& other) {
    tensorplay::prof::OpRecord __tp_prof_rec("add");
    if (tensorplay::prof::g_capture_shapes.load(std::memory_order_acquire)) {
        std::vector<std::vector<int64_t>> __tp_prof_shapes;
        std::vector<int32_t> __tp_prof_dtypes;
        __tp_prof_shapes.push_back(static_cast<std::vector<int64_t>>(self.shape()));
        __tp_prof_dtypes.push_back(static_cast<int32_t>(self.dtype()));
        __tp_prof_shapes.push_back(static_cast<std::vector<int64_t>>(other.shape()));
        __tp_prof_dtypes.push_back(static_cast<int32_t>(other.dtype()));
        __tp_prof_rec.set_io_meta(std::move(__tp_prof_shapes), std::move(__tp_prof_dtypes));
    }
#ifdef USE_CUDA
    tensorplay::prof::GpuTimerPair __tp_gpu(__tp_prof_rec);
#endif
#ifdef USE_CUDA
    cuda::OptionalCUDAGuard device_guard(self.device());
#endif
    static const OperatorHandle op_handle = Dispatcher::singleton().findHandle("add");
    DispatchKey dispatch_key = toBackendKey(dispatchKeyForTensorArgs(self, other));
#ifdef USE_CUDA
    __tp_gpu.arm(self.device());
#endif
    auto&& __tp_result = DispatchStub<Tensor, const Tensor&, const Tensor&>::call(op_handle, dispatch_key, self, other);
#ifdef USE_CUDA
    __tp_gpu.close();
#endif
    if (tensorplay::prof::g_capture_shapes.load(std::memory_order_acquire)) {
        __tp_prof_rec.set_output_bytes(static_cast<int64_t>(__tp_result.numel()) * static_cast<int64_t>(__tp_result.itemsize()));
    }
    return std::move(__tp_result);
}
} // namespace detail
\end{lstlisting}

Details:

\begin{itemize}[leftmargin=1.4em]
\item \texttt{\_\_tp\_prof\_rec} is constructed first, before the shape branch, so the acquire-load happens even when shapes are not captured. The shape branch at iterates tensor-like args (\texttt{is\_tensor\_like}, handling \texttt{is\_list}, \texttt{is\_opt}, \texttt{is\_mutable\_ref}) and copies shapes/dtypes only when \texttt{g\_capture\_shapes} is set. The second load inside the branch means the fully-inactive path costs exactly one load.
\item For mutable ops the version bump after \texttt{DispatchStub::call} is preserved; for \texttt{void} returns the shape/output-bytes tail is omitted.
\item \texttt{set\_output\_bytes} is gated on the same \texttt{g\_capture\_shapes} load and only for \texttt{Tensor}-returning ops. This value feeds the memory snapshot view and is distinct from allocator-level \texttt{MemEvent} accounting.
\item The generator header includes \texttt{Profiler.h} at and \texttt{CUDARuntime.h} under \texttt{USE\_CUDA}, so the emitted TUs compile on both CPU and CUDA builds.
\end{itemize}

The public \texttt{Tensor::add} entry at delegates to \texttt{detail::redispatch\_add} after handling vmap, autocast and autograd dispatch keys; thus the same \texttt{OpRecord} covers both eager and graph-captured executions, and fused \texttt{stax} ops that still route through the dispatcher also report bytes.

\subsubsection{Why disabled is 2 cycles}

\texttt{OpRecord::begin} is one \texttt{memory\_order\_acquire} load of a static atomic, inlined to a \texttt{mov} + \texttt{cmp} + predicted not-taken branch on x86. No thread-local beyond the load, no call. The shape/site second loads sit inside the \texttt{g\_active} true-branch at and, so they add zero cycles when disabled. This matches \texttt{GradMode::is\_enabled} and \texttt{InferenceMode::is\_enabled} guards already emitted around every op.

\subsubsection{Why CPU is 30\,ns}

\texttt{now\_ns} is \texttt{chrono::steady\_clock::now.time\_since\_epoch.count}, which on Linux is a \texttt{clock\_gettime(CLOCK\_MONOTONIC)} vdso call ($\sim$15\,ns). The remaining $\sim$15\,ns is the \texttt{g\_mutex} uncontended lock plus \texttt{g\_events->push\_back} amortized allocation. The measured p50 over 200 iterations of \texttt{add} on 256$\times$512 at (single-thread pinned, \texttt{--threads 1 --framework tp}) is 28--35\,ns added latency.

\subsubsection{Why GPU events are 5\,\textmu s}

\texttt{cudaEventRecord} is a driver call that enqueues a marker on the stream; the per-op pair costs two records plus \texttt{acquire\_event} pool lookup. On the sm\_89 remote box cited, the measured round-trip is 4.2--6.1\,\textmu s. This is why GPU timing is not enabled by default: it dominates kernels shorter than $\sim$10\,\textmu s. For sub-10\,\textmu s kernels, \ac{cupti}'s \texttt{CONCURRENT\_KERNEL} activity is preferable because it timestamps on the GPU and reports asynchronously without per-op driver calls.

\begin{tpinsight}[Insight: One Atomic Separates ``Free'' from ``5\,\textmu s per Op'']
The profiler's cost model is not a smooth dial---it is a cliff structure with exactly three plateaus, and which plateau you occupy is decided by a single \texttt{atomic<bool>} load. Disabled costs $\sim$0.6\,ns because the acquire load inlines to one \texttt{cmp} against a cache line that is never written. Enabled-CPU costs $\sim$30\,ns because the true-branch pays a vdso clock read plus an uncontended mutex. Enabled-GPU costs $\sim$5\,\textmu s because each op arms two \texttt{cudaEventRecord} driver calls. The design lesson: put the \emph{cheapest possible test} in front of the most expensive mechanism, and make the test's false branch contain zero other loads. The shape/site captures obey the same discipline---their guards sit strictly \emph{inside} the \texttt{g\_active} true-branch, so a disabled session never touches their cache lines at all.
\end{tpinsight}

With \texttt{--threads 1} the CPU overhead column should be 8--14\% on 256$\times$512 matmul (base $\sim$12\,\textmu s, profiled $\sim$13.2\,\textmu s), shrinking to $<$2\% on larger shapes where kernel time dominates.

\subsection{Invariants and Edge Cases}

\begin{itemize}[leftmargin=1.2em]
\item \textbf{A1: Exactly one OpRecord per dispatched op.} The redispatch funnel is the single instrumentation site below autograd/autocast/vmap. Public \texttt{Tensor::add} never instruments directly; it delegates to \texttt{detail::redispatch\_add}. Custom operators that call \texttt{Dispatcher::singleton.findHandle} without going through codegen must emit their own \texttt{OpRecord} or be invisible (custom-op wrapper at \texttt{library.py} does so when \texttt{\_note\_profiling\_start} is live, \texttt{profiler.py}).
\item \textbf{A2: Slots stay stable until next start.} \texttt{g\_events} is cleared only by session start and moved out by session stop; the name arena is cleared there too but not after the per-slot move, preserving borrowed pointers until the binding copies them.
\item \textbf{A3: GPU pair stranded on exception is destroyed, not leaked.} If \texttt{DispatchStub::call} throws before \texttt{close}, the \texttt{GpuTimerPair} destructor calls \texttt{close} which still does \texttt{cupti\_pop\_ext} and destroys any acquired start event when \texttt{!rec\_.live\_}.
\item \textbf{A4: Stop waits for inflight.} Session stop waits on \texttt{g\_inflight\_cv} before swapping \texttt{g\_events}, so \texttt{gpu\_resolve\_all} never races a still-unwinding \texttt{\textasciitilde OpRecord} that would write \texttt{end\_ns} after the snapshot.
\item \textbf{A5: CUPTI FlushAll runs without the CUPTI mutex.} The mutex is released before \texttt{FlushAll(0)} because \texttt{buffer\_completed} takes the same mutex to parse and recycle buffers; holding it would deadlock.
\item \textbf{A6: No hard CUPTI/NVTX/ITT link.} All three bridges dlopen,. Missing libraries degrade to \texttt{cupti\_available==false} / \texttt{nvtx\_available==false} / \texttt{itt\_available==false} with a warning, never a link error. A stub provides the same interface for HIP builds.
\end{itemize}

\subsection{Design Trade-offs}
\label{sec:profiler:tradeoffs}

\textbf{Single global session vs.\ per-thread contexts.} Thread-local profiler state would allow concurrent independent sessions and remove the \texttt{g\_mutex} on the event path. Rejected: cross-thread attribution (which op spawned which GPU kernel) becomes ambiguous, and the whole-stack tools TensorPlay bridges to (Nsight via NVTX, VTune via ITT) are global-session by nature. The global \texttt{g\_events} at keeps the join trivial the price of one uncontended lock, $\sim$15\,ns of the 30\,ns enabled cost.

\textbf{\texttt{cudaEvent} pairs vs.\ CUPTI-only timing.} CUPTI \texttt{CONCURRENT\_KERNEL} activity alone could serve all GPU timing, making \texttt{GpuTimerPair} unnecessary. Rejected: CUPTI records only kernels and memcpys---user-level gaps, allocator stalls, and non-kernel work are invisible, and its asynchronous buffer completion makes per-op wall-clock attribution fuzzy. The event pair at measures stream time directly, including gaps, at a known constant $\sim$5\,\textmu s per op. The two are complementary: events for op-relative timing, CUPTI for kernel-level detail when sub-10\,\textmu s resolution matters.

\textbf{dlopen bridges vs.\ hard link dependencies.} Linking CUPTI/NVTX/ITT directly would remove all the availability atomics and stub files. Rejected: any of the three can be absent on a user box (CPU-only container, stripped driver, no VTune install), and a hard link would make \texttt{import tensorplay} fail there. The dlopen-at-first-use design degrades to ``feature off, warning printed,'' matching A6.
