\section{Profiler Subsystem: OpRecord, GpuTimerPair, and Backend Stack}
\label{sec:profiler}

\subsection{Goals and Placement}

The profiler must satisfy three conflicting goals: (i) near-zero overhead when disabled, (ii) accurate CPU+GPU timing when enabled, and (iii) pluggability of backends (CPU tracing, CUDA CUPTI activity, NVTX ranges, ITT tasks). TensorPlay places the core in \texttt{p10} so both \texttt{tpx} (Engine) and kernels can instrument without depending on Python. The Python layer (\texttt{tensorplay.profiler}) merely toggles atomics and drains buffers. Placement follows the dependency rule: \path{p10/include/Profiler.h} is the single header; \texttt{tpx} and \texttt{\_C} include it, never the reverse.

The hot path is one \texttt{std::atomic<bool>} load per dispatched op (\path{p10/include/Profiler.h:129}, \path{p10/src/Profiler.cpp:300}) plus, when shape or site capture is requested, one further load each. This matches the class of guard already emitted around every call for \texttt{GradMode} and \texttt{InferenceMode}. All other work (shape copy, name arena push, GPU event record) sits behind that branch.

Lifecycle, concrete path:line trace:

\begin{enumerate}[leftmargin=1.4em]
\item Construction calls \texttt{OpRecord::begin()} (\path{p10/src/Profiler.cpp:292--336}). First it checks \texttt{g\_emit\_nvtx} and \texttt{g\_emit\_itt} via relaxed loads (so NVTX/ITT ranges can fire without a profiling session for \texttt{kOp}, as noted at \path{Profiler.cpp:296--299}). Then it checks \texttt{g\_active} (\path{Profiler.cpp:300}); if false, returns immediately with \texttt{live\_=false}: disabled cost is one acquire-load and a predicted not-taken branch.
\item If active, it does \path{g\_inflight.fetch\_add(1)} (\path{Profiler.cpp:301}), snapshots \texttt{now\_ns()} (\path{Profiler.cpp:303} via \texttt{steady\_clock}), then locks \texttt{g\_mutex}. A second relaxed check of \texttt{g\_active} handles the race where \texttt{profiler\_stop()} cleared the flag between the two checks (\path{Profiler.cpp:305--309}).
\item It builds an \texttt{Event} (\path{Profiler.cpp:310--324}): \texttt{name} is either the static literal (\texttt{kOp} path, \path{Profiler.cpp:311}) or an arena copy in \texttt{g\_name\_arena} (\path{Profiler.cpp:316--319} for \texttt{kUser}/\texttt{kBackward}). \texttt{tid} comes from \texttt{this\_thread\_id()} (\path{Profiler.cpp:313}, defined at \path{Profiler.cpp:55--61} as a \texttt{thread\_local} hash of \path{std::this\_thread::get\_id()}). If \path{t\_pending\_site.valid} is set, its \path{site\_id/stack\_id} are consumed and cleared (\path{Profiler.cpp:320--324}) so inner composite ops do not inherit the outermost Python site.
\item If \texttt{nvtx\_on || itt\_on}, it calls \path{nvtx\_span\_begin(e.name)} and \path{itt\_span\_begin(e.name)} (\path{Profiler.cpp:325--331}) and sets \path{nvtx\_open\_/itt\_open\_}. Then \path{g\_events->push\_back(e)} and \texttt{slot\_ = size-1}, \texttt{start\_ns\_ = start}, \texttt{live\_=true} (\path{Profiler.cpp:332--335}).
\item \texttt{set\_io\_meta()} (\path{Profiler.cpp:365--373}) and \path{set\_output\_bytes()} (\path{Profiler.cpp:375--378}) lock \texttt{g\_mutex} and write into \path{(*g\_events)[slot\_]} if \texttt{live\_} and slot is in bounds. \texttt{set\_shapes()} is a shapes-only overload for generated dispatchers where dtypes stay unset (\path{Profiler.h:159}, \path{Profiler.cpp:381--383}).
\item Destruction (\path{Profiler.cpp:346--363}) always closes NVTX/ITT first (\path{Profiler.cpp:347--348}), then if \texttt{!live\_} returns. Otherwise it records \texttt{end = now\_ns()}, locks \texttt{g\_mutex}, writes \path{(*g\_events)[slot\_].end\_ns = end} if the slot still exists (dropped silently if \texttt{profiler\_stop()} already cleared the vector), then calls \texttt{release\_inflight()} which does \path{g\_inflight.fetch\_sub(1)} and notifies \texttt{g\_inflight\_cv} when the count reaches zero (\path{Profiler.cpp:44--48}).
\end{enumerate}

The \texttt{g\_inflight} protocol is critical for correctness: \texttt{profiler\_stop()} at \path{Profiler.cpp:110--120} first stores \texttt{g\_active=false}, then waits on \texttt{g\_inflight\_cv} until \texttt{g\_inflight==0} before taking \texttt{g\_mutex} and moving \texttt{g\_events} out. This prevents a CUDA or CPU worker from appending \texttt{gpu\_ms} or \texttt{end\_ns} after \texttt{gpu\_resolve\_all} has snapshotted the vector.

\subsection{Storage: Append-Only Vector as Logical RingBuffer}

The original design document calls this component \texttt{RingBuffer} (\path{p10/include/RingBuffer.h} in the draft). The shipped implementation realizes the same logical buffer as an append-only vector guarded by a mutex plus stable slot indices. Concrete state in \path{p10/src/Profiler.cpp:18--45}:

\begin{lstlisting}[caption={\path{Profiler.cpp:18} --- session storage.}, label=lst:profstorage, style=cppstyle]
std::mutex g_mutex;
std::vector<Event>* g_events = nullptr;              // append-only, slots stable
std::vector<MemEvent>* g_mem_events = nullptr;
std::deque<std::string>* g_name_arena = nullptr;     // owns user/backward names
std::vector<std::pair<std::string,int>>* g_site_table = nullptr;
std::unordered_map<std::string,uint32_t>* g_site_index = nullptr;
std::deque<std::string>* g_frame_arena = nullptr;
std::unordered_map<std::string,uint32_t>* g_frame_index = nullptr;
std::vector<std::vector<uint32_t>>* g_stack_table = nullptr;
std::deque<ProfFrame>* g_frame_store = nullptr;
std::atomic<uint64_t> g_inflight{0};
std::mutex g_inflight_mutex;
std::condition_variable g_inflight_cv;
\end{lstlisting}

Why a vector and not a fixed ring: slots are referenced by \texttt{OpRecord::slot\_} and by \texttt{GpuTimerPair}'s external correlation id (\texttt{slot\_} cast to \texttt{uint64\_t} at \path{ProfilerGpu.cpp:150}) for the entire session. A ring that overwrites would invalidate those indices. The binding layer drains the vector in \texttt{profiler\_stop()} (\path{Profiler.cpp:122--137}) via \path{std::move(*g\_events)} then \texttt{stable\_sort} by \texttt{start\_ns}. The arena (\texttt{g\_name\_arena}) stays alive until the next \texttt{profiler\_start()} because \texttt{Event::name} for user spans is a borrowed pointer into it (\path{Profiler.cpp:128--132} comment).

Pending Python site handling is thread-local at \path{Profiler.cpp:64--68}:

\begin{lstlisting}[caption={\path{Profiler.cpp:64} --- per-thread pending site.}, label=lst:pendingsite, style=cppstyle]
thread_local struct {
  bool valid = false;
  uint32_t site_id = Event::kNoSite;
  uint32_t stack_id = Event::kNoSite;
} t_pending_site;
\end{lstlisting}

\texttt{set\_python\_site()} (\path{Profiler.cpp:140--145}) and \path{set\_python\_stack()} (\path{Profiler.cpp:147--160}) are called by the binding layer while the GIL is held; they intern through \texttt{intern\_site()} (\path{Profiler.cpp:258--271}) and \texttt{intern\_stack()} (\path{Profiler.cpp:162--196}) which dedup via \texttt{g\_site\_index} and \texttt{g\_frame\_index}. The next \texttt{OpRecord::begin()} on that thread consumes the pending site and clears \texttt{valid} (\path{Profiler.cpp:320--324}), so inner composite ops record no site instead of repeating the outermost call.

User annotations have their own LIFO stack at \path{Profiler.cpp:387--389} (\path{thread\_local std::vector<size\_t> t\_user\_stack}) pushed in \texttt{user\_span\_begin()} (\path{Profiler.cpp:391--411}) and popped in \texttt{user\_span\_end()} (\path{Profiler.cpp:413--421}). Both manipulate \texttt{g\_events} under \texttt{g\_mutex} and emit NVTX around the push/pop (\path{Profiler.cpp:410,415}).

The logical RingBuffer properties that remain: no allocation on the hot path beyond the vector's amortized growth (op events are 64 bytes plus optional shared\_ptr payloads), and the buffer is drained exactly once at session stop.

\subsection{GpuTimerPair: cudaEvent vs.\ CUPTI Selection}

\path{p10/include/Profiler.h:227--240} declares \texttt{GpuTimerPair} as a pool-backed \texttt{cudaEvent\_t} pair plus CUPTI correlation bracketing:

\begin{lstlisting}[caption={\path{Profiler.h:227} --- GpuTimerPair handle.}, label=lst:gputimerpair, style=cppstyle]
struct TENSORPLAY_API GpuTimerPair {
  explicit GpuTimerPair(OpRecord& rec) : rec_(rec) {}
  ~GpuTimerPair();
  void arm(const Device& device);  // records start on a CUDA op's stream
  void close();                    // records the end event
private:
  OpRecord& rec_;
  void* gpu_start_ = nullptr;
  void* gpu_stream_ = nullptr;
  int gpu_device_ = -1;
  bool armed_ = false;
};
\end{lstlisting}

The implementation lives in \path{p10/src/ProfilerGpu.cpp}. For \texttt{!USE\_CUDA} it compiles to no-ops at \path{ProfilerGpu.cpp:308--315} so generated code links without \texttt{\#ifdef} noise.

\subsubsection{Selection logic in \texttt{arm()} (\path{ProfilerGpu.cpp:142--163})}

\begin{lstlisting}[caption={\path{ProfilerGpu.cpp:142} --- arm() selection.}, label=lst:gpuarm, style=cppstyle]
void GpuTimerPair::arm(const Device& device) {
  if (!rec_.live_ || !device.is_cuda()) return;
  if (g_gpu_trace.load(memory_order_acquire)) {
    rec_.trace_pushed_ = cupti_push_ext(static_cast<uint64_t>(rec_.slot_));
  }
  if (!g_gpu_timing.load(memory_order_acquire)) return;
  const auto stream = cuda::getCurrentCUDAStream();
  cudaEvent_t start = acquire_event(stream.device_index());
  if (!start || cudaEventRecord(start, stream.stream()) != cudaSuccess) {
    if (start) (void)cudaEventDestroy(start);
    return;
  }
  gpu_start_ = start;
  gpu_stream_ = stream.stream();
  gpu_device_ = stream.device_index();
  armed_ = true;
}
\end{lstlisting}

Two orthogonal features interleave:

\begin{itemize}[leftmargin=1.4em]
\item \textbf{CUPTI correlation} is independent of \texttt{g\_gpu\_timing}. If \texttt{g\_gpu\_trace} is set (\path{Profiler.h:258}), \texttt{arm()} pushes the op's slot as an external correlation id via \texttt{cupti\_push\_ext()} (\path{ProfilerCupti.cpp:549--558}) onto CUPTI's per-thread stack. This happens even when event timing is off, so a \texttt{gpu\_trace} session correlates kernels without paying \texttt{cudaEventRecord} cost.
\item \textbf{cudaEvent timing} is gated on \texttt{g\_gpu\_timing} (\path{Profiler.h:241}). When on, \texttt{arm()} acquires a pooled \texttt{cudaEvent\_t} via \texttt{acquire\_event()} (\path{ProfilerGpu.cpp:54--74}, recycles from \texttt{g\_pool} under \texttt{g\_gpu\_mutex} or creates with \path{cudaEventCreateWithFlags}), records it on the current stream (\path{cuda::getCurrentCUDAStream()}, \path{ProfilerGpu.cpp:153--155}), and saves device/stream/event.
\end{itemize}

\texttt{close()} at \path{ProfilerGpu.cpp:165--195} follows the same order: first it pops the CUPTI correlation if one was pushed (\path{ProfilerGpu.cpp:166--169} via \texttt{cupti\_pop\_ext()} at \path{ProfilerCupti.cpp:561--567}), then if \texttt{armed\_} records the end event via \texttt{acquire\_event()} and \texttt{cudaEventRecord} (\path{ProfilerGpu.cpp:186--191}), and appends a \texttt{LivePair\{slot,device,stream,start,end\}} to \texttt{g\_live} under \texttt{g\_gpu\_mutex} (\path{ProfilerGpu.cpp:192--195}). Profiling never makes a valid op fail: every CUDA error path destroys the partial event and returns.

\subsubsection{Resolution at session stop (\path{ProfilerGpu.cpp:198--271})}

\texttt{gpu\_resolve\_all()} is called from the binding's \texttt{\_profiler\_stop} at \path{src/bindings/python/init.cpp:545} after \texttt{profiler\_stop()} but before returning to Python. Key steps (\path{ProfilerGpu.cpp:198--271}):

\begin{enumerate}[leftmargin=1.4em]
\item Swap \texttt{g\_live} out under the mutex (\path{ProfilerGpu.cpp:204--207}) so dispatch can continue while resolution runs.
\item Compute a deadline from \path{TP\_PROFILER\_GPU\_TIMEOUT\_MS} (default 5000\,ms, \path{ProfilerGpu.cpp:76--87}).
\item Build \texttt{last\_on\_stream} map: one wait per stream is sufficient because CUDA orders event records on a stream (\path{ProfilerGpu.cpp:215--220}).
\item For each stream's last end event, call \texttt{wait\_event()} which polls \texttt{cudaEventQuery} with \texttt{50\,\textmu s} sleeps until success or deadline (\path{ProfilerGpu.cpp:89--98}). This avoids a device-wide synchronize.
\item Resolve each pair via \path{cudaEventElapsedTime} (\path{ProfilerGpu.cpp:236}). On success, write \path{events[slot].gpu\_ms = ms} and invoke the \texttt{emit} callback (\path{ProfilerGpu.cpp:239--240}). Reusable events go to a local \texttt{reusable} vector; failed pairs are destroyed via \path{destroy\_event\_pair()} which does \texttt{cudaEventDestroy} even for pending events (\path{ProfilerGpu.cpp:123--129}). Pending pairs are intentionally not returned to the pool so the next session starts clean.
\item Return reusable events to \texttt{g\_pool} under one lock (\path{ProfilerGpu.cpp:260--265}) and restore the caller's device (\path{ProfilerGpu.cpp:269--270}).
\end{enumerate}

The pool at \path{ProfilerGpu.cpp:41--52} is \path{unordered\_map<int, deque<cudaEvent\_t>>} keyed by device index, created with \texttt{cudaEventDefault} (timing on). \texttt{gpu\_drain\_pool()} at \path{ProfilerGpu.cpp:273--295} swaps and destroys all pooled and live events, used by the binding at process teardown.

\subsection{Integration I: Code Generation (\path{tools/codegen/gen\_api.py})}

Every dispatched execution passes through exactly one \path{detail::redispatch\_*} funnel. The generator instruments that funnel so the profiler sees each op once, below autograd and autocast. At \path{tools/codegen/gen\_api.py:321--444} (\texttt{\_emit\_redispatch}):

\begin{lstlisting}[caption={\path{gen\_api.py:321} --- redispatch instrumentation.}, label=lst:genredispatch, style=cppstyle]
namespace detail {
TENSORPLAY_API Tensor redispatch_add(const Tensor& self, const Tensor& other) {
    tensorplay::prof::OpRecord __tp_prof_rec("add");
    if (tensorplay::prof::g_capture_shapes.load(std::memory_order_acquire)) {
        std::vector<std::vector<int64_t>> __tp_prof_shapes;
        std::vector<int32_t> __tp_prof_dtypes;
        __tp_prof_shapes.push_back(static_cast<std::vector<int64_t>>(self.shape()));
        __tp_prof_dtypes.push_back(static_cast<int32_t>(self.dtype()));
        __tp_prof_shapes.push_back(static_cast<std::vector<int64_t>>(other.shape()));
        __tp_prof_dtypes.push_back(static_cast<int32_t>(other.dtype()));
        __tp_prof_rec.set_io_meta(std::move(__tp_prof_shapes), std::move(__tp_prof_dtypes));
    }
#ifdef USE_CUDA
    tensorplay::prof::GpuTimerPair __tp_gpu(__tp_prof_rec);
#endif
#ifdef USE_CUDA
    cuda::OptionalCUDAGuard device_guard(self.device());
#endif
    static const OperatorHandle op_handle = Dispatcher::singleton().findHandle("add");
    DispatchKey dispatch_key = toBackendKey(dispatchKeyForTensorArgs(self, other));
#ifdef USE_CUDA
    __tp_gpu.arm(self.device());
#endif
    auto&& __tp_result = DispatchStub<Tensor, const Tensor&, const Tensor&>::call(op_handle, dispatch_key, self, other);
#ifdef USE_CUDA
    __tp_gpu.close();
#endif
    if (tensorplay::prof::g_capture_shapes.load(std::memory_order_acquire)) {
        __tp_prof_rec.set_output_bytes(static_cast<int64_t>(__tp_result.numel()) * static_cast<int64_t>(__tp_result.itemsize()));
    }
    return std::move(__tp_result);
}
} // namespace detail
\end{lstlisting}

Details:

\begin{itemize}[leftmargin=1.4em]
\item \texttt{\_\_tp\_prof\_rec} is constructed first (\path{gen\_api.py:327}), before the shape branch, so the acquire-load happens even when shapes are not captured. The shape branch at \path{gen\_api.py:335--389} iterates tensor-like args (\texttt{is\_tensor\_like}, handling \texttt{is\_list}, \texttt{is\_opt}, \texttt{is\_mutable\_ref}) and copies shapes/dtypes only when \texttt{g\_capture\_shapes} is set. The second load inside the branch means the fully-inactive path costs exactly one load.
\item For mutable ops (\path{gen\_api.py:446--462}) the version bump after \texttt{DispatchStub::call} is preserved; for \texttt{void} returns the shape/output-bytes tail is omitted.
\item \texttt{set\_output\_bytes} at \path{gen\_api.py:435--443} is gated on the same \texttt{g\_capture\_shapes} load and only for \texttt{Tensor}-returning ops. This value feeds the memory snapshot view (\path{Profiler.h:84--87}) and is distinct from allocator-level \texttt{MemEvent} accounting.
\item The generator header includes \texttt{Profiler.h} at \path{gen\_api.py:295} and \texttt{CUDARuntime.h} under \texttt{USE\_CUDA} at \path{gen\_api.py:297}, so the emitted TUs compile on both CPU and CUDA builds.
\end{itemize}

The public \texttt{Tensor::add} entry at \path{gen\_api.py:566} delegates to \path{detail::redispatch\_add} after handling vmap, autocast and autograd dispatch keys; thus the same \texttt{OpRecord} covers both eager and graph-captured executions, and fused \texttt{stax} ops that still route through the dispatcher also report bytes.

\subsubsection{Why disabled is 2 cycles}

\texttt{OpRecord::begin()} at \path{Profiler.cpp:300} is one \path{memory\_order\_acquire} load of a static atomic, inlined to a \texttt{mov} + \texttt{cmp} + predicted not-taken branch on x86. No thread-local beyond the load, no call. The shape/site second loads sit inside the \texttt{g\_active} true-branch at \path{gen\_api.py:336} and \path{Profiler.cpp:297--299}, so they add zero cycles when disabled. This matches \path{GradMode::is\_enabled()} and \path{InferenceMode::is\_enabled()} guards already emitted around every op.

\subsubsection{Why CPU is 30\,ns}

\texttt{now\_ns()} at \path{Profiler.cpp:50--53} is \path{chrono::steady\_clock::now().time\_since\_epoch().count()}, which on Linux is a \path{clock\_gettime(CLOCK\_MONOTONIC)} vdso call ($\sim$15\,ns). The remaining $\sim$15\,ns is the \texttt{g\_mutex} uncontended lock plus \path{g\_events->push\_back} amortized allocation. The measured p50 over 200 iterations of \texttt{add} on 256$\times$512 at \path{tools/bench\_profiler\_overhead.py:64--89} (single-thread pinned, \path{--threads 1 --framework tp}) is 28--35\,ns added latency.

\subsubsection{Why GPU events are 5\,\textmu s}

\texttt{cudaEventRecord} is a driver call that enqueues a marker on the stream; the per-op pair costs two records plus \texttt{acquire\_event} pool lookup at \path{ProfilerGpu.cpp:54--74}. On the sm\_89 remote box cited at \path{ProfilerGpu.cpp:15}, the measured round-trip is 4.2--6.1\,\textmu s. This is why GPU timing is not enabled by default: it dominates kernels shorter than $\sim$10\,\textmu s. For sub-10\,\textmu s kernels, CUPTI's \texttt{CONCURRENT\_KERNEL} activity at \path{ProfilerCupti.cpp:251--261} is preferable because it timestamps on the GPU and reports asynchronously without per-op driver calls.

\subsection{Invariants and Edge Cases}

\begin{itemize}[leftmargin=1.2em]
\item \textbf{A1: Exactly one OpRecord per dispatched op.} The redispatch funnel at \path{tools/codegen/gen\_api.py:327} is the single instrumentation site below autograd/autocast/vmap. Public \texttt{Tensor::add} at \path{gen\_api.py:566} never instruments directly; it delegates to \path{detail::redispatch\_add}. Custom operators that call \path{Dispatcher::singleton().findHandle} without going through codegen must emit their own \texttt{OpRecord} or be invisible (custom-op wrapper at \path{tensorplay/library.py} does so when \path{\_note\_profiling\_start} is live, \path{profiler.py:222,228}).
\item \textbf{A2: Slots stay stable until next start.} \texttt{g\_events} is cleared only in \path{clear\_session\_locked()} at \path{Profiler.cpp:70--83} (called by \texttt{profiler\_start}) and moved out in \texttt{profiler\_stop} at \path{Profiler.cpp:122--126}; the arena \texttt{g\_name\_arena} is cleared there too but not after the per-slot move, preserving borrowed pointers until the binding copies them at \path{init.cpp:605--609}.
\item \textbf{A3: GPU pair stranded on exception is destroyed, not leaked.} If \texttt{DispatchStub::call} throws before \texttt{close()}, \path{GpuTimerPair::\textasciitilde GpuTimerPair} at \path{ProfilerGpu.cpp:137--140} calls \texttt{close()} which still does \texttt{cupti\_pop\_ext} (\path{ProfilerGpu.cpp:166--169}) and destroys any acquired start event when \texttt{!rec\_.live\_} (\path{ProfilerGpu.cpp:182--185}).
\item \textbf{A4: Stop waits for inflight.} \texttt{profiler\_stop} at \path{Profiler.cpp:115--120} waits on \texttt{g\_inflight\_cv} before swapping \texttt{g\_events}, so \texttt{gpu\_resolve\_all} at \path{init.cpp:545} never races a still-unwinding \path{\textasciitilde OpRecord} that would write \texttt{end\_ns} after the snapshot.
\item \textbf{A5: CUPTI FlushAll runs without g\_cupti\_mutex.} At \path{ProfilerCupti.cpp:514--521} the mutex is released before \texttt{FlushAll(0)} because \texttt{buffer\_completed} takes the same mutex to parse and recycle buffers; holding it would deadlock.
\item \textbf{A6: No hard CUPTI/NVTX/ITT link.} All three bridges dlopen at \path{ProfilerCupti.cpp:425}, \path{ProfilerNvtx.cpp:64}, \path{ProfilerItt.cpp:55}. Missing libraries degrade to \path{cupti\_available()==false} / \path{nvtx\_available()==false} / \path{itt\_available()==false} with a warning, never a link error. The stub at \path{ProfilerCuptiStub.cpp} provides the same for HIP.
\end{itemize}
