\section{Four-Pillar Decomposition}
\label{sec:arch}

The framework is partitioned into four physically isolated shared libraries plus one Python extension, all produced from a single CMake invocation. Isolation is not editorial; it is enforced by directory, target, link edge, and header visibility. A newcomer reads \texttt{p10} to understand tensor storage without learning any differentiation concept; a kernel author rebuilds only \texttt{p10} after touching an arithmetic kernel; a compiler author experiments inside \texttt{stax} without relinking the storage layer. The cost is explicit boundaries and the absence of whole-program inlining, which this project accepts.

\subsection{Directory \texorpdfstring{$\rightarrow$}{->} Artifact Mapping}
\label{sec:arch:mapping}

Each pillar is a CMake target whose \texttt{OUTPUT\_DIRECTORY} is pinned to a location inside the \texttt{tensorplay} package tree, so an in-tree build is importable without installation and a wheel is importable without \texttt{LD\_LIBRARY\_PATH}. Table~\ref{tab:pillars} is the normative map.

Concretely, \texttt{TP\_PACKAGE\_DIR} defaults to the source tree's \texttt{tensorplay/} directory, and \texttt{TP\_LIB\_DIR} is \texttt{\$\{TP\_PACKAGE\_DIR\}/lib}. The Python surface comprises hundreds of modules, but only one compiled extension is ever imported. The veneer re-exports more than 550 native symbols discovered by enumerating \texttt{dir(\_C)} and filtering \texttt{\_\_module\_\_} rewriting (\S\ref{sec:veneer}). No Python file adds a new CMake target; every Python module is a thin wrapper whose heavy work re-enters \texttt{\_C}.

\subsection{Build Order and the Vacated-Source Record}
\label{sec:arch:buildorder}

 declares the order in exactly four lines:

\begin{lstlisting}[caption={pillar order is load-bearing.}, label=lst:buildorder]
# Add p10
add_subdirectory(p10)          # :938
# Add tpx
add_subdirectory(tpx)          # :941
# Add stax (Optional)
add_subdirectory(stax)         # :944
\end{lstlisting}

 links \texttt{p10} privately; re-exports it publicly so consumers that depend on \texttt{tpx} automatically get the p10 interface. links both \texttt{p10} and \texttt{tpx} privately and re-exports \texttt{p10} publicly at line~17. links \texttt{\_C} against \texttt{p10 tpx stax tp\_python}: this is the only place where the three levels meet. Reordering any of these three \texttt{add\_subdirectory} calls or adding a back edge immediately fails with a CMake configure error or an undefined reference at link time, not a silent runtime mis-order.

The generate step precedes all of this. At a \texttt{custom\_command} generates ten artifacts under  from \texttt{native\_functions.yaml} and \texttt{derivatives.yaml} via \texttt{main.py}. Every pillar target declares \texttt{add\_dependencies(generate\_code)} (e.g.\,). The generated header is mixed into via \texttt{TensorGenerated.h"}; the generated source is appended to \texttt{P10\_SOURCES} at as \texttt{\$\{GEN\_CPP\}}. Thus a YAML edit rebuilds only the changed generated file plus its dependents.

 retains a single commented line:

\begin{lstlisting}[caption={The vacated-source comment in the p10 build file: metadata that once violated the axiom was physically moved out, leaving this trail.}, label=lst:audittrail]
    # src/AutogradMetaInterface.cpp (Moved to TPX)
\end{lstlisting}

This is intentional. An earlier revision implemented the concrete metadata inside \texttt{p10}; the current design keeps \texttt{p10} header-free of \texttt{tpx} so the USB slot at suffices. Leaving the comment in the source list records the decision boundary: grepping the comment proves the file once lived in \texttt{p10} and was deliberately vacated to preserve acyclicity. Deleting it would erase the history of why \texttt{p10} must not include \texttt{tpx}; resurrecting it inside \texttt{p10} would reintroduce a back edge and break the invariant checked by  which must return empty.

A related discipline appears. On Windows where \texttt{BUILD\_SHARED\_LIBS} is normally \texttt{ON} for Linux wheels, the block forces \texttt{BUILD\_SHARED\_LIBS OFF}:

\begin{lstlisting}[caption={Windows static embedding.}, label=lst:winstatic]
if(WIN32 AND BUILD_SHARED_LIBS)
    set(BUILD_SHARED_LIBS OFF)
endif()
\end{lstlisting}

Without the switch, each DLL would require \texttt{\_\_declspec(dllexport)} on every p10 symbol crossing the boundary, which the codebase does not carry. Static linking on Windows embeds the three pillars into the single module \texttt{\_C.pyd} and keeps symbol visibility identical to the Linux shared-library layout without annotating every class.

\subsection{Product Layout: RPATH and the Two Preload Paths}
\label{sec:arch:rpath}

After a build, the package tree is the product:

\begin{lstlisting}[caption={Post-build layout under the package directory.}, label=lst:layout]
tensorplay/
  lib/
    libp10.so
    libtpx.so
    libstax.so
    libtp_python.so
    cudart64_*.dll / cublas64_*.dll / cudnn*.dll   # Windows wheels only
  _C/
    __init__.so          # OUTPUT_NAME "__init__" :1176
    __init__.pyi
  __init__.py            # 1,197 lines, three dirty jobs
  _tensor.py             # Tensor = _C.TensorBase :12
  version.py             # generated at :330
\end{lstlisting}

The relative RPATH makes the layout relocatable. From:

\begin{lstlisting}[caption={RPATH is the loader contract.}, label=lst:rpath]
if(NOT WIN32)
    set_target_properties(p10 tpx stax PROPERTIES
        INSTALL_RPATH "$ORIGIN"
        BUILD_RPATH "$ORIGIN"
    )
    set_target_properties(tp_python PROPERTIES
        INSTALL_RPATH "$ORIGIN"
        BUILD_RPATH "$ORIGIN"
    )
    set_target_properties(_C PROPERTIES
        INSTALL_RPATH "$ORIGIN/../lib"
        BUILD_RPATH "$ORIGIN/../lib"
    )
endif()
\end{lstlisting}

\texttt{p10}, \texttt{tpx}, \texttt{stax}, and \texttt{tp\_python} reside together in \texttt{lib}, so \texttt{\$ORIGIN} suffices: each \ac{dso} finds its siblings without an absolute path, and no \ac{rpath} edit is needed when the tree moves. \texttt{\_C} lives one directory deeper in \texttt{\_C}, so it uses \texttt{lib}. Verification is a single command with no Python involved:

\begin{lstlisting}[caption={Linux loader verification without importing Python.}, label=lst:readelf]
readelf -d tensorplay/lib/libp10.so | grep -i rpath      # $ORIGIN
readelf -d tensorplay/lib/libtpx.so | grep -i rpath      # $ORIGIN
readelf -d tensorplay/_C/__init__.so | grep -i rpath     # $ORIGIN/../lib
ldd tensorplay/_C/__init__.so | grep "not found"          # must be empty
\end{lstlisting}

Failure without this block manifests as \texttt{ImportError: libp10.so: cannot open shared object file} when the wheel is installed into a virtual environment whose \texttt{LD\_LIBRARY\_PATH} is empty, which is precisely the target scenario for a wheel. The comment at documents this as the single reason RPATH exists; Windows ignores RPATH entirely, so the Windows branch is guarded by \texttt{if(NOT WIN32)}.

Windows uses explicit preload instead. defines \texttt{\_load\_dll\_libraries} guarded by \texttt{sys.platform == 'win32'}:

\begin{lstlisting}[caption={ordered DLL preload on Windows.}, label=lst:winpreload]
kernel32 = ctypes.WinDLL("kernel32.dll", use_last_error=True)
# MKL -> CUDA/cuDNN -> p10/tpx/stax   :80
mkl_dlls = glob.glob(os.path.join(package_lib_path, "mkl_*.dll"))
cuda_dlls = glob.glob(os.path.join(package_lib_path, "cudart*.dll")) + \
            glob.glob(os.path.join(package_lib_path, "cublas*.dll")) + \
            glob.glob(os.path.join(package_lib_path, "cudnn*.dll"))
core_dlls = [os.path.join(package_lib_path, "p10.dll"),
             os.path.join(package_lib_path, "tpx.dll"),
             os.path.join(package_lib_path, "stax.dll")]

    if with_load_library_flags:
        res = kernel32.LoadLibraryExW(dll, None, 0x00001100)  # :122
    else:
        res = kernel32.LoadLibraryW(dll)
\end{lstlisting}

\texttt{0x00001100} is \texttt{LOAD\_LIBRARY\_SEARCH\_DEFAULT\_DIRS | LOAD\_LIBRARY\_SEARCH\_DLL\_LOAD\_DIR}, the minimally permissive flag that still searches the package lib directory added earlier via \texttt{os.add\_dll\_directory}. Order is load-bearing: \texttt{mkl\_core} and \texttt{mkl\_sequential} are sorted first inside the MKL group at lines~85--94 because \texttt{mkl\_def} and \texttt{mkl\_avx2} depend on them; CUDA runtime is loaded before \texttt{p10} so that \texttt{CUDA::cudart} symbols required by p10's CUDA kernels are already resolved. The helper \texttt{\_add\_dll\_directory} tries both \texttt{lib} and the legacy  root, plus the interpreter's \texttt{bin}, the base environment, and the user site-packages bin, each guarded by \texttt{os.path.exists} so a missing Conda installation does not error.

\subsection{Virtual-Interface Decoupling: the USB Slot}
\label{sec:arch:usb}

 cannot include \texttt{tpx} yet must carry the differentiation state for tensors that require grad. The naive alternatives are both rejected: putting concrete fields (\texttt{grad\_fn\_}, \texttt{grad\_}) into \texttt{p10} couples storage to differentiation; letting \texttt{p10} include a \texttt{tpx} header creates a circular dependency that \texttt{cmake --build} cannot topologically sort and that defeats incremental builds. The design instead declares a pure abstract slot in \texttt{p10} and plugs a concrete object from \texttt{tpx} through \texttt{shared\_ptr<AutogradMetaBase>} and a \texttt{static\_cast} handshake.

At the slot is four operations, each pure virtual:

\begin{lstlisting}[caption={the pure interface.}, label=lst:autogradbase2]
class P10_API AutogradMetaBase {
public:
  virtual ~AutogradMetaBase() = default;
  virtual bool requires_grad() const = 0;
  virtual void set_requires_grad(bool) = 0;
  virtual Tensor grad() const = 0;
  virtual void set_grad(const Tensor&) = 0;
  virtual bool retains_grad() const = 0;
  virtual void set_retains_grad(bool) = 0;
};
\end{lstlisting}

The header includes only \texttt{Macros.h}; it forwards \texttt{class Tensor} without including \texttt{Tensor.h}, so the compile-time footprint is a single vtable plus six virtual slots (48 bytes on x86-64). No kernel, no engine, no graph concept crosses the boundary here.

 holds the slot:

\begin{lstlisting}[caption={never-copied owner.}, label=lst:implslot]
  // Autograd extension point.
  // Never copied by TensorImpl copy operations: copies start without history.
  std::shared_ptr<AutogradMetaBase> autograd_meta_;
\end{lstlisting}

The copy constructor at deliberately omits this member:

\begin{lstlisting}[caption={history is not duplicated.}, label=lst:copyctor]
TensorImpl::TensorImpl(const TensorImpl& other)
    : storage_offset_(other.storage_offset_),
      sizes_and_strides_(other.sizes_and_strides_),
      dtype_(other.dtype_),
      device_(other.device_),
      version_counter_(other.version_counter_),
      inference_tensor_(other.inference_tensor_),
      is_contiguous_(other.is_contiguous_),
      memory_format_(other.memory_format_),
      storage_(other.storage_),
      shared_state_(other.shared_state_),
      sparse_state_(other.sparse_state_),
      transform_value_(other.transform_value_),
      transform_batch_dim_(other.transform_batch_dim_),
      transform_level_(other.transform_level_),
      quantizer_(other.quantizer_) {}
      // autograd_meta_ is intentionally absent: default-initialized to nullptr
\end{lstlisting}

Thus \texttt{Tensor b = a;} shares storage, sizes, strides, device, dtype, sparse state, quantizer, and the version counter alias, but not the graph. The invariant is: shape mutation and storage aliasing propagate; history does not. Move operations are defaulted, and \texttt{copy\_metadata\_from} at preserves the preservation of \texttt{autograd\_meta\_} by omission.
This matches the ``never copied'' contract at and enables \texttt{auto y = x + 1; y.backward} where \texttt{x} stays a leaf and \texttt{y} becomes its child without aliasing metadata.

The concrete plug lives in:

\begin{lstlisting}[caption={concrete fields, tpx only.}, label=lst:autogradconcrete]
class TENSORPLAY_API AutogradMeta : public AutogradMetaBase {
private:
  bool requires_grad_ = false;
  bool retains_grad_ = false;
  tensorplay::Tensor grad_;
  std::shared_ptr<Node> grad_fn_;
  std::weak_ptr<Node> grad_accumulator_; // avoids leaf cycle
  uint32_t output_nr_ = 0;
  bool has_view_info_ = false;
  tensorplay::Tensor view_base_;
  std::vector<int64_t> view_sizes_;
  std::vector<int64_t> view_strides_;
  int64_t view_storage_offset_ = 0;
  std::function<tensorplay::Tensor(const tensorplay::Tensor&)> view_fn_;
  mutable std::mutex view_mutex_;
};
\end{lstlisting}

\texttt{grad\_accumulator\_} is \texttt{weak\_ptr<Node>} rather than \texttt{shared\_ptr<Node>} because \texttt{AccumulateGrad} strongly owns its leaf tensor; a strong back edge would form an uncollectable cycle that leaks every leaf that ever participated in a graph. All other members are owned strongly; \texttt{view\_fn\_} plus \texttt{view\_mutex\_} support stale-view replay.

The handshake is the two helpers, each a single \texttt{static\_cast} with no \texttt{dynamic\_cast} on the hot path:

\begin{lstlisting}[caption={the cast boundary.}, label=lst:handshake]
AutogradMeta* get_autograd_meta(const Tensor& t) {
    if (auto* impl = t.unsafeGetTensorImpl().get()) {
        return static_cast<AutogradMeta*>(impl->autograd_meta()); // :17
    }
    return nullptr;
}
AutogradMeta* get_or_create_autograd_meta(const Tensor& t) {
    auto impl = t.unsafeGetTensorImpl();
    if (!impl) return nullptr;
    if (auto* meta = impl->autograd_meta()) {
        return static_cast<AutogradMeta*>(meta);                  // :26
    }
    auto meta = std::make_shared<AutogradMeta>();
    auto* raw = meta.get();
    impl->set_autograd_meta(std::move(meta));                      // :30
    return raw;
}
\end{lstlisting}

The call at line~17 is safe because the only concrete subclass ever assigned to \texttt{autograd\_meta\_} is \texttt{AutogradMeta}, constructed at line~28 and installed at line~30. No header in \texttt{p10} ever sees \texttt{AutogradMeta.h}, so the build never lists that include path. The static type system plus the shared-library boundary together enforce the invariant.
A second proof is the failed build when the cast target changes: if \texttt{tpx} were to rename \texttt{AutogradMeta} without updating the cast, the extension \texttt{\_C} would fail to link with \texttt{undefined reference to tensorplay::tpx::AutogradMeta} rather than corrupting a tensor at runtime.

The per-call cost of this design is one indirect virtual call for \texttt{requires\_grad} / \texttt{grad} / \texttt{set\_grad} plus one pointer indirection for \texttt{autograd\_meta\_}. The benefit is that \texttt{p10} rebuilds when a kernel changes no longer trigger a rebuild of \texttt{tpx}, and \texttt{tpx} rebuilds when engine scheduling changes do not trigger a rebuild of \texttt{p10}.

\begin{tpdef}[Definition (USB Slot Pattern)]
A \emph{USB slot} is a virtual interface $I$ declared in a lower-level library $L$, plus an opaque owning pointer of type \texttt{shared\_ptr<I>} embedded in $L$'s state, where the concrete implementation $C{:}I$ lives only in a higher-level library $H$. The pattern is sound iff (i) $L$ never includes any $H$ header; (ii) the pointer is omitted from $L$'s copy constructor (copies start history-free); and (iii) the downcast the $H$ boundary is \texttt{static\_cast}, justified because $C$ is the only class ever installed into the slot. TensorPlay's instance: $I{=}$\texttt{AutogradMetaBase}, $L{=}$\texttt{p10}, $C{=}$\texttt{AutogradMeta}, $H{=}$\texttt{tpx}.
\end{tpdef}

\subsection{Design Axiom: Level Monotonicity}
\label{sec:arch:axiom}

Let $V$ be the set of build targets and let $D\subseteq V\times V$ be the relation ``$a$ links $b$'' (i.e.\ $a$ has a \texttt{target\_link\_libraries} edge to $b$). Define \texttt{level}: $V\rightarrow \mathbb{N}$ by

\begin{table}[H]
\centering
\caption{Levels are total and equal the \texttt{add\_subdirectory} order.}
\label{tab:levels}
\small
\begin{tabular}{clcl}
\toprule
Level & Target & \texttt{add\_subdirectory} line & Header import allowed from higher \\
\midrule
0 & \texttt{p10} & & No lower target exists \\
1 & \texttt{tpx} & & May include \texttt{*.h} \\
2 & \texttt{stax} & & May include \texttt{include}, \texttt{include} \\
3 & \texttt{\_C} / \texttt{tp\_python} &, \texttt{1106} & May include \texttt{p10}, \texttt{tpx}, \texttt{stax} \\
\bottomrule
\end{tabular}
\end{table}

Axiom (level monotonic): $\forall (a,b)\in D,\; \mathrm{level}(a) > \mathrm{level}(b)$.

Equivalently, every edge points strictly downward in the order \texttt{p10=0 < tpx=1 < stax=2 < \_C=3}. Table~\ref{tab:levels} shows that \texttt{D} contains only \texttt{(tpx,p10)}, \texttt{(stax,p10)}, \texttt{(stax,tpx)}, \texttt{(tp\_python,p10)}, \texttt{(\_C,p10)}, \texttt{(\_C,tpx)}, \texttt{(\_C,stax)}, \texttt{(\_C,tp\_python)}, each satisfying the strict inequality. No pair with \texttt{level}(a) $\le$ \texttt{level}(b) is present; in particular \texttt{(p10,tpx)} and \texttt{(p10,stax)} are absent.

The enforcement is by the linker, not by convention. Adding \texttt{AutogradMeta.h"} inside any \texttt{Tensor*.h} introduces a reference to \texttt{tensorplay::tpx::AutogradMeta::requires\_grad} whose definition lives in \texttt{libtpx.so}. Because \texttt{p10} does not link \texttt{tpx} (and must not, by the axiom), the link of \texttt{libp10.so} succeeds but the link of any consumer that does link \texttt{p10} alone fails with \texttt{undefined reference to tensorplay::tpx::AutogradMeta}. On Linux this is diagnosed during \texttt{cmake --build}; on Windows it is diagnosed the \texttt{link.exe} step for \texttt{\_C.pyd}. The alternative failure mode for a conventional monolithic framework would be a static-initialization order defect diagnosed only at program startup.

The axiom also determines rebuild granularity. Touching \texttt{ActivationKernels.cpp} dirties only \texttt{p10} and the final link of \texttt{\_C}; \texttt{tpx} and \texttt{stax} are not rebuilt because they do not depend on \texttt{p10} sources, only on its installed headers. Touching \texttt{Engine.cpp} rebuilds \texttt{tpx} and relinks \texttt{stax} and \texttt{\_C} but not \texttt{p10}. 
A corollary concerns \texttt{tp\_python}. At it is a \texttt{SHARED} library \texttt{CPythonBridge.cpp} that links only \texttt{p10} and \texttt{pybind11}. It exists for exactly one reason documented the pybind11 caster substrate and the wrap-identity cache must be registered from a single module boundary. If \texttt{CPythonBridge.cpp} were compiled separately inside \texttt{p10} and inside \texttt{\_C}, each copy would carry its own registry and the first \texttt{Tensor} returned to Python would segfault. The single shared copy at level~3 keeps \texttt{level(tp\_python)=3 > level(p10)=0} and still allows out-of-tree op modules to link the same substrate via \texttt{add\_tensorplay\_op} without recompiling the core.

\begin{tpnote}[Note: Why a Corollary Library at All?]
The \texttt{tp\_python} split looks redundant---two shared libraries from the same directory, one thin shim. It exists because of a C-level identity requirement: \texttt{pybind11}'s type caster registry is keyed by the address of the translation unit that first registers the caster. Duplicated registrations across \texttt{p10} and \texttt{\_C} would create two distinct \texttt{Tensor} Python types whose pointers never compare equal, so a tensor that crossed the boundary once would be wrapped anew on every subsequent call. Housing the caster substrate in exactly one shared object at makes pointer identity survive arbitrary call sequences. The cost is one extra \texttt{dlopen} at import time (\S\ref{sec:eval} measures it at $\sim$1\,ms).
\end{tpnote}

\begin{tpinsight}[Insight: The Axiom Is Enforced by the Linker, Not by Review]
Every readability project promises ``clean layering''; most deliver it as a convention that erodes under deadline pressure. TensorPlay's axiom survives because violating it produces a \emph{link error}, not a style-comment: an upward \texttt{\#include} inside \texttt{p10} leaves an undefined reference to a symbol that only \texttt{libtpx.so} defines, and the link of the next consumer fails. Convention-based layering degrades silently; linker-based layering degrades loudly. The vacated-source line shows the mechanism working in reverse---metadata that once violated the axiom was physically moved out of \texttt{p10}, leaving a comment as the record.
\end{tpinsight}

\subsection{Python Veneer: Three Dirty Jobs in 1,197 Lines}
\label{sec:veneer}

\texttt{\_\_init\_\_.py} is 1,197 lines and, together with \texttt{\_tensor.py}, constitutes the entire Python-level design that the compiled extension cannot express. Every other Python module (\texttt{nn}, \texttt{optim}, \texttt{autograd}, \texttt{functional}, \texttt{distributed}) ultimately re-enters \texttt{\_C}. Three concerns are impossible to implement cleanly in C++ and are therefore concentrated here.

\subsubsection{Job 1: DLL / Shared-Object Preload (lines 34--205)}
Described in \S\ref{sec:arch:rpath}, this job handles the divergence between the Linux loader (which respects \texttt{RPATH}) and the Windows loader (which ignores it). On Windows the job is mandatory; on Linux it is an opportunistic repair for CUDA wheels. The code is split at line~34 and line~143 with no overlap, so a reader can inspect one platform without understanding the other. The job is the only place that imports \texttt{ctypes} and \texttt{glob}; no kernel or engine file references either.

\subsubsection{Job 2: Symbol Renaming (\texttt{\_C.add} $\rightarrow$ \texttt{tensorplay.add})}

The extension exports every operator as \texttt{\_C.add}, \texttt{\_C.relu}, \texttt{\_C.conv2d} at their C++ names. The veneer re-exports them as flat \texttt{tensorplay.*} names and rewrites \texttt{\_\_module\_\_} so tracebacks and \texttt{help(tensorplay.add)} report the public location. The loop is:

\begin{lstlisting}[caption={renaming with builtin fallback.}, label=lst:renaming]
__attr_name, __obj = "", None
for __attr_name in dir(_C):
    if __attr_name[0] != "_" and not __attr_name.endswith("Base"):
        __all__.append(__attr_name)
        __obj = getattr(_C, __attr_name)
        if callable(__obj) or inspect.isclass(__obj):
            if os.getenv("TENSORPLAY_BUILDING_STUBS") == "1":
                continue
            if __obj.__module__ != __name__:
                try:
                    __obj.__module__ = __name__          # pybind11 class: succeeds
                except AttributeError:                    # builtin_function_or_method: fails
                    if callable(__obj):
                        def make_wrapper(f):
                            @functools.wraps(f)
                            def wrapper(*args, **kwargs):
                                return f(*args, **kwargs)
                            wrapper.__module__ = __name__
                            return wrapper
                        wrapper = make_wrapper(__obj)
                        if __attr_name in globals():
                            globals()[__attr_name] = wrapper
            if __attr_name not in globals():
                globals()[__attr_name] = __obj
\end{lstlisting}

The \texttt{except} exists because pybind11 functions are \texttt{builtin\_function\_or\_method} descriptors whose \texttt{\_\_module\_\_} attribute is read-only in CPython; the fallback wrapper preserves \texttt{inspect.signature} via \texttt{functools.wraps} while fixing \texttt{\_\_module\_\_} to \texttt{"tensorplay"}. Without this job, users would call \texttt{tensorplay.\_C.add} or see tracebacks mentioning \texttt{tensorplay.\_C} instead of \texttt{tensorplay}.

The tensor type itself is finished here: defines \texttt{Tensor = \_C.TensorBase} and then attaches methods (\texttt{t}, \texttt{type}, \texttt{cuda}, \texttt{cpu}, \texttt{long}, \texttt{float}, plus hooks, bitwise dunders, \texttt{permute}, \texttt{expand}, \texttt{unique}, \texttt{topk}) onto that alias. The C++ binding at \texttt{Tensor.cpp} uses \texttt{py::dynamic\_attr} on \texttt{TensorBase} so Python subclasses like \texttt{class MyTensor(Tensor)} can attach per-instance attributes while still being recognized by the native caster. The check is \texttt{py::isinstance< Tensor >(obj)} via the shared caster in \texttt{tp\_python}.

\subsubsection{Job 3: Lazy Subpackages via \texttt{\_\_getattr\_\_} (lines 1118--1134)}

A direct \texttt{import tensorplay.linalg} at veneer top level would force importing 354 modules on every \texttt{import tensorplay}, adding hundreds of milliseconds on import even for scripts that only use \texttt{tensorplay.tensor([1])}. Instead the veneer registers a lazy set:

\begin{lstlisting}[caption={lazy subpackages.}, label=lst:lazy]
else:
    _lazy_modules = {
        "audio",
        "export",
        "func",
        "fft",
        "linalg",
        "quantization",
        "sparse",
        "special",
        "vision",
    }
    def __getattr__(name):
        if name in _lazy_modules:
            return importlib.import_module(f".{name}", __name__)
        raise AttributeError(f"module '{__name__}' has no attribute '{name}'")
\end{lstlisting}

\texttt{\_\_getattr\_\_} is the module-level hook introduced in Python~3.7. It is only invoked for missing attributes, so known names like \texttt{tensorplay.Tensor} or \texttt{tensorplay.add} never enter this path. Under \texttt{TYPE\_CHECKING} (true for static analysis only, false at runtime) the veneer instead imports \texttt{export} and \texttt{func} eagerly at lines~1108--1115 so that pylance and other LSP servers resolve attributes without executing the lazy hook. The accompanying \texttt{TYPE\_CHECKING} import is guarded by \texttt{if TYPE\_CHECKING:} and has no runtime cost.

\subsection{Stax: Minimal IR That Is Not a Second Frontend}
\label{sec:arch:stax}

\texttt{stax} is 76 lines of CMake at producing \texttt{libstax.so} from \texttt{*.cpp}. Its public surface is two headers: and. The design note is explicit:

\begin{lstlisting}[caption={not a second frontend.}, label=lst:staxpy]

and select ``backend="stax"`` once the backend has a production lowering.

    size_t id;
    OpNode* producer; // Producer op, nullptr for graph inputs

\texttt{OpNode} at groups inputs, outputs, owning graph, and attributes through a \texttt{variant<int64\_t, double, string, vector<int64\_t>, vector<double>>} map at line~62. \texttt{Graph} at owns the \texttt{nodes} and \texttt{values} vectors plus the \texttt{inputs} / \texttt{outputs} boundaries, with helpers \texttt{addInput}, \texttt{createNode}, and \texttt{registerOutput} at lines~95--97. The \texttt{IRBuilder} helper at creates named nodes and propagates dtype from the first input.

Execution is strictly sequential. \texttt{Graph::execute} binds concrete \texttt{Tensor} arguments to \texttt{env[ input->id ]} at line~192, then iterates \texttt{nodes} in creation order. Each node dispatches to \texttt{tpx::ops} (e.g.\ \texttt{add}, \texttt{conv2d}, \texttt{matmul}, \texttt{max\_pool2d}, \texttt{batch\_norm}) via the regular dispatcher, preserving device and differentiation semantics. Intermediate lifetimes are bounded by \texttt{remaining\_uses} at line~198 and \texttt{keep\_alive} at line~199; dead values are cleared via \texttt{env[id]=Tensor} at line~215, allowing the allocator to recycle storage inside a single graph run without retaining every intermediate until the function returns.

 adds the only optimization: a pass infrastructure with a single registered pass that fuses \texttt{mul} followed by \texttt{add} into \texttt{fused\_mul\_add} (a single kernel in \texttt{p10}). The registry is a \texttt{map<string, Creator>}, and \texttt{fuseGraph} at line~73 is retained for compatibility. There is no alias analysis, no layout propagation, no autotuning, no code generation to C++/CUDA/PTX, and no persistence format beyond the in-memory \texttt{Graph}.

\subsection{Design Trade-offs}
\label{sec:arch:tradeoffs}

\textbf{Virtual interface vs.\ union payload.} The USB slot could instead be a \texttt{std::variant} or a raw byte blob inside \texttt{p10} with \texttt{tpx} writing into it. Rejected: a variant forces \texttt{p10} headers to enumerate every future metadata layout, so adding a field recompiles the world, and a byte blob abandons type safety the seam that matters most. The virtual interface at costs one vtable indirection but keeps the two libraries compilably independent---\texttt{p10} rebuilds are never triggered by autograd changes.

\textbf{\texttt{\$ORIGIN} RPATH vs.\ installed loader config.} Absolute RPATHs or \texttt{ldconfig} entries would remove the preload logic in. Rejected: absolute paths break relocatability (the tree must run unmodified from any checkout or a USB stick), and system loader config requires root. \texttt{\$ORIGIN} at makes the tree position-independent the price of the Windows branch needing an explicit ordered \texttt{LoadLibraryExW} walk, documented in \S\ref{sec:arch:rpath}.

\textbf{One Python veneer file (1\,197 lines) vs.\ package layout.} Splitting \texttt{\_\_init\_\_.py} into submodules would shorten the file. Rejected: the three ``dirty jobs'' (preload, symbol rename, lazy subpackages) must execute in a strict order before any subpackage import resolves, and a single module makes that ordering linear and greppable (\S\ref{sec:arch} Job 1--3). The cost is one long file; the benefit is that import-order bugs have a single stack trace through one file.
