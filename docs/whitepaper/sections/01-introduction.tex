\section{引言}
\label{sec:intro}

TensorPlay 是密集张量核心的可读性优先实现，包含 C++ 核心（加上生成的绑定）和数百个 Python 模块
。该构建生成四个共享库 \texttt{p10}、\texttt{tpx}、\texttt{stax}、\texttt{tp\_python} 和一个扩展 \texttt{\_C}
 其 \texttt{OUTPUT\_DIRECTORY} 被固定到 \texttt{TP\_PACKAGE\_DIR=tensorplay}
。

\subsection{问题：可读性与性能}
\label{sec:intro:problem}

主流框架将张量存储、算子调度、自动微分 (\ac{ad})、编译和分发集中在一个翻译单元中。结果是最大可见度
优化器：单个 \texttt{LTO} 步骤可以将存储访问内联到内核循环中。成本是认知和增量构建开销。了解张量的存储方式
需要遍历继承链（\texttt{Tensor} $\rightarrow$ \texttt{Variable} $\rightarrow$ 存储）和相关的侵入式引用计数；修改CPU内核
for \texttt{add} 触发整个算子聚合目标的重建；隐式标头包含在核心层和操作层之间创建了事实上的循环依赖关系
如果不首先构建图表，静态分析就无法恢复。

TensorPlay 明确地反转了这种权衡。它针对 \emph{readability} 进行了优化：新手可以通过仅读取 \texttt{p10} 来理解张量存储
 不加载任何差异化概念；一个优化器
\texttt{add} 仅重建张量库（一个构建目标，一个重新链接）；编译器实验位于 \texttt{stax} 内部
无需重新链接存储。
价格是每次调用的明确跨库边界。具体来说，一个 \texttt{atomic<void*>} 获取负载，一个虚拟调度，并且没有 \ac{lto} 跨四个支柱的整个程序内联。
简而言之，调用必须跨边界序列化，但可读性和增量构建的收益大于成本。
该项目接受此成本是因为目标工作负载是教学、正确性检查和硬件实验，而不是冻结内核集上的峰值 FLOPS。

具体来说，边界是在链接时强制执行的，而不是按照惯例。基础库声明一个纯接口（\texttt{requires\_grad}、\texttt{grad}、\texttt{set\_grad}）；张量实现保留从复制构造函数中故意省略的 \texttt{shared\_ptr<AutogradMetaBase> autograd\_meta\_} ，因此 \texttt{Tensor b=a} 共享存储、大小、步幅、设备、数据类型和版本计数器，但不共享历史记录。 autograd库提供了具体的插件（\texttt{grad\_fn\_}、\texttt{grad\_accumulator\_}如\texttt{weak\_ptr<Node>}以避免循环，查看重播状态）；一个边界文件执行单次 \texttt{static\_cast<AutogradMeta*>} 握手。由于基础支柱中没有标头可以看到 autograd 支柱，因此在张量支柱内添加 include 会失败，并出现 \texttt{undefined reference} 链接步骤。

构建粒度遵循相同的公理。构建脚本按依赖顺序添加了四个支柱——张量核心、autograd、编译器——并且每个支柱仅向下链接。接触 CPU 内核文件会弄脏 \texttt{libp10.so} 和最后的 \texttt{\_C} 链接；触摸引擎文件会重建 \texttt{libtpx.so} 加 \texttt{libstax.so} 和 \texttt{\_C} 但不会重建 \texttt{libp10.so}。每个库通过 \texttt{RPATH} 或 \texttt{\$ORIGIN/../lib} 来定位其兄弟库。在 Windows 上，通过有序的 \texttt{LoadLibraryExW} 预加载遍历保留了相同的不变量。

\subsubsection{C2：重新调度和静态注册}
\label{sec:intro:c2}

编码 13 个键：\texttt{CPU}=0、\texttt{CUDA}=1、\texttt{Vulkan}=2、\texttt{AutogradCPU}=3--5、\texttt{AutocastCPU}=6--8、
\texttt{VmapCPU}=9--11，\texttt{Composite}=12，\texttt{EndOfKeys}=13。偏移量 \texttt{kAutogradKeyOffset}=3、\texttt{kAutocastKeyOffset}=6、\texttt{kVmapKeyOffset}=9
 进行优先级算术。 \texttt{DispatchKeySet} 是一个 \texttt{uint32\_t} 位集，其 \texttt{highest\_priority\_key}
at 扫描最高有效的设置位，因此数字较大的键获胜； \texttt{TensorImpl::key\_set} at 计算
从设备和 \texttt{inference\_tensor\_} 设置而不存储它。

每个操作员存储 \texttt{array<atomic<KernelFunction>,13>}； \texttt{OperatorHandle::getKernel} 在做一
\texttt{acquire} 加载，并且仅适用于 \texttt{is\_backend\_key} (0--2)，在 \texttt{Composite} 索引~12 处进行第二次加载。 \texttt{DispatchStub::call} 是
强制自动转换合约 \texttt{is\_autocast\_key(k) \&\& !is\_enabled(k) -> throw} 与 \texttt{[[unlikely]]} 的单一阻塞点并发出 32 帧
当设置 \texttt{TP\_TRACE\_KERNEL\_MISS} 时，为 \texttt{backtrace}。注册是批量的：\texttt{TENSORPLAY\_LIBRARY\_IMPL(KEY, NAME)} 使用两级
\texttt{TP\_CONCAT} at 产生卫生的独特静力学； \texttt{Library::impl} 在连锁电话中。已弃用的每操作
\texttt{TENSORPLAY\_REGISTER\_KERNEL} 保留为旧注册路径。

Python 绑定是双路径且仅填充的。桥接器和生成的模块一起实现解析（
\texttt{tpx\_py\_parse\_into} 通过 \texttt{memcpy} + 线性关键字扫描），检查（16 种 + \texttt{TPK\_OPTIONAL}=0x80），子类/函数钩子
（通过 \texttt{PythonDispatchTLS}），打开包装（快速 \texttt{instance} 支架），并包裹（
\texttt{g\_wrap\_cache} 带胶囊析构函数）。代码生成器发出 \texttt{generated\_functions[]} 和
\texttt{register\_generated\_cpython\_functions} 永远不会隐藏 \texttt{pybind11} 名称（由 \texttt{PyObject\_HasAttrString} 检查）。
它将生成的表安装在 \texttt{TP\_NO\_FASTCALL} 后面；桥保留单个 \texttt{tp\_python} 因此施法者注册表和包装缓存不会重复
每个扩展。

\subsubsection{C3：自动微分}
\label{sec:intro:c3}

没有\ac{tape}。每个需要 grad 的前向操作都会分配一个 \texttt{Node} 子类（从 via 生成的 148 种类型到 \texttt{AutogradNodesGenerated.h} 中，或者是手写节点中）。
\texttt{next\_edges: vector<Edge>} 指向父母； \texttt{Edge} at 带有 \texttt{weak\_ptr<Node>} 加上 \texttt{output\_nr}。
\texttt{output\_nr}。该图是这些边的传递闭包。 \texttt{Node::sequence\_nr} at \texttt{Node.h} 是一个全局单调计数器
\texttt{get\_and\_increment\_sequence\_nr}，由引擎用来确定重新计算顺序的优先级。

\texttt{GraphTask.h} 持有由 \texttt{backward} 发起的任务：\texttt{dependencies\_} 度数计数、\texttt{captured\_vars} 和发起的 \texttt{GraphRoot}
仅当 \texttt{roots.size!=1} 时才在 \texttt{Engine.cpp} 合成。是每个节点累加器，其 \texttt{accumulate} 添加
按拓扑顺序传入的毕业生。通过 \texttt{sequence\_nr} ( \texttt{return
fn->sequence\_nr < other.fn->sequence\_nr}) 将 \texttt{ReadyQueue} 定义为线程安全的最大堆；使用设备分区队列进行调度（\texttt{ready\_queues\_}，
\texttt{queue\_for\_device}、\texttt{execute\_task} at) 和 \texttt{local\_queue} 用于重入，以便 \texttt{Node} 实现
递归调用 \texttt{backward} 不会使全局工作线程陷入僵局。

版本控制是快速失败的，而不是沉默的。 \texttt{VariableVersion.h} 以 \texttt{bump} 支持 \texttt{TensorImpl::version\_counter\_}
 在每个原地突变上。 \texttt{SavedVariable.h} 保存 \texttt{saved\_version\_}；解包检查 \texttt{expected==current} 并抛出
而不是产生数字上错误的梯度，这是引擎中最有价值的可读性保护。另外商店
\texttt{grad\_accumulator\_} 与 \texttt{weak\_ptr<Node>} 相同，因此叶子累加器不会形成无法收集的循环。

\begin{tpdef}[Definition (Link-Time Acyclicity)]
令 $V$ 为构建目标集，并令 $D \subseteq V \times V$ 为由构建系统的 \texttt{target\_link\_libraries} 指令引发的“链接”关系。如果存在级别函数 $\mathrm{level}:V\rightarrow\mathbb{N}$ 和 $\forall(a,b)\in D:\ \mathrm{level}(a)>\mathrm{level}(b)$，则构建为 \emph{acyclic}。 TensorPlay 修复了 \texttt{level(p10)=0}、\texttt{level(tpx)=1}、\texttt{level(stax)=2}、\texttt{level(\_C)=3}；该属性由构建目标排序强制执行，并由空出符号移动进行认证。
\end{tpdef}

\subsubsection{C4：Vmap 和 Profiler 堆栈}
\label{sec:intro:c4}

Vmap 精确地占据了 offset~9，因此它的排名优于 autograd 和 backend。 \texttt{DispatchKey::VmapCPU}=9 且 \texttt{kVmapKeyOffset}=9
; \texttt{toVmapKey} at 和 \texttt{is\_vmap\_key} 是 \texttt{constexpr} 范围测试，低于 1
比较。 \texttt{TransformDispatch} at 和内核表 at 实现每片回退与
分批内核；调度程序在 autograd 层观察张量之前解开变换状态，因此 \texttt{Vmap} 和 autograd 无需第二个调度表即可组合。

该分析器跨越 \ac{cpu} 和 \ac{cuda}，带有一个热路径防护。将 \texttt{g\_active}、\texttt{g\_capture\_shapes}、\texttt{g\_capture\_sites} 导出为
\texttt{atomic<bool>}；当不活动时，每个操作的成本是一次获取负载。 \texttt{OpRecord} 处用 \texttt{end\_ns}、\texttt{tid} 标记插槽，
\texttt{kind}，可选 \texttt{dtypes} 和 \texttt{stack\_id}；每派发 \texttt{GpuTimerPair} 武器，汇集 \texttt{cudaEvent} 对
CUDA 操作并在会话停止时解析已用的 \texttt{gpu\_ms}。 \ac{cupti} \texttt{stop} at \texttt{Profiler.h} dlopen \texttt{libcupti} 并将内核关联到
通过外部相关 ID 推送到 \texttt{GpuTimerPair} 的操作； \ac{nvtx} \texttt{pop} 于 \ac{itt} \texttt{itt\_task\_begin\_name}
 连接 Nsight 和 VTune 的桥梁。当本机库不存在且绑定层位于 \texttt{profiler.py} 时，所有收集器都会正常降级
多路复用采样而不添加构建依赖项。

\subsection{惯例}
\label{sec:intro:conventions}

\texttt{path:line} 表示相对于存储库根目录的文件及其中的一行，\texttt{path:line--line} 是
包含范围。代码清单最多包含空格折叠；标题给出了准确的范围。表格列举了规范值（关键数字、工件名称、修剪轴），而不是
说明性样本。 \texttt{Composite} 是后端中立的后备；它从未出现在 \texttt{DispatchKeySet} 中，并且仅由
\texttt{OperatorHandle::getKernel} 对应 \texttt{is\_backend\_key}。 \texttt{TP\_CONCAT} 是一个两级宏，因此其参数在粘贴之前展开；
引用两级定义，而不是单级变体。
