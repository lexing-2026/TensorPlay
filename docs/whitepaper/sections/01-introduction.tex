\section{Introduction}
\label{sec:intro}

TensorPlay is a readability-first implementation of a dense tensor core, in approximately 75\,k lines of C++ plus 354 Python modules under
\path{tensorplay/}. The build produces four shared libraries \texttt{p10}, \texttt{tpx}, \texttt{stax}, \texttt{tp\_python} and one extension \texttt{\_C}
(\path{tensorplay/\_C/\_\_init\_\_.so}) whose \texttt{OUTPUT\_DIRECTORY} is pinned by \path{CMakeLists.txt:1175--1192} to \path{TP\_PACKAGE\_DIR=tensorplay} at
\path{CMakeLists.txt:325}. Every structural claim below cites \texttt{path:line} against \path{version.txt:1} (1.0.0a0) at \texttt{HEAD 2026-09-02}. No claim relies on external
benchmarks or on prose that cannot be checked with \texttt{grep -n} and \texttt{readelf -d}.

\subsection{Problem: Readability vs.\ Performance}
\label{sec:intro:problem}

Mainstream frameworks co-locate tensor storage, operator dispatch, automatic differentiation, compilation, and distribution in one translation unit. The result is maximal visibility for
the optimizer: a single \texttt{LTO} step can inline storage access into the kernel loop. The cost is cognitive and incremental-build overhead. Understanding how a tensor is stored
requires traversing an inheritance chain (\texttt{Tensor} $\rightarrow$ \texttt{Variable} $\rightarrow$ storage) and the associated intrusive reference counting; modifying a CPU kernel
for \texttt{add} triggers a rebuild of the entire operator aggregation target; implicit header inclusion creates de~facto circular dependencies between core and operator layers
that static analysis cannot recover without building the graph first.

TensorPlay inverts the trade-off explicitly. It optimizes for \emph{readability}: a newcomer can understand tensor storage by reading only \texttt{p10}
(\path{p10/include/TensorImpl.h:23--63}, \path{p10/include/Storage.h:17--58}, \path{p10/include/Allocator.h:14--41}) without loading any differentiation concept; an optimizer for
\texttt{add} rebuilds only \texttt{p10} (\path{p10/CMakeLists.txt:144} accumulates \texttt{P10\_SOURCES}, \path{cmake --build build --target p10 -j4} relinks
\path{tensorplay/lib/libp10.so} alone at \path{CMakeLists.txt:1202} with \texttt{RPATH \$ORIGIN}); a compiler experiment lives inside \texttt{stax}
(\path{stax/include/Graph.h:47--123}, \path{stax/include/Fusion.h:15--73}) without relinking storage.
The price is an explicit cross-library boundary per call. Concretely, one \path{atomic<void*>} acquire load at \path{p10/include/Dispatcher.h:71}, one virtual dispatch at \path{p10/include/AutogradMetaBase.h:13}, and no whole-program inlining across the four pillars.
In short, calls must serialize across the boundary, but the gains in readability and incremental build are larger than the cost.
The project accepts this cost because the target workloads are teaching, correctness auditing, and hardware experimentation---not peak FLOPS on a frozen kernel set.

Concretely, the boundary is enforced at link time, not by convention. \path{p10/include/AutogradMetaBase.h:13} declares a pure interface (\texttt{requires\_grad()}, \texttt{grad()}, \texttt{set\_grad()}); \path{p10/include/TensorImpl.h:43} holds \path{shared\_ptr<AutogradMetaBase> autograd\_meta\_} that is deliberately omitted from the copy constructor at \path{p10/src/TensorImpl.cpp:77--92} so \texttt{Tensor b=a} shares storage, sizes, strides, device, dtype and version counter but not history.
\path{tpx/include/AutogradMeta.h:26} supplies the concrete plug (\texttt{grad\_fn\_}, \texttt{grad\_accumulator\_} as \texttt{weak\_ptr<Node>} to avoid cycles, view replay state). \path{tpx/src/Autograd.cpp:17,26} is the single \path{static\_cast<AutogradMeta*>} handshake.
Because no header under \path{p10/include/} includes \texttt{tpx}, \texttt{grep -rn "tpx" p10/include/ --include="*.h"} returns 0 and adding \path{\#include "tpx/AutogradMeta.h"} inside \texttt{p10} fails with \texttt{undefined reference to tensorplay::tpx::AutogradMeta} at the \path{libp10.so} link step.

Build granularity follows the same axiom. At \path{CMakeLists.txt:938--944} the order is \path{add\_subdirectory(p10)} :938, \path{add\_subdirectory(tpx)} :941,
\path{add\_subdirectory(stax)} :944; \path{tpx/CMakeLists.txt:26,40} and \path{stax/CMakeLists.txt:8,17} link downward only. Touching
\path{p10/src/backend/cpu/ActivationKernels.cpp} dirties exactly \path{libp10.so} and the final \texttt{\_C} link; touching \path{tpx/src/Engine.cpp:621} rebuilds
\path{libtpx.so} plus \path{libstax.so} and \texttt{\_C} but not \path{libp10.so}. Artifact freshness is \path{ls -lt tensorplay/lib/libp10.so tensorplay/lib/libtpx.so
tensorplay/lib/libstax.so tensorplay/\_C/\_\_init\_\_.so} and loader correctness is \path{readelf -d tensorplay/lib/libp10.so | grep -i rpath} (\texttt{\$ORIGIN} at
\path{CMakeLists.txt:1202}) and \path{readelf -d tensorplay/\_C/\_\_init\_\_.so | grep -i rpath} (\path{\$ORIGIN/../lib} at \path{CMakeLists.txt:1210} with \texttt{ldd ... |
grep "not found"} empty). On Windows the same invariant is preserved by ordered \texttt{LoadLibraryExW} with \texttt{0x00001100} at \path{tensorplay/\_\_init\_\_.py:122} and
\path{tensorplay/\_\_init\_\_.py:34--205} preload.

Axiom: $\forall (a,b)\in D$, \texttt{level}(a)$>$\texttt{level}(b) with \texttt{level}(p10)=0, \texttt{level}(tpx)=1, \texttt{level}(stax)=2, \texttt{level}(\_C)=3 and
\texttt{level}(tp\_python)=3. The enforcements are (i) directory isolation, (ii) \path{target\_link\_libraries} edges that point only downward, and (iii) header visibility: no
\path{p10/include/*.h} includes \texttt{tpx}. The audited move at \path{p10/CMakeLists.txt:28} (\path{\# src/AutogradMetaInterface.cpp (Moved to TPX)}) records that concrete
metadata once lived in \texttt{p10} and was vacated to preserve the axiom. The Windows static branch at \path{CMakeLists.txt:934--936} embeds the pillars into \texttt{\_C.pyd} to
avoid \path{\_\_declspec(dllexport)} on every p10 symbol while keeping visibility identical.

\subsubsection{C2: Redispatch and Static Registration}
\label{sec:intro:c2}

\path{p10/include/DispatchKey.h:15--49} encodes 13 keys: \texttt{CPU}=0, \texttt{CUDA}=1, \texttt{Vulkan}=2, \texttt{AutogradCPU}=3--5, \texttt{AutocastCPU}=6--8,
\texttt{VmapCPU}=9--11, \texttt{Composite}=12, \texttt{EndOfKeys}=13. Offsets \texttt{kAutogradKeyOffset}=3, \texttt{kAutocastKeyOffset}=6, \texttt{kVmapKeyOffset}=9 at
\path{DispatchKey.h:51--54} make priority arithmetic. \texttt{DispatchKeySet} at \path{DispatchKey.h:125--187} is a \texttt{uint32\_t} bitset whose \path{highest\_priority\_key()}
at \path{DispatchKey.h:151} scans the most-significant set bit so numerically larger keys win; \path{TensorImpl::key\_set()} at \path{p10/include/TensorImpl.h:135} computes the
set from device and \texttt{inference\_tensor\_} without storing it.

\path{p10/include/Dispatcher.h:49--61} stores \path{array<atomic<KernelFunction>,13>} per operator; \path{OperatorHandle::getKernel} at \path{Dispatcher.h:67--81} does one
\texttt{acquire} load and, only for \texttt{is\_backend\_key} (0--2), a second load at \texttt{Composite} index~12. \texttt{DispatchStub::call} at \path{Dispatcher.h:139} is the
single choke point that enforces the autocast contract \path{is\_autocast\_key(k) \&\& !is\_enabled(k) $\rightarrow$ throw} with \texttt{[[unlikely]]} and emits a 32-frame
\texttt{backtrace} when \path{TP\_TRACE\_KERNEL\_MISS} is set. Registration is bulk: \path{TENSORPLAY\_LIBRARY\_IMPL(KEY, NAME)} at \path{Dispatcher.h:203} uses two-level
\texttt{TP\_CONCAT} at \path{p10/include/Macros.h:23} to produce hygienic unique statics; \texttt{Library::impl} at \path{Dispatcher.h:194} chains calls. The deprecated per-op
\path{TENSORPLAY\_REGISTER\_KERNEL} at \path{Dispatcher.h:177} is retained as a legacy registration path.

Python binding is dual-path and fill-only. \path{src/bindings/python/CPythonBridge.h:28--240} and \texttt{CPythonBridge.cpp} implement parse (\path{CPythonBridge.cpp:801}
\path{tpx\_py\_parse\_into} via \texttt{memcpy} + linear keyword scan), check (\path{CPythonBridge.h:94} 16 kinds + \texttt{TPK\_OPTIONAL}=0x80), subclass/function hooks
(\path{CPythonBridge.cpp:80} \texttt{PythonDispatchTLS}), unpack (\path{CPythonBridge.cpp:989} fast \texttt{instance} holder), and wrap (\path{CPythonBridge.cpp:1398}
\texttt{g\_wrap\_cache} with capsule destructor). \path{tools/codegen/gen\_python\_c.py:882,907} emits \path{generated\_functions[]} and
\path{register\_generated\_cpython\_functions} that never shadows a \texttt{pybind11} name (checked by \path{PyObject\_HasAttrString}). \path{src/bindings/python/init.cpp:697}
installs the generated table last behind \texttt{TP\_NO\_FASTCALL}; \path{CMakeLists.txt:954} keeps a single \texttt{tp\_python} so caster registry and wrap cache are not duplicated
per extension.

\subsubsection{C3: Autograd}
\label{sec:intro:c3}

There is no tape. Each forward op that requires grad allocates a \texttt{Node} subclass (148 types generated from \path{config/derivatives.yaml:1} via \path{tools/codegen/gen\_autograd.py:785} into \path{build/generated/tensorplay/ops/AutogradNodesGenerated.h}, or a handwritten node in \path{tpx/include/ManualNodes.h:1200}).
\path{next\_edges: vector<Edge>} at \path{tpx/include/Node.h:150} points to parents; \texttt{Edge} at \path{tpx/include/Edge.h:14} carries a \texttt{weak\_ptr<Node>} plus \texttt{output\_nr}.
\texttt{output\_nr}. The graph is the transitive closure of those edges. \texttt{Node::sequence\_nr} at \path{tpx/include/Node.h:50,109} is a global monotonic counter from
\path{get\_and\_increment\_sequence\_nr()} at \path{Node.h:34}, used by the engine to prioritize recomputation order deterministically.

\path{tpx/include/GraphTask.h} holds the task launched by \texttt{backward()}: \texttt{dependencies\_} in-degree counts, \texttt{captured\_vars}, and the initiating \texttt{GraphRoot}
synthesized at \path{tpx/src/Engine.cpp:621,648} only when \texttt{roots.size()!=1}. \path{tpx/include/InputBuffer.h:16} is the per-node accumulator whose \texttt{accumulate} adds
incoming grads in topological order. \path{tpx/include/Engine.h:23} defines \texttt{ReadyQueue} as a thread-safe max-heap by \texttt{sequence\_nr} (\path{Engine.h:38} \texttt{return
fn->sequence\_nr() < other.fn->sequence\_nr()}); \path{Engine.h:112--122} dispatches with device-partitioned queues (\texttt{ready\_queues\_} at \path{Engine.h:129},
\texttt{queue\_for\_device} at \path{Engine.h:122}, \texttt{execute\_task} at \path{Engine.h:120}) and a \texttt{local\_queue} for reentrancy so that \texttt{Node} implementations
that call \texttt{backward} recursively do not deadlock the global worker.

Versioning is fail-fast, not silent. \path{p10/include/VariableVersion.h} backs \path{TensorImpl::version\_counter\_} at \path{TensorImpl.h:34} with \texttt{bump()} at
\path{TensorImpl.h:276} on every inplace mutation. \path{tpx/include/SavedVariable.h:15,33} saves \texttt{saved\_version\_}; the unpack checks \texttt{expected==current} and throws
rather than producing a numerically wrong gradient, which is the single most valuable readability guard in the engine. \path{tpx/include/AutogradMeta.h:26} additionally stores
\texttt{grad\_accumulator\_} as \texttt{weak\_ptr<Node>} so leaf accumulators do not form uncollectable cycles.

\subsubsection{C4: Vmap and the Profiler Stack}
\label{sec:intro:c4}

Vmap occupies offset~9 precisely so it outranks autograd and backend. \path{DispatchKey::VmapCPU}=9 at \path{DispatchKey.h:41} with \texttt{kVmapKeyOffset}=9 at
\path{DispatchKey.h:54}; \texttt{toVmapKey} at \path{DispatchKey.h:64} and \texttt{is\_vmap\_key} at \path{DispatchKey.h:81} are \texttt{constexpr} range tests that lower to one
compare. \texttt{TransformDispatch} at \path{p10/include/TransformDispatch.h:14} and the kernel table at \path{p10/include/BatchingKernels.h:18} implement per-slice fallback versus
batched kernels; the dispatcher unwraps transform state before the autograd layer observes the tensor, so \texttt{Vmap} and autograd compose without a second dispatch table.

The profiler spans CPU and GPU with one hot-path guard. \path{p10/include/Profiler.h:129} exports \texttt{g\_active}, \texttt{g\_capture\_shapes}, \texttt{g\_capture\_sites} as
\texttt{atomic<bool>}; when inactive the cost per op is one acquire load. \texttt{OpRecord} at \path{Profiler.h:145} stamps a slot with \path{begin/end\_ns}, \texttt{tid},
\texttt{kind}, optional \path{shapes/dtypes} and \path{site\_id/stack\_id}; \texttt{GpuTimerPair} at \path{Profiler.h:227} arms a pooled \texttt{cudaEvent} pair per dispatched
CUDA op and resolves elapsed \texttt{gpu\_ms} at session stop. \path{cupti\_available/start/stop} at \path{Profiler.h:259,267,270} dlopen \texttt{libcupti} and correlate kernels to
ops via external correlation ids pushed in \texttt{GpuTimerPair}; \path{nvtx\_range\_push/pop} at \path{Profiler.h:283} and \path{itt\_task\_begin\_name} at
\path{Profiler.h:297} bridge to Nsight and VTune. All collectors degrade gracefully when the native library is absent, and the binding layer at \path{tensorplay/profiler.py}
multiplexes sampling without adding a build dependency.

Sparse is the most illustrative trim. \path{p10/include/SparseKernels.h:12} declares the API surface, but \path{DispatchKey.h:15} never defines \texttt{SparseCPU} and
\path{TensorImpl::key\_set()} never emits it, so dispatch never queries a sparse slot. A contributor adding sparse would add a key, extend \texttt{kDispatchKeyCount} from 13, and add
the offset helpers, which is exactly the change the acyclic build is designed to make painful enough to discuss. Meta tensors are absent for the same reason: \texttt{DeviceType::Meta}
exists as an enum value but never participates in \texttt{computeDispatchKey} at \path{Dispatcher.h:31} and never acquires a \texttt{RegisterKernel} entry, so \texttt{has\_kernel(...,
Meta)} remains false by construction. Boxed alias analysis and shape-check elision are absent because the codegen pipeline at \path{tools/codegen/model.py:754} and
\path{gen\_autograd.py:785} deliberately generates straight-line backward formulas without alias metadata; the stax interpreter re-enters \texttt{tpx::ops} at
\path{stax/src/Graph.cpp:192} so correctness of aliasing stays with the eager dispatcher rather than with a compiler pass.

The trimmed axes are not undocumented; they are documented as trimmed so that a reader does not search for a sparse dispatch key that does not exist or file an issue about meta tensors
being broken. Future work that promotes a trimmed axis to a real key must update \path{DispatchKey.h:15}, \path{Dispatcher.h:49}, and the schema validator that admits
\texttt{Vulkan} at \path{tools/codegen/model.py:754} even on CPU builds; the paper version after such a promotion will cite the new \texttt{path:line} and bump \path{version.txt:1}.

\subsection{Conventions}
\label{sec:intro:conventions}

\texttt{path:line} means the file relative to the repository root at the cited tag; \path{p10/include/Dispatcher.h:49} is line~49 of that file. \texttt{path:line--line} is an
inclusive range. \texttt{grep -n} examples are literal commands that reproduce the citation; \texttt{wc -l} and \texttt{grep -c} are the sources of every count. Code listings are
verbatim excerpts with at most whitespace folding; the caption gives the exact range. Tables enumerate normative values (key numbers, artifact names, trimmed axes) rather than
illustrative samples. \texttt{Composite} at \path{DispatchKey.h:36} is a backend-neutral fallback; it never appears in a \texttt{DispatchKeySet} and is consulted only by
\path{OperatorHandle::getKernel} for \texttt{is\_backend\_key}. \texttt{TP\_CONCAT} at \path{p10/include/Macros.h:23} is a two-level macro so its argument expands before pasting;
the paper always cites the two-level definition, not a single-level variant. All shell snippets assume \texttt{bash} and a Release build with \texttt{USE\_CUDA=ON}, \texttt{USE\_MKL=ON}
unless noted as CPU-only.
