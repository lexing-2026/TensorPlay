\section{Autograd: Explicit DAG, ReadyQueue, and Version Guards}
\label{sec:autograd}

This chapter documents the autograd engine as code, not as a concept. There is no \ac{tape}: a search for the symbol returns zero. The graph is an explicit \ac{dag} of \texttt{shared\_ptr<Node>} linked through \texttt{Edge}, dependency-counted, and scheduled across ReadyQueues keyed by \texttt{sequence\_nr}. The chapter walks the node, the edge, the task, the input buffer, the ready queue, and the engine, in that order.

%==============================================================================
\subsection{No Tape, Explicit DAG}
\label{subsec:notape}

The engine builds the graph eagerly during forward. Each op's autograd wrapper allocates a \texttt{Node} subclass (148 types generated from via into \texttt{AutogradNodesGenerated.h}) or uses a handwritten node in (e.g.\ \texttt{CatBackward}, \texttt{MeanBackward}, \texttt{AccumulateGrad}). The node's \texttt{next\_edges:\ vector<Edge>} points to its parents. The whole graph is the transitive closure of those edges. Printing or drawing the graph is a walk of \texttt{shared\_ptr<Node>}; device-partitioned scheduling is a map from node to queue without scanning a global tape. creates a synthetic \texttt{GraphRoot} only when \texttt{roots.size!=1}, otherwise the single root is the graph root directly.

Key invariants:

\begin{itemize}[leftmargin=1.2em]
\item \texttt{sequence\_nr\_} is assigned in the constructor from a. It is monotonic per thread, never global, so the max-heap approximates reverse creation order without a global atomic. compares it.
\item \texttt{topological\_nr\_} is the longest-path distance from leaves. scans \texttt{outputs[].function->topological\_nr}, and both and prune \texttt{topo < min\_topo}. Early ops outside the needed subgraph never enter \texttt{dependencies\_}.
\item \texttt{output\_metas\_} exists because for custom functions the backward inputs correspond to forward \emph{outputs}, not to \texttt{next\_edges} inputs. in fills one \texttt{OutputSlotMeta} per output tensor (shape/dtype/device\_index/valid). Generated nodes leave it empty and rely on \texttt{Edge} hints.
\item Hooks are append-only at graph-build time. The engine iterates them during \texttt{evaluate\_function:426,446} while no other thread mutates the node, so no lock is needed around hooks themselves (the graph is logically immutable once \texttt{execute} starts).
\item \texttt{anomaly\_metadata\_} is allocated lazily in and initialized via which calls \texttt{store\_stack} and, if \texttt{tls\_current\_evaluating\_node} is set, \texttt{assign\_parent}. This chains the creation stack of a backward-created node to its parent.
\end{itemize}

Generated nodes from store \texttt{SavedVariable} members per saved tensor; handwritten nodes in do the same. Each node's destructor need not be virtual for scheduling; \texttt{shared\_from\_this} is required for \texttt{CurrentEvalNodeGuard} to capture the parent in anomaly mode.

\subsubsection{Filtering with \texttt{init\_to\_execute}}
\label{subsubsec:inittoexec}

For \texttt{backward}, \texttt{exec\_info\_} stays empty and every visited node executes. For \texttt{grad(outputs,inputs)}, calls. That method must mark \emph{only} the subgraph needed to produce the requested inputs.

The code at does two passes:

\begin{enumerate}[leftmargin=1.2em]
\item Seed \texttt{exec\_info\_[output\_edge.function].captures\_} with \texttt{(input\_nr, output\_idx)} or \texttt{needed\_=true} when \texttt{accumulate\_grad==true}. pre-sizes the result vector.
\item Walk from \texttt{graph\_root} using an explicit stack of \texttt{Frame\{Node* fn; size\_t next\_next\_fn\_\}}. iterates \texttt{fn->next\_edges} one edge a time. A \texttt{seen} set plus the \texttt{nodeShouldExecute} lambda (\texttt{257}) propagates \texttt{needed\_} backward: if a child already \texttt{should\_execute}, its parent is marked \texttt{needed\_=true} (\texttt{274}). When unwinding (\texttt{287}), a just-finalized node's \texttt{needed\_} is pushed to its DFS parent (\texttt{289}). The \texttt{min\_topo\_nr} computed at (minimum topo among \texttt{outputs}) prunes the walk: any child with \texttt{topological\_nr < min\_topo} is skipped (\texttt{281}) because it cannot reach the requested outputs.
\end{enumerate}

The result is that can early-return after copying captures but before \texttt{apply} when \texttt{!fn\_info.needed\_}: that node's outputs are still needed as captured inputs but the node itself need not compute new grads.

\subsection{ReadyQueue: Priority by \texttt{sequence\_nr}}
\label{subsec:readyqueue}

 implements the scheduler queue (Listing~\ref{lst:readyqueue}).

\begin{lstlisting}[caption={priority queue.}, label=lst:readyqueue]
struct ReadyQueue{ //23
  struct NodeTask{ //25
    shared_ptr<Node> fn_; InputBuffer input_buffer_; GraphTask* graph_; //26
    NodeTask(shared_ptr<Node> f,InputBuffer b,GraphTask* g):fn_(move(f)),input_buffer_(move(b)),graph_(g){} //33
    bool operator<(const NodeTask& o) const { return fn_->sequence_nr() < o.fn_->sequence_nr(); } //37 max-heap
  };
  void push(NodeTask t){ lock_guard<mutex> l(mutex_); heap_.push(move(t)); cv_.notify_one(); } //42
  template<StopFn> optional<NodeTask> pop_until(const StopFn& stop){ //53
    unique_lock<mutex> lock(mutex_);
    for(;;){
      if(!heap_.empty()){ auto t=move(const_cast<NodeTask&>(heap_.top())); heap_.pop(); return t; } //58
      if(stop()) return nullopt; //62
      cv_.wait_for(lock, chrono::milliseconds(5)); //65 poll
    }
  }
  void notify(){ lock_guard<mutex> l(mutex_); cv_.notify_all(); } //74
  mutex mutex_; condition_variable cv_; priority_queue<NodeTask> heap_; //80
};
\end{lstlisting}

The queue is a max-heap by \texttt{sequence\_nr\_} (\ac{dag} execution order; see the definition box below). Since nodes are allocated in forward order, larger \texttt{sequence\_nr} is roughly closer to the outputs, so popping the maximum approximates reverse topological order without computing a topological sort per backward. It is a heuristic, not exact: true topological order is enforced by \texttt{dependencies\_} counting, which prevents execution before parents complete.

\begin{tpdef}[Definition (Priority Heap vs.\ Topological Order)]
Let $G=(N,E)$ be the backward DAG and $\sigma:N\rightarrow\mathbb{N}$ map each node to its \texttt{sequence\_nr} (the forward allocation order). The \texttt{ReadyQueue} pops the pending node with maximal $\sigma$, which equals reverse-forward order. An execution sequence is \emph{valid} iff every node runs after all of its parents (per \texttt{dependencies\_} in-degree counts). The heap achieves validity \emph{without} computing a topological sort: a node enters the heap only after its last parent enqueues it, so any pop order is valid by construction; $\sigma$ merely biases \emph{within} the valid set toward reverse-forward order, improving locality of saved intermediates.
\end{tpdef}

The ready queue is used in two modes. Device workers call \texttt{pop\_until([]{return false;})} and block forever with a 5\,ms poll. The initiating thread calls \texttt{cpu\_queue.pop\_until([\&graph]\{return graph.is\_completed;\})} so it can exit as soon as its \texttt{GraphTask} finishes, even if the CPU queue is otherwise empty. The 5\,ms avoids lost wakeups (the notifier takes the mutex before \texttt{notify}) and bounds idle latency without busy-spinning. The notifier takes the lock before \texttt{notify\_all} so a notification cannot be lost between \texttt{pop\_until}'s empty check and its wait.

Pushing increments no counters itself; the caller must have already bumped the outstanding-task count under \texttt{task.mutex\_}. This ordering matters: workers decrement on completion and the initiator blocks on \texttt{outstanding\_tasks\_==0}.

Design notes:

\begin{itemize}[leftmargin=1.2em]
\item leaks the singleton on purpose (\texttt{new Engine} never freed) because queued tasks and workers may outlive static destructors. The Queues themselves are also leaked.
\item \texttt{ready\_queues\_} maps \texttt{-1} to the CPU queue and non-negative ints to CUDA device indices. Each CUDA device gets exactly one persistent worker spawned on first use. CPU has no worker; the initiator thread drains it.
\item never exits. It blocks in \texttt{pop\_until} and calls, which catches any exception, records it in \texttt{GraphTask::exception\_} via, and marks completion with.
\item is \texttt{thread\_local}. When detects \texttt{nested=true}, it routes every task to a stack-local and drains it itself (\texttt{684}). This keeps reentrant backward (a backward inside a backward's \texttt{apply}) deadlock-free: workers busy with the outer graph cannot block the inner one, and the inner graph's tasks never leak to device queues where workers would wait for an outer initiator that is itself blocked.
\item Build discipline matters: both the root  and the repo root are CMake binary directories pointing \texttt{TP\_PACKAGE\_DIR} at  (see \texttt{CMakeLists.txt} \texttt{TP\_PACKAGE\_DIR}). Concurrent linkers corrupt \texttt{\_C.so}; see \texttt{README.md} compile notes.
\end{itemize}

\subsection{Building the Dependency Count}
\label{subsec:dependencies}

\begin{lstlisting}[caption={BFS in-degree.}, label=lst:computedep]
void Engine::compute_dependencies(Node* root,GraphTask& task,uint64_t min_topo){ //192
  vector<Node*> queue{root}; auto& deps=task.dependencies_; auto& nodes=task.nodes_in_graph_; //194
  while(!queue.empty()){
    auto fn=queue.back(); queue.pop_back(); //198
    if(fn->topological_nr() < min_topo) continue; //201 prune
    for(auto& e: fn->next_edges()){ //204
      if(auto* next=e.function.get()){
        deps[next] += 1; //206
        if(was_inserted(nodes,next)) queue.push_back(next); //215
      }
    }
  }
}
\end{lstlisting}

This is a DFS (vector as stack) over the DAG starting from \texttt{graph\_root}. Each edge contributes one to the child's in-degree stored in. The \texttt{nodes\_in\_graph\_} set ensures each node is expanded once, but the counter still accumulates one per incoming edge (the map is bumped even when the node was already seen). The \texttt{min\_topo} guard (\texttt{201}) skips entire subtrees that were created before the first output of interest; this is critical for \texttt{grad} where only a suffix of the forward matters. Trace level~2 emits per edge when \texttt{TP\_ENGINE\_TRACE=2}.

 is the minimum \texttt{topological\_nr\_} among \texttt{outputs[].function}. If \texttt{outputs} is empty (pure \texttt{backward}), it returns 0 and nothing is pruned.

  DepthGuard depth(nested_depth_); //681
  if(nested){ while(!task.is_completed()){ auto t=local.pop_until([]{return false;}); if(!t) break; execute_task(move(*t), cpu, &local); } //683
  } else { while(!task.is_completed()){ auto t=cpu.pop_until([&task]{return task.is_completed();}); if(!t) break; execute_task(move(*t), cpu, nullptr); } task.wait_for_completion(); } //689
  if(task.exception_) rethrow_exception(task.exception_); //705
  return move(task.captured_vars_); //709
}
\end{lstlisting}

Steps:

\begin{enumerate}[leftmargin=1.2em]
\item Validate \texttt{roots.size==inputs.size} (\texttt{629}) and that \texttt{grad} has non-empty outputs (\texttt{633}).
\item Create and assign \texttt{trace\_id\_} from an atomic counter.
\item Build an ephemeral \texttt{GraphRoot} if fan-in (multi-output backward) is needed; it holds the root edges and forwards the seeded gradients to the correct parents.
\item Compute dependencies (\S\ref{subsec:dependencies}) and, for \texttt{grad}, the \texttt{captures} filter via \texttt{init\_to\_execute}.
\item Enqueue the root(s). In the single-root fast path, the seed gradient is inserted at \texttt{input\_nr} with explicit \texttt{grad\_mode==create\_graph} so the first \texttt{InputBuffer::add} already knows whether to build second-order history.
\item Branch on \texttt{nested\_depth\_}. Nested backs use the local queue; the top-level initiator drains the CPU queue itself while CUDA workers drain their device queues. The initiator also calls after the CPU queue drains, because some work may still be on device workers.
\end{enumerate}

 is RAII: \texttt{++depth} on entry, \texttt{--depth} on exit, even via exception, so reentrancy tracking is exception-safe.

\subsubsection{Step~7: Shape Validation and \texttt{sum\_to\_shape}}
\label{subsubsec:sumto}

Broadcasting during forward inflates a scalar grad to a large shape. Before the next edge consumes the grad, the engine must reduce it to the forward-input shape recorded on that edge. Listing~\ref{lst:sumtoshape} is the routine.

\begin{lstlisting}[caption={broadcast recovery.}, label=lst:sumtoshape]
static Tensor sum_to_shape(const Tensor& grad,const vector<int64_t>& target){ //298
  if(target.empty()) return ops::sum(grad); //301 scalar ()
  int64_t leading=(int64_t)grad.dim()-(int64_t)target.size(); //304
  if(leading<0){ int64_t n=1; for(auto d:target) n*=d; if(grad.numel()==n) return ops::reshape(grad,target); return grad; } //306
  vector<int64_t> reduce; for(int64_t i=0;i<leading;++i) reduce.push_back(i); //318
  for(int64_t i=leading;i<(int64_t)grad.dim();++i) if(target[i-leading]==1 && grad.size(i)!=1) reduce.push_back(i); //319
  Tensor cur=reduce.empty()?grad:ops::sum(grad,reduce,true); //325 keepdim
  if(leading>0) cur=ops::reshape(cur,target); //327
  return cur; //330
}
\end{lstlisting}

Called for each \texttt{i < min(outputs.size,edges.size)}, if \texttt{edges[i].has\_shape\_hint} and the grad's sizes mismatch the hint, \texttt{sum\_to\_shape} is invoked. The logic keeps dimensions where \texttt{target==1} but \texttt{grad>1} and sums with \texttt{keepdim=true}, then reshapes away leading broadcast dimensions. Under \texttt{create\_graph}, the \texttt{reshape} calls join the second-order graph because \texttt{GradModeGuard} is still active.

\subsection{SavedVariable and VariableVersion: Mutation Guard}
\label{subsec:savedvar}

Backward needs forward tensors. Storing a bare \texttt{Tensor} would silently yield wrong grads if the tensor is mutated in-place between forward and backward. TensorPlay uses a version counter on storage plus a guarded handle (Listings~\ref{lst:savedvar}--\ref{lst:varver}).

\begin{lstlisting}[caption={guarded handle.}, label=lst:savedvar]
class SavedVariable{ //15
  Tensor data_; uint32_t saved_version_=0; //39
  void save(const Tensor& t){ //8 in SavedVariable.cpp

Why eagerly allocated: always allocates a \texttt{VersionCounter}. If allocation were lazy, a base that had not yet mutated and a view created before any mutation would each grow their own counter on first bump, and later mutations on one alias would be invisible to the other. Eager allocation plus guarantees all aliases observe the same bump. The counter is atomic so bumps from one alias are visible to readers holding another.

\begin{tppitfall}[Pitfall: ``Lazy Version Counter'' Is Silently Wrong, Not Slow]
The eager \texttt{VersionCounter} allocation at looks like a gratuitous \texttt{make\_shared} for every tensor, including the vast majority that never join a graph. Tempting ``optimization'': allocate the counter on first \texttt{bump}. That optimization silently breaks view aliasing: \texttt{x} and \texttt{x.view(...)} would each lazily allocate \emph{their own} counter on first mutation, so \texttt{SavedVariable::unpack} at would see \texttt{saved\_version\_==current} even after the alias was mutated in place---producing numerically wrong gradients with no exception. The failure signature is the opposite of the current design's: today a mutated-in-place saved variable \emph{throws} with both version numbers in the message; under lazy allocation it would compute garbage. Correctness guards must fail loud, and loudness must not depend on allocation timing.
\end{tppitfall}

The binding is more than a trampoline. Three hot-path optimizations cut per-op Python overhead:

\begin{enumerate}[leftmargin=1.2em]
\item and batch edge wiring: one crossing builds the \texttt{vector<Edge>} for all tensor args by iterating \texttt{py::isinstance<Tensor>} at and calling per tensor, then \texttt{add\_next\_edge\_list} once. The non-batched Python loop in would pay N pybind crossings otherwise.
\item is the single-entry fast path. \item and \texttt{grad} release the GIL before entering \texttt{grad}, because workers need it to re-enter Python for \texttt{PyNode::apply}. Holding it would deadlock.
\end{enumerate}

Hook registration on \texttt{Node} wraps the user hook with a GIL acquire so hooks are safe even when invoked from CUDA workers.

\subsection{Deep Dive: Six Mechanisms Under the Scheduling Story}
\label{subsec:autograd-deep}

\subsubsection{The \texttt{topological\_nr} Pruning Fence}
\label{subsubsec:topoprune}

Every node carries a second counter besides \texttt{sequence\_nr}: a \texttt{topological\_nr} maintained incrementally at edge insertion time. When a node links to a parent, its counter becomes the parent's counter plus one---if that is larger than its current value:

\begin{lstlisting}[caption={Topological number maintenance is two lines at graph-construction time---no pass over the graph is ever needed later.}]
void update_topological_nr(const Edge& edge) {
    if (!edge.is_valid()) return;
    auto topo_nr = edge.function->topological_nr();
    if (topological_nr_ <= topo_nr) {
        topological_nr_ = topo_nr + 1;
    }
}
\end{lstlisting}

The counter enables the engine's most effective optimization: before counting dependencies, the engine computes the \emph{minimum} topological number among the requested outputs, and both the BFS and the execute-marking walk skip any node whose number is smaller. The invariant that makes this sound: a node with \texttt{topo\_nr} smaller than an output's can, by construction, never lie on a path \emph{to} that output, so the walk does not need to visit it. On a graph where \texttt{backward()} targets only a late output, whole subtrees of early forward ops are pruned before the counters are even built---the fence is what keeps \texttt{grad(outputs=[y])} from paying for \texttt{backward()} over the entire graph.

\subsubsection{\texttt{AccumulateGrad}: the Leaf Contract}
\label{subsubsec:accumulategrad}

Leaf tensors do not receive gradients through the generic propagation path. Each leaf with \texttt{requires\_grad} owns a dedicated \texttt{AccumulateGrad} node whose \texttt{sequence\_nr} is \texttt{UINT64\_MAX}, forcing the priority queue to schedule it as early as its dependencies allow. Its body implements the full leaf contract in one page: device check, shape reconciliation, contiguity, and the final store:

\begin{lstlisting}[caption={The leaf node's shape reconciliation: the same reduce-then-reshape logic as the engine-wide \texttt{sum\_to\_shape}, specialized for parameters.}]
explicit AccumulateGrad(const Tensor& t)
    : Node(UINT64_MAX), value_(t) {}   // always scheduled ASAP

variable_list apply(variable_list&& inputs) override {
    if (inputs.empty() || !inputs[0].defined()) return {};
    Tensor grad = inputs[0];
    /* device check: param vs grad must agree */
    /* shape reconciliation:
       1. sum away extra leading dims (broadcast inflated them)
       2. sum away dims where param has size 1 and grad larger
       3. reshape to the parameter's exact rank and sizes      */
    if (auto* meta = impl::get_autograd_meta(value_)) {
        // Materialize strided gradients: downstream consumers (foreach
        // optimizers, .numpy()) rely on dense storage.
        if (!grad.is_contiguous()) grad = grad.contiguous();
        meta->accum_grad(grad);
    }
    return {};
}
\end{lstlisting}

Three design points are worth reading off. First, the shape fix lives \emph{at the leaf}, not in every producing node: intermediate nodes pass broadcast-inflated shapes along their edges and only the final destination reconciles. Second, the contiguity materialization documents its consumer contract---the \emph{foreach} optimizer kernels and the NumPy bridge both require dense storage, so a transposed gradient is copied once here rather than surprising a consumer later. Third, the metadata side of the store is a weak-reference handshake: the tensor's \texttt{grad\_accumulator} is a \texttt{weak\_ptr<Node>} precisely because the node strongly owns the tensor---a strong edge back would form an uncollectable cycle that leaks every leaf that ever participated in a graph.

\subsubsection{Exception Containment and the First-Error Rule}
\label{subsubsec:exceptions}

Backward is a concurrent execution over multiple worker threads, so exception handling is a design question, not an afterthought. The rules: (i) each worker catches every exception thrown by a node's \texttt{apply} and records it into the \texttt{GraphTask} with a first-wins policy---the mutex-guarded store keeps the \emph{first} exception pointer and silently drops later ones, because a graph that has already failed does not need three error reports; (ii) the recording worker then decrements the outstanding-task count exactly as a success would, so completion accounting stays correct on the failure path; (iii) the initiating thread, which blocks on the task's condition variable, wakes on completion and rethrows the recorded exception after the graph has fully quiesced. The consequence: one node's shape error never leaves sibling workers spinning, and the user sees a single traceback from a single deterministic place---the initiating thread, after the graph drains.

\begin{lstlisting}[caption={Completion accounting is identical for success and failure; only the initiating thread ever rethrows.}]
bool task_completed() {
    std::lock_guard<std::mutex> lock(mutex_);
    --outstanding_tasks_;
    if (outstanding_tasks_ == 0) {
        completed_ = true;
        cv_.notify_all();       // wakes the initiator's wait_for_completion
        return true;
    }
    return false;
}
void record_exception(std::exception_ptr exc) {
    std::lock_guard<std::mutex> lock(mutex_);
    if (!exception_) exception_ = std::move(exc);   // first error wins
}
\end{lstlisting}

\subsubsection{Final Callbacks: Post-Backward Hooks Without Racing}
\label{subsubsec:finalcallbacks}

Some consumers need code to run \emph{after} the whole graph finishes but \emph{from inside} the backward call---the FSDP backward-completion hooks are the motivating example. A plain ``call my function at the end of \texttt{backward}'' API cannot work in an engine where any worker might be the last to finish. The engine exposes \texttt{queue\_callback}, valid only while a backward is executing on the current thread; the \texttt{GraphTask} stores the callback vector under its own mutex, and the initiator drains the list \emph{by index in a loop} rather than consuming the vector wholesale---because a callback is allowed to queue another callback while the drain is running. Execution order is therefore well-defined (FIFO including callbacks queued during the drain), and the drain runs before the initiating thread returns from \texttt{backward}, so post-backward logic observes fully accumulated leaf gradients without any user-side polling.

\subsubsection{Reentrant Backward and the Local-Queue Trick}
\label{subsubsec:reentrant}

A node's \texttt{apply} may itself call \texttt{backward}---higher-order differentiation with \texttt{create\_graph}, or a custom function that reduces a loss mid-graph. The engine tracks a \texttt{thread\_local} nesting depth; when it is nonzero, the execute path routes \emph{every} task of the inner graph to a stack-local \texttt{ReadyQueue} that only the current thread drains. The deadlock this prevents is structural: without it, an inner task could land on a device queue whose worker is busy with the outer graph, waiting for a node that can only run after the inner backward returns---a cycle across two queues. With the local queue the inner graph is strictly single-threaded, self-contained, and cannot block on outer-graph workers; nested graphs lose intra-graph parallelism, which is acceptable because reentrant backward is rare and usually small, while the alternative is a deadlock that no scheduling priority can recover.

\subsubsection{Engine Tracing: Observing the Scheduler}
\label{subsubsec:enginetrace}

The scheduler's decisions---dependency counts, buffer coalescing, queue routing---are exactly the parts a reader cannot infer from a static diagram. An environment-gated trace facility makes them observable: \texttt{TP\_ENGINE\_TRACE=1} emits lifecycle events, level~2 adds per-node applications with shapes and every delivery decision (counter decrement, buffer hit, enqueue), and level~3 prints truncated gradient \emph{values}. Every line is prefixed with the graph's monotonic id, so nested and concurrent backwards remain separable in the log; nodes are labeled \texttt{name\#sequence\_nr@pointer-suffix}, a label that stays stable for one graph and is greppable across it. The facility compiles to zero cost when the level variable reads zero (one static integer load per event site), so it can ship enabled and be turned on for a misbehaving graph in production without rebuilding.

Takeaways:

\begin{itemize}[leftmargin=1.2em]
\item The data structure is implemented in $\sim$1\,k lines (\texttt{*.h} +). The compactness comes from trimming sparse/quantized/inference key combinations, alias-key remapping, and operator boxing.

\subsection{Invariants, Traces, and Local Verification}
\label{subsec:verify}

Checked invariants the code enforces; violations are either warned or hard-fail:

\begin{itemize}[leftmargin=1.2em]
\item updates before pushing. Forgetting this would let \texttt{min\_topo} prune incorrectly and drop live dependencies.
\item requires \texttt{use\_count==2} (temporary impl alias counts as one) and \texttt{storage==1}. Accumulating in-place on a shared storage would alias-corrupt a sibling.
\item checks \texttt{stop} \emph{after} the heap-empty test but \emph{before} waiting. Reversing the order would sleep one extra poll interval after the graph completes.
\item must precede the queue push. Workers incrementally decrement and test \texttt{outstanding==0}; pushing without counting would hang the initiator.
\item throws with both \texttt{saved\_version\_} and current version. The message is the same string users see in both codebases, enabling transferred runbooks.
\end{itemize}
