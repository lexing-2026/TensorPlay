\section{Autograd: Explicit DAG, ReadyQueue, and Version Guards}
\label{sec:autograd}

This chapter documents the autograd engine as code, not as a concept. Every claim cites a concrete \texttt{path:line} and can be reproduced with \texttt{grep -rn} on the version at \path{version.txt:1}. There is no Tape: \path{grep -r Tape tpx/} returns zero. The graph is an explicit DAG of \texttt{shared\_ptr<Node>} linked through \texttt{Edge}, dependency-counted, and scheduled across ReadyQueues keyed by \texttt{sequence\_nr}. The chapter walks \path{Node.h:26}, \path{Edge.h:14}, \path{GraphTask.h:22}, \path{InputBuffer.h:16}, \path{Engine.h:23}, \path{Engine.cpp:621}, \path{SavedVariable.h:15}, \path{VariableVersion.h:13}, \path{AnomalyMode.h:14}, \path{GradMode.h:8}, and \path{src/bindings/python/Autograd.cpp:24}.

%==============================================================================
\subsection{No Tape, Explicit DAG}
\label{subsec:notape}

The engine builds the graph eagerly during forward. Each op's autograd wrapper allocates a \texttt{Node} subclass (148 types generated from \path{config/derivatives.yaml:1} via \path{tools/codegen/gen\_autograd.py:785} into \path{build/generated/tensorplay/ops/AutogradNodesGenerated.h}) or uses a handwritten node in \path{tpx/include/ManualNodes.h:1200} (e.g.\ \texttt{CatBackward}, \texttt{MeanBackward}, \texttt{AccumulateGrad}). The node's \path{next\_edges:\ vector<Edge>} (\path{tpx/include/Node.h:150}) points to its parents. The whole graph is the transitive closure of those edges. Printing or drawing the graph is a walk of \texttt{shared\_ptr<Node>}; device-partitioned scheduling is a map from node to queue without scanning a global tape. \path{tpx/src/Engine.cpp:621} creates a synthetic \texttt{GraphRoot} only when \texttt{roots.size()!=1}, otherwise the single root is the graph root directly (\path{Engine.cpp:648}).

Key invariants:

\begin{itemize}[leftmargin=1.2em]
\item \texttt{sequence\_nr\_} is assigned in the constructor (\path{Node.h:50}) from a \path{thread\_local counter:35}. It is monotonic per thread, never global, so the max-heap approximates reverse creation order without a global atomic. \path{ReadyQueue::NodeTask::operator<:37} compares it.
\item \texttt{topological\_nr\_} is the longest-path distance from leaves. \path{compute\_min\_topological\_nr:127} scans \path{outputs[].function->topological\_nr()}, and both \path{compute\_dependencies:201} and \path{GraphTask::init\_to\_execute:281} prune \texttt{topo < min\_topo}. Early ops outside the needed subgraph never enter \texttt{dependencies\_}.
\item \texttt{output\_metas\_} exists because for custom functions the backward inputs correspond to forward \emph{outputs}, not to \texttt{next\_edges} inputs. \path{PyNode::attach\_outputs:159} in \path{src/bindings/python/Autograd.cpp:159} fills one \texttt{OutputSlotMeta} per output tensor (shape/dtype/device\_index/valid). Generated nodes leave it empty and rely on \texttt{Edge} hints.
\item Hooks are append-only at graph-build time. The engine iterates them during \path{evaluate\_function:426,446} while no other thread mutates the node, so no lock is needed around hooks themselves (the graph is logically immutable once \texttt{execute} starts).
\item \texttt{anomaly\_metadata\_} is allocated lazily in \path{Node::anomaly\_metadata():122} and initialized via \path{init\_anomaly\_metadata():132} which calls \texttt{store\_stack()} and, if \path{tls\_current\_evaluating\_node} is set, \texttt{assign\_parent}. This chains the creation stack of a backward-created node to its parent.
\end{itemize}

Generated nodes from \path{tools/codegen/gen\_autograd.py:785} store \texttt{SavedVariable} members per saved tensor; handwritten nodes in \path{tpx/include/ManualNodes.h:1200} do the same. Each node's destructor need not be virtual for scheduling; \texttt{shared\_from\_this} is required for \path{CurrentEvalNodeGuard} to capture the parent in anomaly mode.

\subsubsection{Filtering with \texttt{init\_to\_execute}}
\label{subsubsec:inittoexec}

For \texttt{backward()}, \texttt{exec\_info\_} stays empty and every visited node executes. For \path{grad(outputs,inputs)}, \path{Engine::execute:658} calls \path{GraphTask::init\_to\_execute:224}. That method must mark \emph{only} the subgraph needed to produce the requested inputs.

The code at \path{Engine.cpp:224--293} does two passes:

\begin{enumerate}[leftmargin=1.2em]
\item Seed \path{exec\_info\_[output\_edge.function].captures\_} with \path{(input\_nr, output\_idx)} or \texttt{needed\_=true} when \path{accumulate\_grad==true} (\path{Engine.cpp:227}). \path{captured\_vars\_.resize(output\_idx):239} pre-sizes the result vector.
\item Walk from \texttt{graph\_root} using an explicit stack of \texttt{Frame\{Node* fn; size\_t next\_next\_fn\_\}} (\path{Engine.cpp:241}). \path{Frame::get\_next\_fn():246} iterates \texttt{fn->next\_edges()} one edge at a time. A \texttt{seen} set plus the \texttt{nodeShouldExecute} lambda (\texttt{257}) propagates \texttt{needed\_} backward: if a child already \texttt{should\_execute}, its parent is marked \texttt{needed\_=true} (\texttt{274}). When unwinding (\texttt{287}), a just-finalized node's \texttt{needed\_} is pushed to its DFS parent (\texttt{289}). The \texttt{min\_topo\_nr} computed at \path{Engine.cpp:127} (minimum topo among \texttt{outputs}) prunes the walk: any child with \path{topological\_nr < min\_topo} is skipped (\texttt{281}) because it cannot reach the requested outputs.
\end{enumerate}

The result is that \path{Engine::evaluate\_function:341} can early-return after copying captures but before \texttt{apply} when \texttt{!fn\_info.needed\_}: that node's outputs are still needed as captured inputs but the node itself need not compute new grads.

\subsection{ReadyQueue: Priority by \texttt{sequence\_nr}}
\label{subsec:readyqueue}

\path{tpx/include/Engine.h:23--83} implements the scheduler queue (Listing~\ref{lst:readyqueue}).

\begin{lstlisting}[caption={\path{Engine.h:23} --- priority queue.}, label=lst:readyqueue]
struct ReadyQueue{ //23
  struct NodeTask{ //25
    shared_ptr<Node> fn_; InputBuffer input_buffer_; GraphTask* graph_; //26
    NodeTask(shared_ptr<Node> f,InputBuffer b,GraphTask* g):fn_(move(f)),input_buffer_(move(b)),graph_(g){} //33
    bool operator<(const NodeTask& o) const { return fn_->sequence_nr() < o.fn_->sequence_nr(); } //37 max-heap
  };
  void push(NodeTask t){ lock_guard<mutex> l(mutex_); heap_.push(move(t)); cv_.notify_one(); } //42
  template<StopFn> optional<NodeTask> pop_until(const StopFn& stop){ //53
    unique_lock<mutex> lock(mutex_);
    for(;;){
      if(!heap_.empty()){ auto t=move(const_cast<NodeTask&>(heap_.top())); heap_.pop(); return t; } //58
      if(stop()) return nullopt; //62
      cv_.wait_for(lock, chrono::milliseconds(5)); //65 poll
    }
  }
  void notify(){ lock_guard<mutex> l(mutex_); cv_.notify_all(); } //74
  mutex mutex_; condition_variable cv_; priority_queue<NodeTask> heap_; //80
};
\end{lstlisting}

The queue is a max-heap by \texttt{sequence\_nr\_}. Since nodes are allocated in forward order, larger \texttt{sequence\_nr} is roughly closer to the outputs, so popping the maximum approximates reverse topological order without computing a topological sort per backward. It is a heuristic, not exact: true topological order is enforced by \texttt{dependencies\_} counting, which prevents execution before parents complete.

\path{pop\_until:53} is used in two modes. Device workers call \path{queue.pop\_until([]{return false;})} (\path{Engine.cpp:169}) and block forever with a 5\,ms poll. The initiating thread calls \path{cpu\_queue.pop\_until([\&graph]{return graph.is\_completed();}):693} so it can exit as soon as its \texttt{GraphTask} finishes, even if the CPU queue is otherwise empty. The 5\,ms \path{wait\_for:65} avoids lost wakeups (the notifier takes the mutex before \texttt{notify}: \path{Engine.h:74} comments this explicitly) and bounds idle latency without busy-spinning. \path{notify:74} takes the lock before \texttt{notify\_all} so a notification cannot be lost between \texttt{pop\_until}'s empty check and its wait.

\path{push:42} increments no counters itself; the caller must have already called \path{GraphTask::task\_enqueued():67} before pushing, which does the \path{outstanding\_tasks\_++} under \texttt{task.mutex\_}. This ordering matters: workers decrement on completion and the initiator blocks on \path{outstanding\_tasks\_==0}.

Design notes:

\begin{itemize}[leftmargin=1.2em]
\item \path{get\_default\_engine:145} leaks the singleton on purpose (\texttt{new Engine()} never freed) because queued tasks and workers may outlive static destructors. The Queues themselves are also leaked (\path{Engine.h:129}).
\item \texttt{ready\_queues\_} maps \texttt{-1} to the CPU queue and non-negative ints to CUDA device indices. Each CUDA device gets exactly one persistent worker spawned on first use (\path{Engine.cpp:158}). CPU has no worker; the initiator thread drains it.
\item \path{worker\_main:166} never exits. It blocks in \texttt{pop\_until} and calls \path{execute\_task:175}, which catches any exception, records it in \path{GraphTask::exception\_} via \path{record\_exception:185}, and marks completion with \path{task\_completed():186}.
\item \path{nested\_depth\_:133} is \texttt{thread\_local}. When \path{execute:662} detects \texttt{nested=true}, it routes every task to a stack-local \path{local\_queue:667} and drains it itself (\texttt{684}). This keeps reentrant backward (a backward inside a backward's \texttt{apply}) deadlock-free: workers busy with the outer graph cannot block the inner one, and the inner graph's tasks never leak to device queues where workers would wait for an outer initiator that is itself blocked.
\item Build discipline matters: both the root \path{build/} and the repo root are CMake binary directories pointing \texttt{TP\_PACKAGE\_DIR} at \path{tensorplay/} (see \path{CMakeLists.txt} \texttt{TP\_PACKAGE\_DIR}). Concurrent linkers corrupt \path{\_C.so}; see \path{docs/whitepaper/README.md} compile notes.
\end{itemize}

void Engine::compute_dependencies(Node* root,GraphTask& task,uint64_t min_topo){ //192
  vector<Node*> queue{root}; auto& deps=task.dependencies_; auto& nodes=task.nodes_in_graph_; //194
  while(!queue.empty()){
    auto fn=queue.back(); queue.pop_back(); //198
    if(fn->topological_nr() < min_topo) continue; //201 prune
    for(auto& e: fn->next_edges()){ //204
      if(auto* next=e.function.get()){

        if(was_inserted(nodes,next)) queue.push_back(next); //215
      }
    }
  }
}
\end{lstlisting}

This is a DFS (vector as stack) over the DAG starting from \texttt{graph\_root}. Each edge contributes one to the child's in-degree stored in \path{dependencies\_[child]++:206}. The \texttt{nodes\_in\_graph\_} set ensures each node is expanded once, but the counter still accumulates one per incoming edge (the map is bumped even when the node was already seen). The \texttt{min\_topo} guard (\texttt{201}) skips entire subtrees that were created before the first output of interest; this is critical for \texttt{grad()} where only a suffix of the forward matters. Trace level~2 emits \path{EngineTrace::emit("dep \%s -> \%s count=\%d"):211} per edge when \texttt{TP\_ENGINE\_TRACE=2}.

\path{compute\_min\_topological\_nr:127} is the minimum \texttt{topological\_nr\_} among \texttt{outputs[].function}. If \texttt{outputs} is empty (pure \texttt{backward()}), it returns 0 and nothing is pruned.

Steps:

\begin{enumerate}[leftmargin=1.2em]
\item Validate \path{roots.size()==inputs.size()} (\texttt{629}) and that \texttt{grad()} has non-empty outputs (\texttt{633}).
\item Create \path{GraphTask(keep\_graph,create\_graph):636} and assign \texttt{trace\_id\_} from an atomic counter (\path{Engine.cpp:68}).
\item Build an ephemeral \texttt{GraphRoot} if fan-in (multi-output backward) is needed; it holds the root edges and forwards the seeded gradients to the correct parents.

\item Branch on \texttt{nested\_depth\_}. Nested backs use the local queue; the top-level initiator drains the CPU queue itself while CUDA workers drain their device queues. \end{enumerate}

\path{DepthGuard:121} is RAII: \texttt{++depth} on entry, \texttt{--depth} on exit, even via exception, so reentrancy tracking is exception-safe.

\subsubsection{Step~7: Shape Validation and \texttt{sum\_to\_shape}}

Broadcasting during forward inflates a scalar grad to a large shape. Before the next edge consumes the grad, the engine must reduce it to the forward-input shape recorded on that edge. Listing~\ref{lst:sumtoshape} is the routine at \path{Engine.cpp:298--331}.

\begin{lstlisting}[caption={\path{Engine.cpp:298} --- broadcast recovery.}, label=lst:sumtoshape]

  if(target.empty()) return ops::sum(grad); //301 scalar ()
  int64_t leading=(int64_t)grad.dim()-(int64_t)target.size(); //304

The binding is more than a trampoline. Three hot-path optimizations cut per-op Python overhead:

\begin{enumerate}[leftmargin=1.2em]
\item \path{autograd.collect\_next\_edges:202} and \path{setup\_custom\_function\_graph:214} batch edge wiring: one crossing builds the \texttt{vector<Edge>} for all tensor args by iterating \path{py::isinstance<Tensor>} at \path{Autograd.cpp:222} and calling \path{collect\_next\_edges:229} per tensor, then \path{add\_next\_edge\_list} once. The non-batched Python loop in \path{tensorplay/autograd/function.py:255} would pay N pybind crossings otherwise.
\item \path{custom\_function\_apply:286} is the single-entry fast path. It creates the \texttt{PyNode}, unpacks \texttt{needs\_input\_grad}, wires \texttt{next\_edges} (\texttt{327}), disables GradMode (\texttt{346}), calls \texttt{forward} plus \texttt{setup\_context}, marks outputs with \texttt{set\_grad\_fn} plus \texttt{OutputSlotMeta} (\texttt{368}), and returns \path{(output, ctx, needs, executable, node)} all in one GIL hold. Python only builds the backward closure afterwards. This replaces five round-trips with one.
\item \path{backward:408} and \texttt{grad:419} release the GIL (\path{py::gil\_scoped\_release:415}) before entering \path{tpx::backward/grad}, because workers need it to re-enter Python for \texttt{PyNode::apply}. Holding it would deadlock.
\end{enumerate}

\path{PyNode::num\_inputs:30} overrides the default \path{next\_edges\_.size()} when \texttt{output\_metas\_} is non-empty, because for custom functions the backward arity is the forward's outputarity, not its input arity. Hook registration on \texttt{Node} (\path{Autograd.cpp:95}) wraps the user hook with a GIL acquire so hooks are safe even when invoked from CUDA workers.

\begin{itemize}[leftmargin=1.2em]
\item The data structure is implemented in $\sim$1\,k lines (\path{tpx/include/*.h} + \path{tpx/src/Engine.cpp:713}). The compactness comes from trimming sparse/quantized/inference key combinations, alias-key remapping, and operator boxing.

\subsection{Invariants, Traces, and Local Verification}
\label{subsec:verify}

Checked invariants the code enforces; violations are either warned or hard-fail:

\begin{itemize}[leftmargin=1.2em]
\item \path{Node::add\_next\_edge:86} updates \path{topological\_nr\_:141} before pushing. Forgetting this would let \texttt{min\_topo} prune incorrectly and drop live dependencies.
\item \path{InputBuffer::can\_accumulate\_inplace:16} requires \texttt{use\_count==2} (temporary impl alias counts as one) and \texttt{storage==1}. Accumulating in-place on a shared storage would alias-corrupt a sibling.
\item \path{ReadyQueue::pop\_until:62} checks \texttt{stop()} \emph{after} the heap-empty test but \emph{before} waiting. Reversing the order would sleep one extra poll interval after the graph completes.
\item \path{GraphTask::task\_enqueued:67} must precede the queue push. Workers incrementally decrement and test \texttt{outstanding==0}; pushing without counting would hang the initiator.
\item \path{SavedVariable::unpack:20} throws with both \texttt{saved\_version\_} and current version. The message at \path{SavedVariable.cpp:22} is the same string users see in both codebases, enabling transferred runbooks.
\end{itemize}

The engine's \texttt{ReadyQueue} heuristic plus exact \texttt{dependencies\_} gating jointly guarantee that no node runs before its consumers have all delivered, yet nodes far from the root (large \texttt{sequence\_nr}) run as early as possible, bounding \texttt{not\_ready\_} occupancy. Together these three mechanisms (explicit DAG, versioned storage, global anomaly chain) are the contracts the rest of the framework relies on.
