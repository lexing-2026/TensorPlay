\section{重分发：分发键、分发器与注册宏}
\label{sec:redispatch}

Redispatch 将张量的运行时属性解析为键，选择
从每个操作员原子表中选择最高优先级内核，并强制执行
自动转换契约了一个单一的阻塞点。 Python表面暴露了相同的
通过两个合作层的运算符：手写的 \texttt{pybind11}
绑定和生成的 \texttt{METH\_FASTCALL} 函数，都是漏斗
通过 \texttt{CPythonBridge} 助手和共享的 \texttt{tp\_python}
图书馆。该设计将异构键空间修剪为 13 个插槽，编码分层
作为固定偏移量，以便优先级是算术，使用获取/释放原子
将类型擦除隔离到一个模板，而不是锁定热路径，并且
重用一种 Python 类型注册，以便返回的张量保留身份。

\subsection{DispatchKey：13 个键和固定偏移}
\label{sec:dispatchkey}

定义了 13 个 live key 加哨兵；
数字顺序优先：

\begin{lstlisting}[caption={13 keys.}, label=lst:dispatchkey]
enum class DispatchKey : uint8_t {
  CPU=0, CUDA=1, Vulkan=2,
  AutogradCPU=3, AutogradCUDA=4, AutogradVulkan=5,
  AutocastCPU=6, AutocastCUDA=7, AutocastVulkan=8,
  VmapCPU=9, VmapCUDA=10, VmapVulkan=11,
  Composite=12, EndOfKeys=13
};
constexpr size_t kBackendKeyCount=3, kAutogradKeyOffset=3,
                 kAutocastKeyOffset=6, kVmapKeyOffset=9;
\end{lstlisting}

\texttt{Composite}=12 的存储不符合逻辑优先级，因此
\texttt{dispatchKeyIndex} 是一个普通的
\texttt{static\_cast<size\_t>} 和 \texttt{Composite} 永远不会进入
\texttt{highest\_priority\_key} 扫描。帮手
 是 \texttt{constexpr}：

\begin{lstlisting}[caption={arithmetic helpers.}, label=lst:dispatchhelpers]
inline constexpr DispatchKey toAutogradKey(DispatchKey b){return DispatchKey(uint8_t(b)+kAutogradKeyOffset);}
inline constexpr DispatchKey toAutocastKey(DispatchKey b){return DispatchKey(uint8_t(b)+kAutocastKeyOffset);}
inline constexpr DispatchKey toVmapKey(DispatchKey b){return DispatchKey(uint8_t(b)+kVmapKeyOffset);}
inline constexpr bool is_autograd_key(DispatchKey k){uint8_t v=uint8_t(k); return v>=3 && v<6;}
inline constexpr bool is_autocast_key(DispatchKey k){uint8_t v=uint8_t(k); return v>=6 && v<9;}
inline constexpr bool is_vmap_key(DispatchKey k){uint8_t v=uint8_t(k); return v>=9 && v<12;}
inline constexpr bool is_backend_key(DispatchKey k){return k==DispatchKey::CPU||k==DispatchKey::CUDA||k==DispatchKey::Vulkan;}
inline constexpr DispatchKey toBackendKey(DispatchKey k){
  return is_vmap_key(k)?DispatchKey(uint8_t(k)-9):is_autograd_key(k)?DispatchKey(uint8_t(k)-3)
        :is_autocast_key(k)?DispatchKey(uint8_t(k)-6):k;}
\end{lstlisting}

\texttt{is\_backend\_key} 枚举三个密集键； \texttt{Composite}
为 false，它控制 \S\ref{sec:handle} 中的后备。
\texttt{computeDispatchKey} 地图 \texttt{Device}
经 \texttt{is\_cuda}/\texttt{is\_vulkan} 至 \texttt{Vulkan}。

\subsection{DispatchKeySet：位掩码和优先级}
\label{sec:keyset}

是一个 32 位的位集； 13 位直播：

\begin{lstlisting}[caption={bitmask.}, label=lst:keysetdef]
class DispatchKeySet{
public:
  using raw_t=uint32_t;
  constexpr DispatchKeySet() noexcept: mask_(0){}
  static constexpr DispatchKeySet make(DispatchKey k){return DispatchKeySet(raw_t(1)<<uint8_t(k));}
  void add(DispatchKey k){mask_|=raw_t(1)<<uint8_t(k);}
  bool has(DispatchKey k) const {return mask_ & (raw_t(1)<<uint8_t(k));}
  bool empty() const {return mask_==0;} raw_t raw() const {return mask_;}
  DispatchKeySet operator|(DispatchKeySet o) const {return DispatchKeySet(mask_|o.mask_);}
  // remove_autograd/autocast/vmap build masks by iterating kBackendKeyCount (3):
  DispatchKeySet remove_autograd() const {raw_t m=0; for(size_t i=0;i<3;++i) m|=raw_t(1)<<(i+3); return DispatchKeySet(mask_&~m);}
private: raw_t mask_=0;
};
\end{lstlisting}

优先级是最高有效的设置位，即最大的数字 \ac{op} 键获胜：

\begin{lstlisting}[caption={scan high $\rightarrow$ low.}, label=lst:highestkey]
constexpr DispatchKey highest_priority_key() const {
  if(!mask_) return DispatchKey::EndOfKeys;
  uint8_t idx=0; raw_t m=mask_; while(m>>=1) ++idx; return DispatchKey(idx);}
\end{lstlisting}

计算每次调用的集合；不
字段存储：

\begin{lstlisting}[caption={computed, not stored.}, label=lst:implkeyset]
DispatchKeySet key_set() const {
  DispatchKey backend=computeDispatchKey(device_);
  DispatchKeySet ks;
  if(is_batched()){ks.add(toVmapKey(backend)); return ks;}
  ks.add(backend);
  if(!inference_tensor_) ks.add(toAutogradKey(backend));
  return ks;
}
\end{lstlisting}

\texttt{is\_batched} 检查 \texttt{transform\_value\_!=nullptr}
;推理张量 (\texttt{inference\_tensor\_}
来自施工时的 \texttt{InferenceMode::is\_enabled}，
) 省略自动微分位。成本是一台设备查询加上
两个位操作，比存储位集的原子加载便宜。生成的重新调度
帮助者致电 \texttt{key\_set} 一次，
缓存结果，并通过 \texttt{OperatorHandle::getKernel} 处理顶部键进行迭代
然后用 \texttt{remove\_autograd} 剥离该层，直到
\texttt{highest\_priority\_key==EndOfKeys} 或找到内核；循环是
最多三次迭代，因为只能同时存在三层。

\subsection{调度表和调度程序}
\label{sec:dispatcher}

每个操作员存储一张固定表：

\begin{lstlisting}[caption={13 atomics per operator.}, label=lst:dispatchtable]
using KernelFunction = void*;
constexpr size_t kDispatchKeyCount = size_t(DispatchKey::EndOfKeys); // 13
inline constexpr size_t dispatchKeyIndex(DispatchKey k) noexcept {return size_t(k);}
struct P10_API DispatchTable{
  explicit DispatchTable(std::string n): name(std::move(n)){
    for(auto& k: kernels) k.store(nullptr,memory_order_relaxed);}
  std::string name;
  std::array<std::atomic<KernelFunction>, kDispatchKeyCount> kernels;
};
\end{lstlisting}

索引是一个强制转换。 ctor里的商店轻松，注册发布于
\texttt{release}，查找消耗 \texttt{acquire} （热路径上没有锁定）。
标题为 214 行。

\begin{lstlisting}[caption={registry map.}, label=lst:registermap]
class P10_API Dispatcher{
public:
  static Dispatcher& singleton();
  void registerKernel(const std::string& op, DispatchKey k, KernelFunction f);
  OperatorHandle findHandle(const std::string& op);
  std::vector<std::string> operator_names() const;
  KernelFunction direct_kernel(const std::string& op, DispatchKey k) const;
  bool has_kernel(const std::string& op, DispatchKey k) const;
private:
  Dispatcher()=default;
  std::unordered_map<std::string,std::unique_ptr<DispatchTable>> operators_;
  mutable std::mutex mutex_;
};
\end{lstlisting}

是迈耶的单例泄露以避免
退出顺序销毁：

\begin{lstlisting}[caption={singleton.}, label=lst:singleton]
Dispatcher& Dispatcher::singleton(){ static Dispatcher* instance=new Dispatcher(); return *instance; }
void Dispatcher::registerKernel(const std::string& op, DispatchKey k, KernelFunction f){
  if(dispatchKeyIndex(k)>=kDispatchKeyCount) throw std::invalid_argument("invalid key: "+op);
  std::lock_guard<std::mutex> lk(mutex_); auto& t=operators_[op];
  if(!t) t=std::make_unique<DispatchTable>(op);
  t->kernels[dispatchKeyIndex(k)].store(f,memory_order_release);}
\end{lstlisting}

\texttt{findHandle} 还锁定并创建
表如果不存在，则返回一个非拥有的 \texttt{OperatorHandle} ，其原始
\texttt{const DispatchTable*} 在进程生命周期内保持稳定。
\texttt{direct\_kernel}/\texttt{has\_kernel} 在锁定状态下加载，无需回退。

生成的redispatch函数将句柄缓存在本地，因此之后的热路径
预热执行两个 \texttt{acquire} 加载和一个预测分支；寒冷
添加新运算符的路径需要支付 \texttt{unordered\_map} 重新哈希和锁定。
内省助手 \texttt{direct\_kernel} 和 \texttt{has\_kernel} 存在
仅用于调试并故意避免复合回退，以便转储
工具可以区分“此键上没有内核”和“由 Composite 提供服务”。
所有三个助手都锁定，因为他们远离热路径并且必须观察
地图的一致快照，而并发注册可能会插入新的
table.

\subsection{OperatorHandle::getKernel：复合后备}
\label{sec:handle}

是热负载：

\begin{lstlisting}[caption={backend fallback.}, label=lst:getkernel]
KernelFunction getKernel(DispatchKey k) const noexcept {
  if(!table_ || dispatchKeyIndex(k)>=kDispatchKeyCount) return nullptr;
  auto v=table_->kernels[dispatchKeyIndex(k)].load(memory_order_acquire);
  if(!v && is_backend_key(k)){
    constexpr auto c=dispatchKeyIndex(DispatchKey::Composite);
    static_assert(c<kDispatchKeyCount,"composite out of range");
    v=table_->kernels[c].load(memory_order_acquire);
  }
  return v;
}
\end{lstlisting}

仅\texttt{is\_backend\_key}(0--2)查阅索引~12；自动微分/自动转换/vmap
要么有内核，要么缺失。显式后端条目覆盖 Composite
无需注销它，因此通用内核为所有后端提供服务，直到
出现特定于硬件的一个。两个负载都是 \texttt{acquire}，与
\texttt{release} 商店位于 \texttt{registerKernel}。

\subsection{DispatchStub：类型化的阻塞点和回溯}
\label{sec:stub}

是唯一的类型安全边界；
生成的代码永远不会在调用站点进行强制转换：

\begin{lstlisting}[caption={autocast guard + miss trace.}, label=lst:stub]
template<typename R, typename... Args>
struct DispatchStub{
  static R call(const OperatorHandle& h, DispatchKey k, Args... args){
    if(is_autocast_key(k) && !autocast::is_enabled(k)) [[unlikely]]
      TP_THROW(NotImplementedError,"Autocast kernel while disabled: "+std::string(h.name())+" "+toString(k));
    auto v=h.getKernel(k);
    if(!v){ if(getenv("TP_TRACE_KERNEL_MISS")){
        fprintf(stderr,"[kernel-miss] op=%s key=%d\n",h.name(),int(k));
        void* bt[32]; int n=backtrace(bt,32); backtrace_symbols_fd(bt,n,2);}
      TP_THROW(NotImplementedError,"Kernel not found for "+std::string(h.name())+" on "+toString(k));}
    using F=R(*)(Args...); auto fn=reinterpret_cast<F>(v);
    if constexpr(std::is_void_v<R>) fn(std::forward<Args>(args)...); else return fn(std::forward<Args>(args)...);
  }
  static R call(const std::string& op, DispatchKey k, Args... args){
    return call(Dispatcher::singleton().findHandle(op),k,std::forward<Args>(args)...);}
};
\end{lstlisting}

\texttt{autocast::is\_enabled} 是向前声明的
避免将 \texttt{Tensor.h} 拉入每个用户；守卫是唯一的
强制执行禁用自动转换 $\rightarrow$ 未命中合同的地方，即使
上层调度已经跳过它。提供 32 帧转储
当设置 \texttt{TP\_TRACE\_KERNEL\_MISS} 时为 fd~2。分支已标记
\texttt{[[unlikely]]} 所以预测的路径是非投掷的坠落路径，
在分支预测后添加对自动转换键的比较，而对其他键不添加比较。
字符串重载很方便；热调用将句柄缓存在 \texttt{static
const} local 在 (\texttt{static const
OperatorHandle op = Dispatcher::singleton.findHandle("add")}) 处发出，因此
\texttt{findHandle} 的互斥量在每个进程中获取一次，而不是在每次调用中获取一次。

\subsection{Python/C++ 双重绑定}
\label{sec:dualbinding}

使用 \texttt{UNITY\_BUILD ON} 构建 \texttt{\_C}
（30+ TU）； \texttt{p10} 选择退出。在非 Windows 上，
添加单个共享桥：

\begin{lstlisting}[caption={one shared copy.}, label=lst:tppythontarget]
if(NOT WIN32)
  add_library(tp_python SHARED src/bindings/python/CPythonBridge.cpp)
  target_link_libraries(tp_python PUBLIC p10 pybind11::pybind11)
endif()
\end{lstlisting}

评论解释：每个扩展副本
第一个返回的张量上的脚轮基底和包装缓存段错误，因为
每个副本都有自己的 \texttt{pybind11::detail::type\_caster} 注册表，并且
它自己的 \texttt{g\_wrap\_cache} 地图；第一个 \texttt{tpx\_py\_wrap} 来自
第二个扩展将插入到与第一个扩展不同的地图中
\texttt{tpx\_py\_tensor\_cref} 注册自。单个 \texttt{tp\_python}
强制使用一个注册表和一个缓存；用户操作模块通过构建
\texttt{add\_tensorplay\_op} 链接相同的库并在之后加载
\texttt{\_C} 已注册 \texttt{TensorBase}，因此他们的解包击中了
直接 \texttt{instance} 持有者路径。 \texttt{\_C} 链接 \texttt{p10 tpx stax
tp\_python}； Windows 嵌入桥
静态地，因为不存在 \texttt{\_\_declspec(dllexport)} 注释并且
否则 DLL 边界会隐藏注册表。

\paragraph{pybind11 路径。}
寄存器 \texttt{py::class\_<Tensor>(m,"TensorBase",py::dynamic\_attr)}；
 别名 \texttt{Tensor=\_C.TensorBase}。
\texttt{Ops.cpp} 手写 \texttt{.def} 来实现自定义语义（工厂 dtype
分辨率，splats）。 \texttt{PYBIND11\_MODULE(\_C,m)}
 调用 \texttt{init\_dtype} $\rightarrow$ \texttt{init\_ops}
按顺序。

\paragraph{METH\_FASTCALL 路径。} \texttt{gen\_python\_c.py}
发出 \texttt{TensorCPythonGenerated.h} 与

  {"add",(PyCFunction)(void*)pyop_add_function,METH_FASTCALL|METH_KEYWORDS,"add(Tensor self,...)"},

安装仅填充：

\paragraph{工厂蹦床。} installs six
\texttt{METH\_FASTCALL} 蹦床：

\begin{lstlisting}[caption={capture-aware trampoline.}, label=lst:factoryhook]
struct FactoryHook{PyObject *raw,*wrapper,*tensor_type,*scalar_type; bool varargs;};
PyObject* factory_trampoline(PyObject* self,PyObject* const* a,Py_ssize_t n,PyObject* kwnames){
  auto* h=(FactoryHook*)PyCapsule_GetPointer(self,nullptr);
  if(tensorplay::stax::currentCaptureState().compile_depth>0)
    return PyObject_Vectorcall(h->wrapper,a,size_t(n),kwnames);
  // normalize device strings, size listification, full(3,v)->full([3],v)
  return PyObject_Vectorcall(h->raw,a,size_t(n),kwnames);
}

\subsubsection{解析}

\begin{lstlisting}[caption={zero-alloc merge.}, label=lst:parseinto]
void tpx_py_parse_into(PyObject* const* a,Py_ssize_t n,PyObject* kwnames,
                       const char* const* kwlist,Py_ssize_t nkws,const char* op,PyObject** out){
  for(Py_ssize_t i=0;i<nkws;++i) out[i]=nullptr;
  if(n>nkws) throw std::invalid_argument(std::string(op)+": too many positionals");
  if(n>0) std::memcpy(out,a,size_t(n)*sizeof(PyObject*));
  Py_ssize_t nkw=kwnames?PyTuple_GET_SIZE(kwnames):0;
  for(Py_ssize_t i=0;i<nkw;++i){
    PyObject* k=PyTuple_GET_ITEM(kwnames,i); int slot=-1;
    for(Py_ssize_t j=0;j<nkws;++j) if(kwlist[j] && PyUnicode_CompareWithASCIIString(k,kwlist[j])==0){slot=int(j);break;}
    if(slot<0) throw std::invalid_argument(std::string(op)+": unexpected keyword");
    if(out[slot]) throw std::invalid_argument(std::string(op)+": multiple values for "+std::string(kwlist[slot]));
    out[slot]=a[n+i];}
}
\end{lstlisting}

\texttt{args[0..n)} 是位置，\texttt{args[n..n+nkw)} 是关键字
与 \texttt{kwnames} 平行的值（FASTCALL 约定）。线性关键词扫描
使用 \texttt{PyUnicode\_CompareWithASCIIString} 而不使用 UTF-8 实现；
重复/未知的键抛出 \texttt{invalid\_argument} 所以多重重载
团体可能会失败。

\subsubsection{打开包装并包裹}

\begin{lstlisting}[caption={identity cache.}, label=lst:wrapcache]

  const void* impl=t.unsafeGetTensorImpl().get();
  auto it=g_wrap_cache.find(impl); if(it!=g_wrap_cache.end()){Py_INCREF(it->second); return it->second;}
  PyObject* w=py::cast(t).release().ptr();
  if(impl){PyObject* c=PyCapsule_New(const_cast<void*>(impl),nullptr,&wrap_cache_capsule_destructor);
    if(c && PyObject_SetAttrString(w,"__tp_impl_capsule__",c)==0) g_wrap_cache.emplace(impl,w); Py_XDECREF(c);}

映射到Python：

\begin{lstlisting}[caption={map.}, label=lst:translate]
PyObject* translate_exception(const Exception& e){
  if(dynamic_cast<const IndexError*>(&e)) return PyExc_IndexError;
  if(dynamic_cast<const TypeError*>(&e)) return PyExc_TypeError;
  if(dynamic_cast<const NotImplementedError*>(&e)) return PyExc_NotImplementedError;

\end{lstlisting}

\texttt{g\_device\_mismatch\_type} 设置为via
\texttt{py::register\_exception<DeviceMismatchError>(m,"DeviceMismatchError",PyExc\_RuntimeError)}。
pybind11 翻译器附加了 C++ 堆栈跟踪
仅当 \texttt{TENSORPLAY\_SHOW\_CPP\_STACKTRACES=1} 时：

\begin{lstlisting}[caption={translator.}, label=lst:pytranslator]
py::register_exception_translator([](std::exception_ptr p){
  try{std::rethrow_exception(p);} catch(const tensorplay::Exception& e){
    std::string m=e.msg(); const char* v=getenv("TENSORPLAY_SHOW_CPP_STACKTRACES");
    if(v && std::string(v)=="1" && !e.stacktrace().empty()) m+="\n\n"+e.stacktrace();
    PyErr_SetString(translate_exception(e),m.c_str());}});
\end{lstlisting}

生成的 FASTCALL 主体包含
\texttt{catch(const std::exception\& e)\{tpx\_py\_set\_error(e); return nullptr;\}}
，分享
相同的映射，因此两条路径都显示相同的 Python 异常。两位译者
是互补的：pybind11 翻译器处理逃避任何异常的异常
\texttt{.def} 调用，而每个 FASTCALL 条目拥有自己的 try/catch，以便
参数解包期间的类型错误会报告操作名称和
尝试分派之前的参数索引，允许多重重载组
区分参数形状不匹配（\texttt{invalid\_argument} 失败）
来自内核故障（立即 \texttt{PyErr\_SetString}）。

\begin{tpexample}[Example: Tracing \texttt{tp.add(a,b)} Through All 13 Slots]
令 \texttt{a} 为 CPU 浮点张量，\texttt{requires\_grad=True} 和 \texttt{b} 为普通 CPU 浮点张量，禁用自动转换，无 vmap。桥接器将两者解压并调用为 \texttt{add} 生成的包装器。输出路径上的 \texttt{key\_set} 产生位 \texttt{CPU(0)} $\cup$ \texttt{AutogradCPU(3)} 因为 \texttt{a} 需要梯度。 \texttt{highest\_priority\_key} 返回 \texttt{AutogradCPU}=3，因此 \texttt{getKernel(3)} 找到生成的 autograd 包装器，该包装器记录 \texttt{AddBackward} 节点，然后用 \texttt{remove\_autograd} 调用 \texttt{redispatch\_add}。第二次迭代看到 \texttt{CPU}=0，通过 \texttt{DispatchStub::call} 在 \texttt{PointwiseKernels.cpp} 处找到 \texttt{add\_cpu}，并执行 TensorIterator 循环。步行恰好触及了十三个槽位中的两个；其余十一个从未装载。相同输入上的推理模式会产生一位集 \texttt{\{CPU\}} 和一次迭代。
\end{tpexample}
每个表条目都是枚举值或 \texttt{constexpr} 的直接转录，并且
每个列表都是逐字摘录，最多有空格折叠。篇幅不是通过散文的膨胀而是通过揭露五个具体的
定义重新调度的工件：使优先级成为的偏移算术
强制转换，避免存储位集的两分支 \texttt{key\_set}，13-
元素原子数组，使查找无锁，两级
\texttt{TP\_CONCAT} 使批量注册变得卫生，并且单个共享
\texttt{tp\_python} 保持施法者注册表和包装缓存一致
跨越双重绑定。

最终的不变量将各层联系在一起：\texttt{TensorImpl::key\_set} never
不会产生 \texttt{Composite}, \texttt{OperatorHandle::getKernel}
从非后端键回退，\texttt{DispatchStub} 永远不会看到禁用的
自动转换键而不抛出， \texttt{Library::impl} 从不存储 null
函数指针，FASTCALL 层永远不会隐藏 \texttt{pybind11} 名称，
\texttt{tpx\_py\_parse\_into} 永远不会写入超过 \texttt{nkws}（换行缓存）的内容
永远不会持有悬空指针，因为胶囊析构函数在
\texttt{TensorImpl} 删除器之前的 GIL 和 \texttt{translate\_exception}
永远不会返回 null，因为后备是 \texttt{RuntimeError}。检查每一个
不变式是一次搜索或 \texttt{gdb} 断点
线。
