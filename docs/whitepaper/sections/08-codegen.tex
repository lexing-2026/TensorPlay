\section{Code Generation and Build}
\label{sec:codegen}

Code generation is the only mechanism that can keep 479 operator schemas, 187 backward formulas, 13 dispatch keys, two language surfaces, and six build artifacts mutually consistent without drift. The contract is two YAML files; the engine is a pure-Python generator driven by the local schema model; the output is ten staged headers and sources that are compiled as ordinary translation units. Nothing is hand-edited after generation: the first line of every artifact reads \path{// Generated by tools/codegen/main.py -- DO NOT EDIT} (\path{build/generated/tensorplay/ops/TensorGenerated.h:1}) and the build refuses to link if the generator is stale.

\subsection{Contract: Two YAML Files}

\path{config/native\_functions.yaml:1} is 9\,445 lines (9\,415 at the cited tag, \path{wc -l config/native\_functions.yaml}) and declares 479 distinct operator names across 2\,809 \texttt{- func:} records when overloads and \texttt{.out} variants are expanded. Each entry binds five fields: \texttt{func} (the FunctionSchema string), \texttt{variants} (\texttt{function} and/or \texttt{method}), \texttt{dispatch} (a map from \texttt{CPU}, \texttt{CUDA}, \texttt{Composite} to kernel symbol), optional \texttt{python\_defaults}, and optional \texttt{device\_check} / \path{structured\_delegate} / \texttt{tags}. The schema string is the single source for the C++ signature, the Python binding, and the dispatcher key table. Variants decide surface: \texttt{function} becomes a static member \texttt{Tensor::zeros} and a module function \texttt{tensorplay.zeros}; \texttt{method} becomes an instance member \texttt{tensor.view}. A representative factory entry spells its defaults inline, e.g.\ \path{func: zeros(int[] size, *, ScalarType dtype=Float32, Device device=cpu, bool requires\_grad=False) -> Tensor} with \texttt{variants: function} and \texttt{dispatch: \{CPU: zeros\_cpu, CUDA: zeros\_cuda\}}. An in-place entry carries mutability in the type: \path{add\_(Tensor(a!) self, Tensor other, Scalar alpha=1) -> Tensor(a!)} with \texttt{variants: method}.

\path{config/derivatives.yaml:1} is 1\,330 lines (1\,324 at tag) with 345 \texttt{- name:} records that collapse to 187 backward formulas after grouping by base name. Each record names forward argument gradients symbolically: \path{name: add(Tensor self, Tensor other, Scalar alpha=1) -> Tensor} with \texttt{self: grad} and \texttt{other: grad * alpha} etc.\ The YAML never carries C++ types or dispatch keys; those are inferred from the native entry it references. Formulas may invoke dispatched ops (\texttt{mul}, \texttt{sum\_to\_shape}) and free functions parsed by the same expression AST that powers the backward-node emitter. Random ops add the \path{nondeterministic\_seeded} tag automatically (\path{tools/codegen/model.py:754}) and the \texttt{Vulkan} key remains reserved on CPU builds.

Both files are the only inputs the Python pipeline is allowed to read besides its own \texttt{*.py} sources. The invariant is checked structurally: \path{tools/codegen/model.py:1000} \texttt{parse\_native\_yaml} parses the same file twice through the local schema pipeline, normalizes \texttt{int64\_t} to \texttt{int} and \texttt{Composite} to \path{CompositeExplicitAutograd}, and raises \texttt{ValueError} on any dropped record, dispatch projection mismatch (\path{model.py:690}), variant mismatch (\path{model.py:730}), or operator-name collision (\path{model.py:1026}).

- func: add.Tensor(Tensor self, Tensor other, *, Scalar alpha=1) -> Tensor

  dispatch: {CPU: add_cpu, CUDA: add_cuda}

- func: add_.Tensor(Tensor(a!) self, Tensor other, *, Scalar alpha=1) -> Tensor(a!)

\subsection{Schema Model: \path{tools/codegen/model.py:1} (1\,055 lines)}

The model layer is a thin projection into the local schema records. \path{model.py:32} \texttt{\_ensure\_schema\_model} loads the parser modules and caches the module. \path{model.py:548} \texttt{parse\_schema} replaces \texttt{int64\_t} with \texttt{int}, recovers keyword-only arguments, and maps every parsed type through \texttt{\_type\_from\_tg} (\path{model.py:203}) into the local \texttt{Type} record (\path{model.py:143}). \texttt{Type} stores \texttt{kind}, \texttt{is\_list}, \texttt{is\_opt}, \texttt{mutability}, and \texttt{list\_elem\_opt}; helpers \texttt{is\_tensor\_like}, \texttt{is\_mutable\_ref}, and \path{is\_mutable\_tensor\_list} drive mutability handling downstream.

\path{model.py:250} \texttt{NativeFunction} carries \texttt{schema}, \texttt{base\_name}, \texttt{cpp\_name}, \texttt{overload\_name}, \path{args: list[Argument]}, \path{returns: list[ReturnDecl]}, \texttt{variants}, \texttt{dispatch}, \texttt{device\_check}, \path{structured\_delegate}, \texttt{pydefaults}, \texttt{schema\_kind} (\texttt{functional} / \texttt{inplace} / \texttt{mutable}), \texttt{tags}, and \texttt{backend\_metadata}. View metadata (\texttt{is\_view\_op}, \path{returns\_view\_of\_input}, \texttt{view\_input\_name}) is lazily loaded from \path{tools.autograd.gen\_inplace\_or\_view\_type} via \path{\_ensure\_view\_metadata} (\path{model.py:80}). \path{model.py:643} \path{\_native\_function\_from\_yaml} merges the local YAML fields onto the reference function, sets \path{cpp\_no\_default\_args}, and validates the dispatch map after normalizing \texttt{Composite} to \path{CompositeExplicitAutograd}. \path{model.py:832} \path{NativeFunctionCollection} wraps the resulting list and exposes \path{grouped\_native\_functions} and \path{grouped\_view\_functions} using the same pre-grouping the reference generator uses, so downstream generators see identical functional/out and view/view\_copy/view\_inplace groups as the canonical build.

\subsubsection{\path{model.py:548} \texttt{parse\_schema} through the schema model}

\texttt{parse\_schema} (\path{model.py:548}) is the only spelling of a FunctionSchema in the repository. It delegates to the local parser while preserving local invariants. Steps:

\begin{enumerate}[nosep, leftmargin=1.2em]
\item Normalize \texttt{int64\_t} to \texttt{int} for the parser while the local \texttt{Type.kind} keeps \texttt{int64\_t} via \texttt{\_KIND\_ALIASES} (\path{model.py:134}).
\item Call \path{tgm.FunctionSchema.parse} and assert round-trip fidelity (\path{model.py:554}: \texttt{str(ts) != schema} raises).
\item Recover keyword-only status from \path{ts.arguments.flat\_kwarg\_only} (\path{model.py:558}) because \texttt{ts.arguments.all} flattens the three buckets.
\item Expand \path{TensorOptionsArguments} wrappers (\path{model.py:576} \texttt{expand}) into the four constituent \texttt{dtype}/\texttt{layout}/\texttt{device}/\texttt{pin\_memory} arguments, in schema order.
\item Map each \texttt{tgm} type via \texttt{\_type\_from\_tg} (\path{model.py:203}) which peels \texttt{OptionalType} / \texttt{ListType}, detects \texttt{list\_elem\_opt}, and applies \texttt{_KIND\_ALIASES} (\texttt{SymInt} $\rightarrow$ \texttt{int64\_t} is reversed at \path{\_type\_from\_tg:218}).
\item Materialize mutability: when the \texttt{tgm} annotation is write (\path{model.py:562} \path{a.annotation.is\_write}) and the kind is \texttt{Tensor}, re-create the \texttt{Type} with \texttt{mutability="a"} so \texttt{is\_mutable\_ref} and \path{is\_mutable\_tensor\_list} are true.
\item Deduplicate the Python-facing rename \texttt{self} $\rightarrow$ \texttt{input} (\path{model.py:590}) with numeric suffixes when a schema already contains \texttt{input}.
\end{enumerate}

\subsection{Tensor Surface: \path{tools/codegen/gen\_api.py:1} (718 lines)}

Every operator obtains two surfaces: a backend redispatch funnel (\path{detail::redispatch\_*}) that resolves the kernel through the dispatcher and a public \texttt{Tensor} member that performs checks and transform dispatch before funneling into redispatch. Both are emitted from \texttt{gen\_api.py}.

\subsubsection{Overload Planning: \path{gen\_api.py:128} \texttt{plan\_members}}

C++ cannot overload on return type, default value, or constness alone. \path{gen\_api.py:78} \texttt{\_overload\_key} collapses a variant to \path{(cpp\_name, tuple(cpp\_arg\_type))} after stripping \texttt{requires\_grad} and, for \texttt{method}, \texttt{self}. \path{gen\_api.py:112} \texttt{\_prefix\_ambiguous} deems two members colliding when they share a common prefix of parameter types and every parameter past that prefix is defaulted on both sides; a call supplying only the prefix would be viable for both and overload resolution would be ambiguous. \path{gen\_api.py:64} \path{\_HANDWRITTEN\_TENSOR\_METHODS} lists members owned by \path{p10/include/Tensor.h:80} (\texttt{dim}, \texttt{numel}, \texttt{detach}, \texttt{as\_strided}, \texttt{to}, etc.); a handwritten no-argument member plus a generated one-argument member with a default would create the same ambiguity, so the handwritten owner wins. \texttt{plan\_members} iterates schemas in YAML order, records emitted parameter lists per \texttt{cpp\_name}, and marks \path{plan[(func\_name, variant)]} false when the new variant would collide or is handwritten. The map is consulted by both \texttt{generate\_header} and \texttt{generate\_cpp} so a suppressed member still keeps its redispatch helper and registration entry.

\subsubsection{Header Emission: \path{gen\_api.py:246} \texttt{generate\_header}}

\texttt{generate\_header} writes \texttt{TensorGenerated.h} under \texttt{\#pragma once} with \texttt{\#include <tuple>}. It replays \texttt{plan\_members}, deduplicates on \texttt{\_overload\_key}, and emits \texttt{static} for \texttt{function} variants (factory surface \texttt{Tensor::zeros}) and instance members otherwise, appending \texttt{const} via \texttt{\_is\_const\_method} (\path{gen\_api.py:95}) when \texttt{self} is not \texttt{a!}. Signatures are rendered by \path{gen\_api.py:172} \texttt{method\_signature} using \path{api\_types.cpp\_return\_type} and \texttt{cpp\_arg\_type} with defaults from \texttt{cpp\_default} unless \path{cpp\_no\_default\_args} suppresses them or the op is \texttt{.out}. The result is a header designed to be included inside \texttt{class Tensor} (\S\ref{sec:codegen_class_mixing}) rather than at namespace scope.

\subsubsection{Device and Key Resolution: \texttt{\_device\_source} and \path{\_dispatch\_key\_expr}}

\path{gen\_api.py:187} \texttt{\_device\_source} returns \path{(dispatch\_key\_source, target\_device\_expr)} for one schema and variant. If a \texttt{device} argument exists it is used directly, with optional-device fallback to \path{Device(DeviceType::CPU)} or \texttt{self.device()} for \texttt{\_like} factories; for \texttt{method} variants \texttt{device()} means \texttt{self.device()}, later rewritten to \texttt{self.device()} inside the free-function redispatch. Otherwise the first non-optional \texttt{Tensor}, then the first \texttt{Tensor[]} via \texttt{deviceForTensorArg}, otherwise CPU. \path{gen\_api.py:218} \path{\_dispatch\_key\_expr} selects the highest active transform key: \texttt{copy\_} uses its first argument, random factories in \path{\_RANDOM\_TRANSFORM\_OPS} (\path{gen\_api.py:31}) use \path{transform::dispatch\_key\_for\_random(computeDispatchKey(device))}, and the general case folds \path{dispatchKeyForTensorArgs(self, a, b)} across every tensor-like argument (method receiver becomes \texttt{*this} outside redispatch and \texttt{self} inside).

def _substitute(template: str, env: dict[str, str]) -> str:  # gen_pyi.py:500
    def replace(m):
        indent, key = m.group(1), m.group(2)
        if indent is None:  # mid-line hole: verbatim
            return env[key]
        content = textwrap.indent(env[key], indent)  # block hole
        return "\n".join(line.rstrip() for line in content.splitlines())

\subsection{CPython Fast Path: \path{tools/codegen/gen\_python\_c.py:1} (944 lines)}

\subsection{Freshness and Failure Modes}

Stale artifacts are not subtle: \path{CMakeLists.txt:891} depends on every \path{tools/codegen/*.py}, so touching any generator or schema parser forces regeneration before the next \texttt{ninja -C build} links. The \texttt{GENERATED TRUE} property tells CMake to delete outputs on \path{cmake --build --target clean}, and \path{build/generated/tensorplay/ops/} is \texttt{.gitignore}'d so no stale header can be accidentally committed. Failures are fail-fast: an unknown C++ type in \texttt{\_BRIDGE} (\path{gen\_python\_c.py:274} \texttt{\_require\_bridge}) raises \texttt{SystemExit} with \path{native CPython bridge has no converter for C++ type}, an unhandled default in \texttt{\_default\_pyobject} raises the same, and a dispatch projection mismatch (\path{model.py:708}) prints both expected and actual kernel maps. The most common user error is editing \texttt{TensorGenerated.h} by hand; the file header \path{// Generated by tools/codegen/main.py -- DO NOT EDIT} is a contract: the next build overwrites it and \texttt{git diff} shows the drift.

\subsection{Why Generation Beats Metaprogramming}

A conceivable alternative is C++ templates that expand schemas at compile time. TensorPlay rejects it for three concrete reasons. First, overload ambiguity (\path{plan\_members:128}) is a property of the C++ overload set and cannot be decided by a macro that sees one schema at a time; the Python planner sees the whole set and drops later colliding overloads. Second, Python defaults (\texttt{python\_defaults} in YAML) require knowledge of the Python signature reorder (\texttt{gen\_python.py}) that no C++ template can synthesize. Third, the profiler and version-bump code inside \path{\_emit\_redispatch:304} reference symbols (\texttt{OpRecord}, \texttt{GpuTimerPair}, \texttt{OperatorHandle}) whose names are stringified from \texttt{func\_name}; a template would need \path{\_\_PRETTY\_FUNCTION\_\_} parsing. Staged generation keeps the C++ compiler as a pure consumer of well-formed headers, which is why \texttt{p10} deliberately opts out of \texttt{UNITY\_BUILD} (\path{CMakeLists.txt}) while \texttt{\_C} opts in.
