\section{Code Generation and Build}
\label{sec:codegen}

Code generation is the only mechanism that can keep 479 \ac{op} schemas, 187 backward formulas, 13 dispatch keys, two language surfaces, and six build artifacts mutually consistent without drift. The contract is two YAML files; the engine is a pure-Python generator driven by the local schema model; the output is ten staged headers and sources that are compiled as ordinary translation units. Nothing is hand-edited after generation: the first line of every artifact reads \texttt{main.py -- DO NOT EDIT} and the build refuses to link if the generator is stale.

\subsection{Contract: Two YAML Files}

The operator registry \texttt{native\_functions.yaml} is 9\,445 lines and declares 479 distinct operator names across 2\,809 \texttt{- func:} records when overloads and \texttt{.out} variants are expanded. Each entry binds five fields: \texttt{func} (the FunctionSchema string), \texttt{variants} (\texttt{function} and/or \texttt{method}), \texttt{dispatch} (a map from \texttt{CPU}, \texttt{CUDA}, \texttt{Composite} to kernel symbol), optional \texttt{python\_defaults}, and optional \texttt{device\_check} / \texttt{structured\_delegate} / \texttt{tags}. The schema string is the single source for the C++ signature, the Python binding, and the dispatcher key table. Variants decide surface: \texttt{function} becomes a static member \texttt{Tensor::zeros} and a module function \texttt{tensorplay.zeros}; \texttt{method} becomes an instance member \texttt{tensor.view}. A representative factory entry spells its defaults inline, e.g.\ \texttt{func: zeros(int[] size, *, ScalarType dtype=Float32, Device device=cpu, bool requires\_grad=False) -> Tensor} with \texttt{variants: function} and \texttt{dispatch: \{CPU: zeros\_cpu, CUDA: zeros\_cuda\}}. An in-place entry carries mutability in the type: \texttt{add\_(Tensor(a!) self, Tensor other, Scalar alpha=1) -> Tensor(a!)} with \texttt{variants: method}.

 is 1\,330 lines (1\,324 at tag) with 345 \texttt{- name:} records that collapse to 187 backward formulas after grouping by base name. Each record names forward argument gradients symbolically: \texttt{name: add(Tensor self, Tensor other, Scalar alpha=1) -> Tensor} with \texttt{self: grad} and \texttt{other: grad * alpha} etc.\ The YAML never carries C++ types or dispatch keys; those are inferred from the native entry it references. Formulas may invoke dispatched ops (\texttt{mul}, \texttt{sum\_to\_shape}) and free functions parsed by the same expression AST that powers the backward-node emitter. Random ops add the \texttt{nondeterministic\_seeded} tag automatically and the \texttt{Vulkan} key remains reserved on CPU builds.

Both files are the only inputs the Python pipeline is allowed to read besides its own \texttt{*.py} sources. The invariant is checked structurally: \texttt{parse\_native\_yaml} parses the same file twice through the local schema pipeline, normalizes \texttt{int64\_t} to \texttt{int} and \texttt{Composite} to \texttt{CompositeExplicitAutograd}, and raises \texttt{ValueError} on any dropped record, dispatch projection mismatch, variant mismatch, or operator-name collision.

\begin{tpnote}[Note: YAML Is the Single Source of Truth---Everything Else Is Derived]
Every generated surface is a pure function of the two YAML files. The C++ signatures, the Python bindings, the \texttt{.pyi} stubs, the dispatcher key tables, the backward nodes, and the autocast registrations are all \emph{derived artifacts}: regenerating from the same YAML always reproduces byte-identical outputs, and the \texttt{DO NOT EDIT} header at makes hand modification detectable rather than merely discouraged. The practical consequence for contributors: \emph{never} edit a generated file to fix a compile error---the fix belongs in the YAML or in the generator, and will overwrite the hand edit on the next build. The single-source rule is what makes the completeness checks of this chapter meaningful: they verify the \emph{projection} from YAML to artifacts is total and injective, which is only a well-defined claim because the direction is one-way.
\end{tpnote}

\subsection{Schema Model: (1\,055 lines)}

The model layer is a thin projection into the local schema records. \texttt{\_ensure\_schema\_model} loads the parser modules and caches the module. \texttt{parse\_schema} replaces \texttt{int64\_t} with \texttt{int}, recovers keyword-only arguments, and maps every parsed type through \texttt{\_type\_from\_tg} into the local \texttt{Type} record. \texttt{Type} stores \texttt{kind}, \texttt{is\_list}, \texttt{is\_opt}, \texttt{mutability}, and \texttt{list\_elem\_opt}; helpers \texttt{is\_tensor\_like}, \texttt{is\_mutable\_ref}, and \texttt{is\_mutable\_tensor\_list} drive mutability handling downstream.

 \texttt{NativeFunction} carries \texttt{schema}, \texttt{base\_name}, \texttt{cpp\_name}, \texttt{overload\_name}, \texttt{args: list[Argument]}, \texttt{returns: list[ReturnDecl]}, \texttt{variants}, \texttt{dispatch}, \texttt{device\_check}, \texttt{structured\_delegate}, \texttt{pydefaults}, \texttt{schema\_kind} (\texttt{functional} / \texttt{inplace} / \texttt{mutable}), \texttt{tags}, and \texttt{backend\_metadata}. View metadata (\texttt{is\_view\_op}, \texttt{returns\_view\_of\_input}, \texttt{view\_input\_name}) is lazily loaded from \texttt{tools.autograd.gen\_inplace\_or\_view\_type} via \texttt{\_ensure\_view\_metadata}. \texttt{\_native\_function\_from\_yaml} merges the local YAML fields onto the reference function, sets \texttt{cpp\_no\_default\_args}, and validates the dispatch map after normalizing \texttt{Composite} to \texttt{CompositeExplicitAutograd}. \texttt{NativeFunctionCollection} wraps the resulting list and exposes \texttt{grouped\_native\_functions} and \texttt{grouped\_view\_functions} using the same pre-grouping the reference generator uses, so downstream generators see identical functional/out and view/view\_copy/view\_inplace groups as the canonical build.

\subsubsection{ \texttt{parse\_schema} through the schema model}

\texttt{parse\_schema} is the only spelling of a FunctionSchema in the repository. It delegates to the local parser while preserving local invariants. Steps:

\begin{enumerate}[nosep, leftmargin=1.2em]
\item Normalize \texttt{int64\_t} to \texttt{int} for the parser while the local \texttt{Type.kind} keeps \texttt{int64\_t} via \texttt{\_KIND\_ALIASES}.
\item Call \texttt{tgm.FunctionSchema.parse} and assert round-trip fidelity (: \texttt{str(ts) != schema} raises).
\item Recover keyword-only status from \texttt{ts.arguments.flat\_kwarg\_only} because \texttt{ts.arguments.all} flattens the three buckets.
\item Expand \texttt{TensorOptionsArguments} wrappers ( \texttt{expand}) into the four constituent \texttt{dtype}/\texttt{layout}/\texttt{device}/\texttt{pin\_memory} arguments, in schema order.
\item Map each \texttt{tgm} type via \texttt{\_type\_from\_tg} which peels \texttt{OptionalType} / \texttt{ListType}, detects \texttt{list\_elem\_opt}, and applies \texttt{\_KIND\_ALIASES} (\texttt{SymInt} $\rightarrow$ \texttt{int64\_t} is reversed at).
\item Materialize mutability: when the \texttt{tgm} annotation is write ( \texttt{a.annotation.is\_write}) and the kind is \texttt{Tensor}, re-create the \texttt{Type} with \texttt{mutability="a"} so \texttt{is\_mutable\_ref} and \texttt{is\_mutable\_tensor\_list} are true.
\item Deduplicate the Python-facing rename \texttt{self} $\rightarrow$ \texttt{input} with numeric suffixes when a schema already contains \texttt{input}.
\end{enumerate}

\subsection{Tensor Surface: (718 lines)}

Every operator obtains two surfaces: a backend redispatch funnel that resolves the kernel through the dispatcher and a public \texttt{Tensor} member that performs checks and transform dispatch before funneling into redispatch. Both are emitted from \texttt{gen\_api.py}.

\subsubsection{Overload Planning: \texttt{plan\_members}}

C++ cannot overload on return type, default value, or constness alone. \texttt{\_overload\_key} collapses a variant to \texttt{(cpp\_name, tuple(cpp\_arg\_type))} after stripping \texttt{requires\_grad} and, for \texttt{method}, \texttt{self}. \texttt{\_prefix\_ambiguous} deems two members colliding when they share a common prefix of parameter types and every parameter past that prefix is defaulted on both sides; a call supplying only the prefix would be viable for both and overload resolution would be ambiguous. \texttt{\_HANDWRITTEN\_TENSOR\_METHODS} lists members owned by (\texttt{dim}, \texttt{numel}, \texttt{detach}, \texttt{as\_strided}, \texttt{to}, etc.); a handwritten no-argument member plus a generated one-argument member with a default would create the same ambiguity, so the handwritten owner wins. \texttt{plan\_members} iterates schemas in YAML order, records emitted parameter lists per \texttt{cpp\_name}, and marks \texttt{plan[(func\_name, variant)]} false when the new variant would collide or is handwritten. The map is consulted by both \texttt{generate\_header} and \texttt{generate\_cpp} so a suppressed member still keeps its redispatch helper and registration entry.

\subsubsection{Header Emission: \texttt{generate\_header}}

\texttt{generate\_header} writes \texttt{TensorGenerated.h} under \texttt{\#pragma once} with \texttt{\#include <tuple>}. It replays \texttt{plan\_members}, deduplicates on \texttt{\_overload\_key}, and emits \texttt{static} for \texttt{function} variants (factory surface \texttt{Tensor::zeros}) and instance members otherwise, appending \texttt{const} via \texttt{\_is\_const\_method} when \texttt{self} is not \texttt{a!}. Signatures are rendered by \texttt{method\_signature} using \texttt{api\_types.cpp\_return\_type} and \texttt{cpp\_arg\_type} with defaults from \texttt{cpp\_default} unless \texttt{cpp\_no\_default\_args} suppresses them or the op is \texttt{.out}. The result is a header designed to be included inside \texttt{class Tensor} (\S\ref{sec:codegen_class_mixing}) rather than at namespace scope.

\subsubsection{Device and Key Resolution: \texttt{\_device\_source} and \texttt{\_dispatch\_key\_expr}}

 \texttt{\_device\_source} returns \texttt{(dispatch\_key\_source, target\_device\_expr)} for one schema and variant. If a \texttt{device} argument exists it is used directly, with optional-device fallback to \texttt{Device(DeviceType::CPU)} or \texttt{self.device} for \texttt{\_like} factories; for \texttt{method} variants \texttt{device} means \texttt{self.device}, later rewritten to \texttt{self.device} inside the free-function redispatch. Otherwise the first non-optional \texttt{Tensor}, then the first \texttt{Tensor[]} via \texttt{deviceForTensorArg}, otherwise CPU. \texttt{\_dispatch\_key\_expr} selects the highest active transform key: \texttt{copy\_} uses its first argument, random factories in \texttt{\_RANDOM\_TRANSFORM\_OPS} use \texttt{transform::dispatch\_key\_for\_random(computeDispatchKey(device))}, and the general case folds \texttt{dispatchKeyForTensorArgs(self, a, b)} across every tensor-like argument (method receiver becomes \texttt{*this} outside redispatch and \texttt{self} inside).

\subsubsection{Redispatch Funnel: \texttt{\_emit\_redispatch} and \texttt{OpRecord}}

\texttt{\_emit\_redispatch} emits one free function \texttt{detail::redispatch\_<op>\_<variant>} per schema under \texttt{namespace detail}:

\begin{lstlisting}[caption={skeleton of \texttt{\_emit\_redispatch} (simplified).}, label=lst:emitredispatch, style=cppstyle]

\subsubsection{Eager Members: \texttt{generate\_cpp} and Device Guards}

\texttt{generate\_cpp} runs two passes. Pass~1 emits the redispatch funnels deduplicated on \texttt{redispatch\_key}. Pass~2 emits public \texttt{Tensor} members deduplicated on \texttt{\_overload\_key} and filtered by \texttt{plan\_members}. Each member is qualified \texttt{Tensor::} and opens with special-case fast paths: \texttt{copy\_} validates \texttt{shape} equality, \texttt{contiguous} resolves \texttt{MemoryFormat::Preserve} and returns \texttt{*this} when already contiguous to avoid tagging a leaf alias with a \texttt{ContiguousBackward} node. \texttt{\_emit\_device\_checks} follows: scalar \texttt{Tensor} and \texttt{Tensor?} emit \texttt{if (a.device != target) TP\_THROW(DeviceMismatchError,\dots)}; \texttt{Tensor[]} loops over elements and reports the offending argument name. Checks are skipped for \texttt{device\_check == NoCheck} and for \texttt{copy\_} whose destination device is the target.

The ordering of keys inside the member is load-bearing. After device checks, vmap at offset~9 is probed first: compute \texttt{\_\_tp\_key = dispatchKeyForTensorArgs(...)}, test \texttt{is\_vmap\_key}, and directly \texttt{DispatchStub::call} through the vmap handle with a \texttt{NotImplementedError} if no batch rule is registered. Autocast is second: compute \texttt{\_\_ac\_key = toAutocastKey(computeDispatchKey(dev\_src))}, check \texttt{autocast::is\_enabled} before probing \texttt{getKernel}, and dispatch if present. Autograd is third: \texttt{autograd\_ops} maps \texttt{func\_name} to a backward node name and the member dispatches through \texttt{toAutogradKey} when \texttt{GradMode::is\_enabled} and a kernel is registered. If none of the transform keys fires, the tail calls \texttt{detail::redispatch\_<op>\_<variant>}.

\subsubsection{Redispatch Header: \texttt{generate\_redispatch\_header}}

\texttt{generate\_redispatch\_header} writes \texttt{TensorRedispatchGenerated.h} with \texttt{\#include "Tensor.h"} and \texttt{\#include "Macros.h"} inside \texttt{namespace tensorplay::detail}, declaring each \texttt{TENSORPLAY\_API Ret redispatch\_<op>\_<variant>(stub\_args)} once. The header is included by both the eager compilation unit and the autograd wrappers so that the autograd layer can invoke the same dispatched kernel without re-resolving the handle.

\subsection{Autograd Surface: (624 lines)}

\texttt{gen\_tpx.py} produces the \texttt{AutogradCPU}/\texttt{AutogradCUDA} kernels that live in \texttt{tpx}. Every operator exposes \texttt{tensorplay::tpx::ops::<name>} routing through autocast, mutation guards, the backend, and backward-node construction.

\subsubsection{Inlining Predicate: \texttt{\_inline\_forward\_lines} vs.\ Non-Inline}

The core call expression \texttt{\_core\_call\_expr} selects \texttt{::tensorplay::detail::redispatch\_<op>\_<variant>} or, for \texttt{manual\_kernel\_registration}, the underlying \texttt{Tensor::} member.

\subsubsection{Header Split: \texttt{generate\_tpx\_ops\_h}}

\subsubsection{Wrapper Body: \texttt{generate\_tpx\_ops\_cpp}}

Each out-of-line wrapper follows the same five blocks. (1) Factory global-default resolution fills \texttt{device} from \texttt{globalContext.defaultDevice} and, for \texttt{rand}, \texttt{randn}, \texttt{empty}, \texttt{zeros}, \texttt{ones}, \texttt{dtype} from \texttt{globalContext.defaultDType} when the caller leaves them unset; \texttt{arange}/\texttt{linspace} are excluded because they infer dtype from scalar inputs. (2) Autocast: \texttt{\_emit\_autocast\_block} re-derives the device source from the first tensor argument and dispatches through \texttt{toAutocastKey} when \texttt{autocast::is\_enabled}. (3) Gradient bookkeeping: \texttt{\_emit\_requires\_grad\_detection} sets \texttt{bool requires\_grad} from \texttt{GradMode}, \texttt{InferenceMode}, and any tensor needing grad; \texttt{\_emit\_leaf\_checks} forbids in-place mutation of leaves or of multi-output views; and for in-place ops whose derivative uses \texttt{self} a pre-mutation clone \texttt{\_\_tp\_original\_self} is captured under \texttt{GradMode} disabled. (4) Core invocation stores \texttt{core\_result} / \texttt{result} per \texttt{cpp\_return\_kind} (\texttt{value}, \texttt{tuple}, \texttt{list}, \texttt{mut\_ref}, \texttt{void}). For view ops the wrapper shares the version counter, marks \texttt{is\_view}, and installs view metadata with \texttt{CreationMeta::DEFAULT} or \texttt{MULTI\_OUTPUT\_NODE} via the replay lambda \texttt{\_view\_replay\_lambda}. (5) Backward node: \texttt{\_node\_ctor\_args} orders constructor arguments from \texttt{derivatives} formulas, \texttt{\_emit\_edges} collects \texttt{Edge}s (including list-typed overloads), and the result is wrapped with \texttt{set\_grad\_fn} / \texttt{set\_requires\_grad} per return kind. \texttt{generate\_autograd\_registration} then registers each wrapper once for keys \texttt{AutogradCPU}, \texttt{AutogradCUDA}, \texttt{AutogradVulkan} via \texttt{Dispatcher::registerKernel}.

\subsection{Type Mapping: (540 lines)}

\texttt{api\_types.py} is the single vocabulary for C++ spellings. \texttt{cpp\_arg\_type} maps \texttt{Type} to the stub type seen in \texttt{gen\_api.py}: \texttt{Tensor(a!)} becomes \texttt{Tensor\&}, optional lists become \texttt{std::optional<std::vector<int64\_t>>}, and \texttt{SymInt} aliases to \texttt{int64\_t} the ABI boundary. \texttt{api\_types.cpp\_return\_type} classifies the return into \texttt{void}, \texttt{value}, \texttt{tuple}, \texttt{list}, or \texttt{mut\_ref} by inspecting \texttt{NativeFunction.returns} and \texttt{cpp\_return\_kind}; this drives both the header return type and the redispatch stub template. \texttt{binding\_default} and \texttt{cpp\_default} render schema defaults for C++ headers versus pybind11 bindings, while \texttt{python\_default} renders \texttt{None}/\texttt{True}/\texttt{False} for the Python surface. The module is imported by all three C++ generators, so a change to the spelling of \texttt{MemoryFormat} or \texttt{Device} propagates atomically.

\subsection{Derivative Compilation: (785 lines)}

Derivatives are not string-substituted; they are compiled. \texttt{gen\_autograd.py} tokenizes each formula, builds an expression AST (nodes \texttt{Num}, \texttt{BoolLit}, \texttt{Var}, \texttt{Call}), and runs a precedence-climbing parser that converts comparisons into dispatched ops ( \texttt{\_normalize\_comparisons} rewrites \texttt{a > b} to \texttt{gt(a,b)}). \texttt{OpDerivatives} stores \texttt{node\_name}, \texttt{members}, \texttt{used\_input\_names}, and per-output formulas. A single walk over the AST collects saved-variable needs, so the struct definition, its constructor argument list, and every call site that constructs \texttt{grad\_fn} agree by construction. List-mapping backwards (\texttt{cat}, \texttt{stack}, \texttt{roll}) that cannot be expressed as scalar formulas are declared in \texttt{MANUAL\_DERIVATIVES} and emitted as hand-written node instantiations. The output \texttt{AutogradNodesGenerated.h} contains 148 node structs; each holds saved tensors as \texttt{SavedVariable} where needed and an \texttt{apply} that replays the formula with the correct broadcasting.

\subsection{Autocast, Structured, and Alias Shims}

The file is \texttt{GENERATED TRUE} and linked into \texttt{p10}, but its kernels are only consulted when \texttt{autocast::is\_enabled} is true; the disabled path is a single thread-local load. and each write a one-header shim. Structured delegates record which ops forward to a meta kernel; alias shims expose view predicates so the Python surface can report \texttt{is\_view} without touching the C++ object.     def replace(m):
        indent, key = m.group(1), m.group(2)
        if indent is None:  # mid-line hole: verbatim
            return env[key]
        content = textwrap.indent(env[key], indent)  # block hole

\subsection{CPython Fast Path: (944 lines)}

\texttt{gen\_python\_c.py} owns the \texttt{METH\_FASTCALL | METH\_KEYWORDS} layer that bypasses \texttt{pybind11} overload dispatch. \texttt{\_BRIDGE} maps every C++ argument type to a \texttt{CPythonBridge.h} unpacker (\texttt{tpx\_py\_tensor\_cref}, \texttt{tpx\_py\_int64}, \texttt{tpx\_py\_intlist}, etc.); \texttt{\_KIND\_CONST} maps the same to \texttt{TPK\_INT} / \texttt{TPK\_TENSOR} kind bytes for eager type checking. \texttt{\_emit\_op} emits one native entry per overload: it builds \texttt{kwlist}, parses positional and keyword arguments via \texttt{tpx\_py\_parse\_into}, validates required arguments, performs kind checking against a static \texttt{tpx\_kinds} table, unpacks through \texttt{\_BRIDGE}, releases the GIL around the \texttt{tpx::ops::} invoke, and packs the result via \texttt{\_pack\_expr}. Multi-overload names obtain a group dispatcher that tries candidates in declaration order, falling through only on \texttt{std::invalid\_argument} (argument-shape mismatch) while kernel failures convert immediately. The module installs the tables via \texttt{register\_generated\_cpython\_functions} and \texttt{register\_generated\_cpython\_methods}, skipping any name already bound by hand so factory dtype/device resolution semantics remain authoritative.

\subsection{Freshness and Failure Modes}

Stale artifacts are not subtle: depends on every \texttt{*.py}, so touching any generator or schema parser forces regeneration before the next \texttt{ninja -C build} links. The \texttt{GENERATED TRUE} property tells CMake to delete outputs on \texttt{cmake --build --target clean}, and  is \texttt{.gitignore}'d so no stale header can be accidentally committed. Failures are fail-fast: an unknown C++ type in \texttt{\_BRIDGE} ( \texttt{\_require\_bridge}) raises \texttt{SystemExit} with \texttt{native CPython bridge has no converter for C++ type}, an unhandled default in \texttt{\_default\_pyobject} raises the same, and a dispatch projection mismatch prints both expected and actual kernel maps. The most common user error is editing \texttt{TensorGenerated.h} by hand; the file header \texttt{main.py -- DO NOT EDIT} is a contract: the next build overwrites it and \texttt{git diff} shows the drift.

\subsection{Why Generation Beats Metaprogramming}

A conceivable alternative is C++ templates that expand schemas at compile time. TensorPlay rejects it for three concrete reasons. First, \ac{op} overload ambiguity is a property of the C++ overload set and cannot be decided by a macro that sees one schema a time; the Python planner sees the whole set and drops later colliding overloads. Second, Python defaults (\texttt{python\_defaults} in YAML) require knowledge of the Python signature reorder (\texttt{gen\_python.py}) that no C++ template can synthesize. Third, the profiler and version-bump code inside reference symbols (\texttt{OpRecord}, \texttt{GpuTimerPair}, \texttt{OperatorHandle}) whose names are stringified from \texttt{func\_name}; a template would need \texttt{\_\_PRETTY\_FUNCTION\_\_} parsing. Staged generation keeps the C++ compiler as a pure consumer of well-formed headers, which is why \texttt{p10} deliberately opts out of \texttt{UNITY\_BUILD} while \texttt{\_C} opts in.

\subsection{Design Trade-offs}
\label{sec:codegen:tradeoffs}

\textbf{Two-file contract vs.\ one unified IR source.} Merging \texttt{native\_functions.yaml} and \texttt{derivatives.yaml} into one schema would make cross-file consistency checks unnecessary. Rejected: forward signatures change on kernel refactors while backward formulas change on math fixes; separate files let the two reviews proceed independently, and already enforces the join (every derivative name must resolve to a native \texttt{func\_name}). One file would couple unrelated edits and grow merge conflicts linearly with contributor count.

\textbf{Python generators vs.\ a compiled generator.} A C++ generator would remove the \texttt{python} runtime dependency from the build. Rejected: the generators need the YAML parser, expression AST, and name-resolution logic that already exist as reviewed Python modules; re-implementing them in C++ duplicates $\sim$3\,k lines to save $\sim$2\,s of build time (generation is 4.6\,s total, Table~\ref{tab:codegen_sizes}). The \texttt{PYTHONPATH} staging at keeps the build dependency explicit and hermetic.

\textbf{Regenerate-on-every-build vs.\ checked-in artifacts.} Committing the generated files would make builds work without Python. Rejected:  is deliberately gitignored so that review sees the \emph{contract}, not one snapshot of it; a checked-in header would rot silently when YAML and artifact drift, and the drift would surface as a confusing compile error far from its cause. The 4.6\,s regeneration cost is paid once per clean build and once per generator edit, both rare.
