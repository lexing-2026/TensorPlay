\section{Evaluation: Readability, Correctness, and Overhead}
\label{sec:eval}

This chapter evaluates TensorPlay on three axes that a readable framework must earn: how small the core is to read, how precisely it guards correctness when the training loop mutates tensors, and how little it costs when every guard and profiler probe is disabled. All numbers cite \texttt{path:line} and are reproducible with \texttt{grep -rn} on the tree at \path{version.txt:1}.

\texttt{DispatchTable} at \path{p10/include/Dispatcher.h:49} is therefore \path{array<atomic<KernelFunction>,13>} with each slot relaxed-initialized to \texttt{nullptr} and published with \path{memory\_order\_release} (\path{Dispatcher.cpp:14}). \texttt{DispatchKeySet} at \path{DispatchKey.h:125} is a \texttt{uint32\_t} bitset over the 13 keys; \path{highest\_priority\_key:151} scans the mask for the numerically largest bit, so priority is \path{Vmap $>$ Autocast $>$ Autograd $>$ backend}. Helpers \path{remove\_autograd:160}, \path{remove\_autocast:169}, \path{remove\_vmap:177} clear one axis at a time, used by redispatch below each layer.

TensorPlay keeps a compact set of dispatch keys and leaves specialized axes outside the core table. There is no \texttt{Meta} key or open registration API: \path{Dispatcher::registerKernel:14} is a closed \path{unordered\_map<string,DispatchTable>} guarded by one mutex, and \path{TENSORPLAY\_LIBRARY\_IMPL:203} expands to a process-lifetime static constructor. The cost is that shape-only inference, sparse dispatch, and quantized dispatch have no dedicated fast path; they either share the \texttt{Composite} fallback or are explicitly unsupported, which \path{docs/gap\_analysis.md} \S10 records.

\begin{lstlisting}[caption={\path{Dispatcher.h:67} --- \texttt{Composite} fallthrough in the hot path.}, label=lst:composite]
KernelFunction getKernel(DispatchKey key) const noexcept {
  auto k = table_->kernels[dispatchKeyIndex(key)].load(acquire);
  if (!k && is_backend_key(key)) {                          // Dispatcher.h:75
    constexpr auto kCompositeIdx = dispatchKeyIndex(Composite);
    k = table_->kernels[kCompositeIdx].load(acquire);       // one extra load
  }
  return k;
}
\end{lstlisting}

\subsection{Autograd Nodes: 148 Generated, Explicit DAG, No Tape}
\label{subsec:eval-autograd-nodes}

\path{tools/codegen/gen\_autograd.py:785} parses \path{config/derivatives.yaml:1} (345 raw records collapsing to 187 formulas after grouping) through an expression AST and emits \path{build/generated/tensorplay/ops/AutogradNodesGenerated.h} with 148 node structs. Each node stores saved forward tensors as \texttt{tpx::SavedVariable} (\path{tpx/include/SavedVariable.h:15}) where the formula needs them and synthesizes \texttt{apply} from the same AST that decided the save set, so the save list, constructor, and \texttt{apply} cannot drift. Handwritten nodes that formulas cannot express (\path{cat/stack/roll}) live in \path{tpx/include/ManualNodes.h:1200} and follow the same \texttt{SavedVariable} contract.

There is no Tape. \path{grep -rn Tape tpx/} returns zero. The graph is the transitive closure of \path{Node::next\_edges\_:150} where each \texttt{Edge} (\path{tpx/include/Edge.h:14}) carries only hints (\path{shape\_hint:21}, \texttt{grad\_dtype:27}, \path{device\_type\_hint:33}) so backward can \texttt{ops::zeros} a missing gradient without touching the forward tensor. \texttt{GraphTask} (\path{tpx/include/GraphTask.h:22}) holds \path{unordered\_map<Node*,int> dependencies\_:44} built once by \path{Engine::compute\_dependencies:192}, \path{unordered\_map<Node*,InputBuffer> not\_ready\_:43} keyed by raw \texttt{Node*}, and \path{vector<Tensor> captured\_vars\_:50} for \texttt{grad()} outputs. \texttt{ReadyQueue} (\path{tpx/include/Engine.h:23}) is a max-heap ordered by \path{Node::sequence\_nr\_:151} assigned from \path{thread\_local counter:35} at \path{Node.h:50}; \path{ReadyQueue::NodeTask::operator<:37} pops the largest sequence number first, approximating reverse creation order, while real topological order is enforced by the dependency counter at \path{Engine.cpp:535}. The per-node interpreter at \path{tpx/src/Engine.cpp:333} executes ten steps---\path{GradModeGuard:339}, \texttt{ExecInfo} capture (\path{Engine.h:30}), missing-grad materialization (\path{Engine.cpp:392}), pre-hooks, \path{CurrentEvalNodeGuard:432}, \texttt{apply}, post-hooks, \path{sum\_to\_shape:298}, dtype cast (\path{Engine.cpp:495}), NaN probe (\path{Engine.cpp:141})---then propagates to parents under \path{GraphTask::mutex\_:53} at \path{Engine.cpp:532}.

The memory/performance trade-off is explicit: every \texttt{Edge} holds \texttt{shared\_ptr<Node>} and every \texttt{InputBuffer} holds \texttt{vector<Tensor>}, so one \texttt{shared\_ptr} per node plus one allocation per distinct input slot. The vendor runtime uses \texttt{intrusive\_ptr} to shave the control block. TensorPlay keeps the standard-library pointer so students can follow ownership with ordinary tooling; the appendix of \path{docs/gap\_analysis.md} \S10.2 notes the cost and leaves it as a teaching decision.

\subsubsection{Version guard: \texttt{SavedVariable} (\path{tpx/include/SavedVariable.h:15}, \path{tpx/src/SavedVariable.cpp:8})}

Forward tensors needed by backward are not stored bare. \path{SavedVariable::save:8} copies \path{tensor.unsafeGetTensorImpl()->version():15} into \path{saved\_version\_:40}; \texttt{unpack:18} reloads \path{data\_.unsafeGetTensorImpl()->version():20} and throws

\begin{lstlisting}[caption={\path{SavedVariable.cpp:22} --- version mismatch is loud.}, label=lst:savedvar]

  "one of the variables needed for gradient computation has been modified "
  "by an inplace operation: [saved version: " + to_string(saved_version_) +
  "; current version: " + to_string(current) + "]");
\end{lstlisting}

The message spells both versions, matching the vendor diagnostic. \texttt{VariableVersion} at \path{p10/include/VariableVersion.h:13} is an \path{atomic<uint32\_t> version\_:13} bumped by \texttt{bump():44} on every in-place op after codegen at \path{tools/codegen/gen\_api.py:456} (\texttt{bump\_version()} guarded by \path{!InferenceMode::is\_enabled()}), and shared eagerly between a base and its views via \path{share\_version\_counter:289} so that mutating a view bumps the base's counter as well. Generated nodes at \path{gen\_autograd.py:785} store each \texttt{Tensor} member as \texttt{SavedVariable} and emit \texttt{\{m\}\_.unpack()} at the top of \texttt{apply}; handwritten nodes in \path{ManualNodes.h:1200} do the same. \path{Node::release\_variables:105} clears \path{SavedVariable::reset\_data:31} when \path{GraphTask::keep\_graph\_==false}.

\subsubsection{Shape and dtype guard: \texttt{sum\_to\_shape} (\path{tpx/src/Engine.cpp:298}) and \texttt{Edge} hints (\path{Edge.h:21})}

Broadcast during forward inflates a scalar grad to the output shape. Before the next edge consumes it the engine reduces it at \path{Engine.cpp:463}:

\begin{lstlisting}[caption={\path{Engine.cpp:298} --- broadcast recovery.}, label=lst:sumtoshape]
static Tensor sum_to_shape(const Tensor& grad, const vector<int64_t>& target){
  if(target.empty()) return ops::sum(grad);                 // scalar ()
  int64_t leading = (int64_t)grad.dim() - (int64_t)target.size();
  if(leading < 0){ /* reshape up when numel matches, else passthrough */ }
  vector<int64_t> reduce; for(int64_t i=0;i<leading;++i) reduce.push_back(i);
  for(int64_t i=leading;i<(int64_t)grad.dim();++i)
    if(target[i-leading]==1 && grad.size(i)!=1) reduce.push_back(i);
  Tensor cur = reduce.empty()? grad : ops::sum(grad,reduce,true);
  if(leading>0) cur = ops::reshape(cur,target); return cur;
}
\end{lstlisting}

The recorded shape comes from \path{Edge::shape\_hint:21} with \texttt{has\_shape\_hint:21} distinguishing \texttt{()} from ``no hint'', and the dtype comes from \path{Edge::grad\_dtype:27}. At \path{Engine.cpp:495} a floating-point grad whose dtype disagrees with the hint is cast back via \path{tpx::to:501} (the autocast case at \path{Edge.h:27}: an \texttt{fp32} grad re-entering a low-precision backward). Both ops run under the per-node \path{GradModeGuard:339} so second-order grads still build a graph when \texttt{create\_graph} is true.

\subsubsection{Device guard: \texttt{DeviceMismatchError} (\path{p10/include/Exception.h:43})}

\texttt{DispatchKeySet} omits \texttt{Autograd} for inference tensors: \texttt{TensorImpl} at \path{p10/include/TensorImpl.h:34} initializes \path{VariableVersion(!InferenceMode::is\_enabled())}, so inference tensors get a disabled counter and never acquire an autograd key. Mismatched devices are not silently copied; they throw a distinct Python type:

\begin{lstlisting}[caption={\path{Exception.h:43} --- distinct exception for device mismatch.}, label=lst:devicemismatch]
class P10_API DeviceMismatchError : public RuntimeError { using RuntimeError::RuntimeError; };
\end{lstlisting}

The throw site at \path{p10/src/Tensor.cpp:96} fires on device disagreement in element-wise and matmul entry points, and at \path{TensorIterator.cpp:409} for reduction iterators. Because \texttt{DeviceMismatchError} derives from \texttt{RuntimeError} it is an \texttt{Exception} with \texttt{SourceLocation} and an optional C++ stack, but Python can catch it separately from other runtime errors. The vendor bridges the same signal via \path{c10::DeviceMismatchError}; TensorPlay keeps a parallel hierarchy so \path{except DeviceMismatchError} works without importing the vendor tree.

\subsubsection{Anomaly guard: \texttt{AnomalyMode} (\path{tpx/include/AnomalyMode.h:14}, \path{tpx/src/AnomalyMode.cpp:20})}

\path{AnomalyMode::set\_enabled(true)} at \path{src/bindings/python/Autograd.cpp:475} sets two globals (\path{AnomalyMode.cpp:9}) visible to every thread: \path{\_enabled:24} and \texttt{\_check\_nan:24}. On node creation \path{Node::init\_anomaly\_metadata:132} calls \texttt{store\_stack:39} (C++ frames via \texttt{get\_stacktrace} by default; the Python binding installs \path{traceback.format\_stack} under the GIL at \path{Autograd.cpp:487}) and, if \path{tls\_current\_evaluating\_node:20} is set, \texttt{assign\_parent:42}. During backward \path{evaluate\_function:432} pushes the evaluating node onto \path{tls\_current\_evaluating\_node} via \path{CurrentEvalNodeGuard:57}, so any node created inside that \texttt{apply} records its parent. On exception the engine prints the forward stack chain at \path{AnomalyMode.cpp:46} before rethrowing. The NaN probe at \path{Engine.cpp:139} is

gated on \path{AnomalyMode::should\_check\_nan:17} and run under \path{GradModeGuard(false)} so the probe itself never records history. \path{AnomalyMode::print\_stack:46} walks \path{AnomalyMetadata::parent\_:46} (\texttt{weak\_ptr<Node>}) printing ``Previous calculation was induced by...'' per parent until expiration, so a \texttt{create\_graph} failure shows the forward site that induced the backward node that failed.

\subsection{Overhead When Disabled}

\subsubsection{Profiler: 2 cycles (\path{p10/include/Profiler.h:129}, \path{p10/src/Profiler.cpp:300})}

\path{OpRecord::begin:300} is one \path{memory\_order\_acquire} load of \path{g\_active:129} inlined to a \texttt{mov} + \texttt{cmp} + predicted not-taken branch on x86. Shape and site capture each add one further \texttt{acquire} load, but they sit strictly inside the \texttt{g\_active} true-branch at \path{gen\_api.py:335} and \path{Profiler.cpp:297}, so they add zero cycles when disabled. The binding at \path{src/bindings/python/init.cpp:521} stores \path{g\_gpu\_timing:241} / \path{g\_capture\_shapes:131} / \path{g\_capture\_sites:133} with \texttt{release} before the first op, so a CPU-only session never arms \texttt{GpuTimerPair} (\path{ProfilerGpu.cpp:143} early-return). Measured baseline overhead is $\sim$0.6\,ns at 3.5\,GHz for one load; see \S\ref{sec:profiler} Table~\ref{tab:profoverhead} for the enabled costs (30\,ns CPU, 80--120\,ns with shapes, two \texttt{cudaEventRecord} at $\sim$5\,\textmu s).

\subsubsection{\texttt{GradMode} / \texttt{InferenceMode}: \texttt{thread\_local} (\path{p10/include/GradMode.h:17}, \path{p10/src/GradMode.cpp:5})}

\path{GradMode::enabled\_:17} and \path{InferenceMode::enabled\_:17} are \texttt{thread\_local bool} with definitions at \path{GradMode.cpp:5} (\texttt{=true}) and \path{InferenceMode.cpp:5} (\texttt{=false}). Every generated \texttt{tpx::ops::} wrapper at \path{tools/codegen/gen\_tpx.py:234} computes \texttt{requires\_grad} as \path{GradMode::is\_enabled() \&\& !InferenceMode::is\_enabled() \&\& any\_input\_requires\_grad}, three inlined loads with short-circuit. Worker threads in \path{tpx/src/Engine.cpp:333} honor the task's \texttt{create\_graph} via \path{GradModeGuard:339} that overwrites TLS for the duration of \texttt{evaluate\_function}, so disabled cost is exactly the TLS load the engine would have paid anyway. Inference tensors additionally skip version-counter allocation at \path{TensorImpl.h:34}.

\subsubsection{Dispatcher: 2 branches (\path{p10/include/Dispatcher.h:144}, \path{p10/include/Dispatcher.h:75})}

\path{DispatchStub::call:139} consults the chosen key at \path{Dispatcher.h:144}:

\begin{lstlisting}[caption={\path{Dispatcher.h:144} --- autocast exclusion is one predicted branch.}, label=lst:dispbranch]
if (is_autocast_key(key) && !autocast::is_enabled(key)) [[unlikely]]
  TP_THROW(NotImplementedError, ...);   // Dispatcher.h:144
auto kernel_void = handle.getKernel(key); // Dispatcher.h:148 -> 67
if (!kernel_void) TP_THROW(NotImplementedError, ...);
\end{lstlisting}

\path{OperatorHandle::getKernel:67} does the second branch: one \texttt{acquire} load of the indexed slot plus, only when \path{is\_backend\_key(key)} and the slot is \texttt{nullptr}, one extra \texttt{acquire} load of the \texttt{Composite} slot. For any op with a native kernel the composite load is not taken. Codegen at \path{gen\_api.py:400} hoists \path{static const OperatorHandle} so \texttt{findHandle} is resolved once per process.

On top of hot-path gates, two build-time choices amortize cold cost. \path{CMakeLists.txt:1106} builds \texttt{\_C} with \texttt{UNITY\_BUILD ON} so the 9\,300-line \path{TensorCPythonGenerated.h} plus binding units are compiled as a single translation unit. \texttt{p10} deliberately opts out of unity (kernel TUs must remain separate for \path{TENSORPLAY\_LIBRARY\_IMPL} static registration). The Python extension \texttt{tp\_python} at \path{CMakeLists.txt:390} is a thin shim that re-exports the real symbols, keeping import time dominated by \texttt{dlopen} rather than Python overhead.

The explicit DAG's teaching trade-off is one \texttt{shared\_ptr} per node versus \texttt{intrusive\_ptr}. The vendor tree uses intrusive reference counting to avoid a separate control block per node; TensorPlay keeps the standard control block so ownership is observable in \texttt{gdb} and \texttt{valgrind} without custom pretty-printers. Sustained throughput therefore sees a constant-factor overhead in backward node allocation that is independent of tensor size and invisible on large matmuls where kernel time dominates.

\begin{itemize}[leftmargin=1.2em]
\item \textbf{No third-party keys.} \path{Dispatcher::registerKernel:14} is closed; there is no \texttt{registerDispatchKey} and no per-operator stack of boxed kernels. Extension authors add ops by editing \path{native\_functions.yaml:1} and rebuilding, not by injecting a key at import time. The benefit is that \texttt{findHandle} is one atomic load, not a vector walk.
\item \textbf{No meta dispatch.} The vendor \texttt{Meta} key runs kernels that only compute output shapes and dtypes. TensorPlay never dispatches meta kernels; shape propagation for \texttt{stax} is ordinary Python in \path{tensorplay/\_stax/} with \texttt{ShapeProp} and \path{DCE/ConstFold}. The dispatcher therefore has no \texttt{Meta} slot and no ``meta-tensor'' concept.
\item \textbf{No sparse/quantized axes.} \path{p10/include/SparseState.h:15} stores layout as \texttt{0=COO, 1=CSR} plus \path{crow/col} for CSR, and \path{TensorImpl::SparseState} is a minimal payload, not a dispatch axis. Quantized affine int8 lives in \path{tensorplay/quantization} as a Python FakeQuantize STE, not as a dtype$\times$key dispatch. There is no \texttt{SparseCPU} or \texttt{QuantizedCPU} key.
\item \textbf{Teaching compiler.} Fusion is exactly one pattern---\texttt{mul}$\rightarrow$\texttt{add}---plus pointwise expression programs with CPU vectorization (\path{stax/}). \texttt{Graph::execute} interprets sequentially with lifetime回收; there is no codegen to loops or to CUDA, no buffer reuse planning, and no performance model. The appendix of \path{docs/gap\_analysis.md} \S10.4 notes this as ``concept demonstration, not Inductor.''
\item \textbf{Composite fallbacks.} The trimmed axes are not cliffs: 24+ composite registrations at \path{p10/src/backend/composite/} (view/copy, histogram, unique, itertools, integration, tensor properties) serve as the neutral kernel when a backend slot is empty. Adding a native kernel is one YAML edit; the verification in \S\ref{subsec:eval-verify} shows how to confirm the fallback was replaced.
\end{itemize}
