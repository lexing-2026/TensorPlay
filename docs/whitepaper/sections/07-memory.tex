\section{Memory: DataPtr, Storage, TensorImpl, and Tensor}
\label{sec:memory}

Memory in TensorPlay is a strict three-layer stack: raw allocation (\texttt{DataPtr} plus per-device \texttt{Allocator}), byte container (\texttt{StorageImpl} / \texttt{Storage}), and typed view with shape and dispatch state (\texttt{TensorImpl} / \texttt{Tensor}). Each layer is physically isolated, cited below at \texttt{path:line}, and designed so that the cheapest operation---a view---touches no allocator at all. This section documents the mechanism field by field, constructor by constructor, with line-precise evidence.

\subsection{DataPtr: Move-Only Handle with Erased Deleter and Device}
\label{sec:dataptr}

 defines \texttt{DataPtr} as a move-only handle over four words:

\begin{lstlisting}[caption={move-only handle, 4 words.}, label=lst:dataptrfull]
class DataPtr {
 private:
  void* data_;          // typed data pointer returned to callers
  void* ctx_;           // context passed to deleter (not necessarily data_)
  DeleterFnPtr deleter_; // void(*)(void*)  --- capture-less, trivially copyable
 public:
  Device device_;        // Device{type,index} travels with the allocation
  DataPtr() : data_(nullptr), ctx_(nullptr), deleter_(nullptr),
              device_(DeviceType::Unknown) {}
  DataPtr(void* data, void* ctx, DeleterFnPtr ctx_deleter, Device device)
      : data_(data), ctx_(ctx), deleter_(ctx_deleter), device_(device) {}
  DataPtr(void* data, DeleterFnPtr deleter, Device device)  // ctx == data
      : data_(data), ctx_(data), deleter_(deleter), device_(device) {}
  DataPtr(DataPtr&& other) noexcept : DataPtr() { swap(other); }
  DataPtr& operator=(DataPtr&& other) noexcept { if(this!=&other){clear(); swap(other);} return *this; }
  DataPtr(const DataPtr&) = delete;             // no copy
  DataPtr& operator=(const DataPtr&) = delete;
  ~DataPtr(){ clear(); }
  void clear(){ if(deleter_) deleter_(ctx_); data_=ctx_=nullptr; deleter_=nullptr; }
  void swap(DataPtr& other) noexcept;           // swaps 4 words
  void* get(){ check_device(); return data_; }
  const void* get() const { check_device(); return data_; }
  void* get_context() const { return ctx_; }
  DeleterFnPtr get_deleter() const { return deleter_; }
  void* release(){ void* p=data_; data_=ctx_=nullptr; deleter_=nullptr; return p; }
  operator bool() const { return data_!=nullptr; }
};
\end{lstlisting}

Design points, each verifiable in:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{Erased deleter via \texttt{ctx}.} The alias \texttt{DeleterFnPtr = void(*)(void*)} is a plain function pointer, not \texttt{std::function}. Stateful cleanup is encoded by passing a separate \texttt{ctx\_} to \texttt{deleter\_(ctx\_)}---a context-carrying signature that avoids allocation and capture. The alternative constructor \texttt{DataPtr(void*,DeleterFnPtr,Device)} sets \texttt{ctx\_==data\_} for stateless cases such as \texttt{deleteCPP}.
\item \textbf{Device travels with the allocation.} The public field \texttt{Device device\_} is initialized to \texttt{Unknown} for the null state and is swapped in alongside the pointers. Every \texttt{get} enforces a debug check in when \texttt{NDEBUG} is absent, warning on \texttt{Unknown} access. Higher layers (\texttt{StorageImpl}, \texttt{TensorImpl}) read \texttt{data\_ptr.device\_} to decide copy paths rather than caching a second copy of the type.
\item \textbf{Move-only, not copyable.} Both copy operations are \texttt{=delete}, and both move operations swap through a null default. Table~\ref{tab:dataptr} summarizes the deleter choices offered in the header.
\end{itemize}

The size implication is immediate: \texttt{sizeof(DataPtr)} is four pointers (three \texttt{void*}/function pointer plus \texttt{Device} with padding), trivially relocatable by \texttt{swap} and safe to return by value from \texttt{Allocator::allocate}.

\subsubsection{CachingAllocator Internals}

The CPU implementation lives entirely in an anonymous namespace in. Its structure:

\begin{lstlisting}[caption={bucketed caching allocator.}, label=lst:cachingalloc]
class CachingAllocator : public Allocator {
  struct Header { size_t size; };                // raw allocation size incl. header
  static constexpr size_t HEADER_SIZE = 64;      // 64-byte alignment
  mutable std::mutex mutex_;
  mutable std::unordered_map<size_t, std::vector<void*>> free_blocks_; // bucket -> raw ptrs
 public:
  static CachingAllocator* instance(){ static CachingAllocator* inst=new CachingAllocator(); return inst; }
  static void deleter(void* ptr){ // ptr == data pointer (header+64)
    char* raw = static_cast<char*>(ptr) - HEADER_SIZE;
    Header* h = reinterpret_cast<Header*>(raw);
    size_t size = h->size;                       // rounded size, incl. header
    prof::mem_record_free(ptr, int64_t(size-HEADER_SIZE), false, -1, -1);
    instance()->free(raw, size);
  }
  void free(void* ptr, size_t size){ std::lock_guard<std::mutex> l(mutex_); free_blocks_[size].push_back(ptr); }
  DataPtr allocate(size_t nbytes) const override {
    size_t total_size = nbytes + HEADER_SIZE;    // data starts at raw+64
    total_size = (total_size + 63) & ~size_t(63); // bucket to 64 bytes
    void* ptr=nullptr;
    { std::lock_guard<std::mutex> l(mutex_);
      auto it=free_blocks_.find(total_size);
      if(it!=free_blocks_.end() && !it->second.empty()){ ptr=it->second.back(); it->second.pop_back(); }
    }
    if(!ptr) ptr = alloc_aligned(total_size);    // posix_memalign 64
    if(!ptr) TP_THROW(RuntimeError,"Out of memory");
    reinterpret_cast<Header*>(ptr)->size = total_size;
    void* data_ptr = static_cast<char*>(ptr) + HEADER_SIZE;
    prof::mem_record_alloc(data_ptr, int64_t(total_size-HEADER_SIZE), false, -1, -1);
    return DataPtr(data_ptr, deleter, Device(DeviceType::CPU));
  }
};
\end{lstlisting}

Concrete details:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{64-byte header and alignment.} \texttt{HEADER\_SIZE=64} guarantees that \texttt{data = raw+64} is 64-byte aligned whenever \texttt{raw} is, since 64 divides the alignment. The helper \texttt{alloc\_aligned} uses \texttt{posix\_memalign(\&ptr,64,nbytes)} on POSIX and \texttt{\_aligned\_malloc} on Windows.
\item \textbf{Bucketing.} The total size \texttt{nbytes+64} is rounded up to the next multiple of 64: \texttt{(total\_size+63) \& \~{}63}. Buckets are keyed by this rounded total (\texttt{free\_blocks\_.find(total\_size)} at), reducing fragmentation while keeping the reuse check O(1). The \texttt{Header::size} field stores the rounded size so \texttt{deleter} can return the block to the correct bucket without recomputing.
\item \textbf{Free list.} \texttt{free\_blocks\_: unordered\_map<size\_t, vector<void*>>} is a per-bucket stack; \texttt{free} pushes the raw pointer, \texttt{allocate} pops it when present. The map and vectors are guarded by \texttt{mutex\_} on both paths.
\item \textbf{Deleter path.} \texttt{deleter(void* ptr)} recovers the header via \texttt{ptr-64}, reads \texttt{size}, records the free for the profiler, and re-inserts into the cache rather than calling \texttt{free}. Thus the \texttt{DataPtr} returned by \texttt{allocate} carries \texttt{deleter==CachingAllocator::deleter} and \texttt{ctx==data}, so destruction recycles instead of releasing to the OS.
\item \textbf{Profiler hook.} Both allocation and free call \texttt{free} with the bucket-rounded user size \texttt{total\_size-64}, keeping the capture's alloc/free bytes consistent.
\end{itemize}

\subsubsection{Global Dispatch: \texttt{getCPUAllocator}, \texttt{getAllocator}, \texttt{copyAllocationBytes}}

\texttt{getCPUAllocator} returns \texttt{CachingAllocator::instance}, a leaked singleton so its destructor never races with late \texttt{DataPtr} destruction. \texttt{getAllocator(DeviceType)} switches on the type and throws \texttt{NotImplementedError} for unbuilt backends, with conditional compilation for \texttt{USE\_CUDA} and \texttt{USE\_VULKAN}.

\begin{tpnote}[Note: Why a Leaked Singleton, Not a Static Instance]
\texttt{CachingAllocator::instance} deliberately \emph{leaks}: the singleton is allocated with \texttt{new} and never deleted. A \texttt{static} storage-duration object would have its destructor run at process exit, after which any still-alive \texttt{DataPtr} whose deleter targets the caching allocator would call into a destroyed \texttt{free\_blocks\_} map---undefined behavior in a program that is often shutting down from an interpreter with lingering tensor references. Leaking turns that hazard into a bounded, passive cost (one allocator object plus cached blocks, never returned to the OS) and removes the destructor-ordering problem entirely. The trade-off is explicit: \texttt{valgrind --leak-check=full} will always report the allocator's blocks as ``still reachable,'' never ``lost.''
\end{tpnote}

\texttt{copyAllocationBytes} is the cross-device \texttt{memcpy} used by \texttt{StorageImpl::set\_nbytes}:

\begin{lstlisting}[caption={copy dispatch.}, label=lst:copybytes]
void copyAllocationBytes(void* dst, const Device& dst_dev,
                         const void* src, const Device& src_dev, size_t nbytes){
  if(!dst||!src||nbytes==0) return;
  if(dst_dev.is_cpu() && src_dev.is_cpu()){ std::memcpy(dst,src,nbytes); return; }
#ifdef USE_VULKAN
  if(dst_dev.is_vulkan()||src_dev.is_vulkan()){
    vulkan::copyHostVisibleBytes(const_cast<void*>(dst),dst_dev,
                                 const_cast<void*>(src),src_dev,nbytes); return;
  }
#endif
#ifdef USE_CUDA
  const Device cuda_dev = dst_dev.is_cuda()? dst_dev : src_dev;
  cuda::CUDAGuard guard(cuda_dev);
  auto stream = cuda::getCurrentCUDAStream(int(cuda_dev.index()));
  cudaMemcpyKind kind = cudaMemcpyDefault;
  if(dst_dev.is_cuda() && src_dev.is_cuda()) kind=cudaMemcpyDeviceToDevice;
  else if(dst_dev.is_cuda()) kind=cudaMemcpyHostToDevice;
  else kind=cudaMemcpyDeviceToHost;
  cuda::checkCuda(cudaMemcpyAsync(dst,src,nbytes,kind,stream.stream()),"cudaMemcpyAsync (storage resize)");
  if(dst_dev.is_cuda()) cuda::recordStream(dst,stream);
  if(src_dev.is_cuda()) cuda::recordStream(const_cast<void*>(src),stream);
  if(dst_dev.is_cpu()||src_dev.is_cpu()) stream.synchronize();
  return;
#else
  if(dst_dev.is_cuda()||src_dev.is_cuda()) TP_THROW(RuntimeError,"cannot copy CUDA storage in CPU-only build");
#endif
  TP_THROW(RuntimeError,"cannot copy storage between these devices");
}
\end{lstlisting}

The three branches are concrete: CPU--CPU uses \texttt{std::memcpy}, Vulkan host-visible bytes use a dedicated path, and CUDA uses \texttt{cudaMemcpyAsync} on the current stream with stream recording and a host-visible synchronize when either side is CPU. This is the only place where CPU vs.\ accelerator copies diverge; higher layers call it blindly.

\subsection{StorageImpl: Bytes plus \texttt{resizable}, and \texttt{Storage}: \texttt{shared\_ptr} Wrapper}
\label{sec:storage}

\subsubsection{StorageImpl}

 is the byte container:

\begin{lstlisting}[caption={bytes, allocator, resizable.}, label=lst:storageimplfull]
struct P10_API StorageImpl {
  DataPtr data_ptr;       // owns the allocation, carries Device
  size_t nbytes;          // logical byte extent (may be < bucket size)
  Allocator* allocator;   // non-owning; used for growth
  bool resizable;         // false for wrapped external memory
  StorageImpl(size_t size, Allocator* alloc, bool resizable=true) // :19
      : nbytes(size), allocator(alloc), resizable(resizable) {
    if(allocator) data_ptr = allocator->allocate(nbytes);
  }
  StorageImpl(size_t size, Allocator* alloc, const Device& device, bool resizable=true) // :26
      : nbytes(size), allocator(alloc), resizable(resizable) {
    if(allocator) data_ptr = allocator->allocate(nbytes, device);
  }
  StorageImpl(DataPtr&& ptr, size_t size, Allocator* alloc, bool resizable=false) // :33
      : data_ptr(std::move(ptr)), nbytes(size), allocator(alloc), resizable(resizable) {}
  void* data(){ return data_ptr.get(); }
  const void* data() const { return data_ptr.get(); }
  void set_nbytes(size_t new_nbytes){ // :44
    if(nbytes==new_nbytes) return;
    if(!resizable || !allocator) TP_THROW(RuntimeError,"Storage is not resizable");
    DataPtr new_data = allocator->allocate(new_nbytes, data_ptr.device_); // :50
    size_t copy_size = std::min(nbytes, new_nbytes);                        // :52
    if(data_ptr.get() && new_data.get())
      copyAllocationBytes(new_data.get(), new_data.device_,                 // :54
                          data_ptr.get(), data_ptr.device_, copy_size);
    data_ptr = std::move(new_data); nbytes = new_nbytes;                    // :58
  }
};
\end{lstlisting}

Key semantics:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{Four fields, no shape.} \texttt{data\_ptr}, \texttt{nbytes}, \texttt{allocator*}, \texttt{resizable} are the entire state. Interpretation as \texttt{float32} vs.\ \texttt{int64} is the job of \texttt{TensorImpl::dtype\_}, not storage.
\item \textbf{Three constructors.} Allocate-via-allocator, allocate-on-device, and wrap-existing-\texttt{DataPtr}. The wrapping form defaults to \texttt{resizable=false} because an externally owned deleter cannot be regrown by the allocator. Both allocating constructors guard \texttt{if(allocator)} before calling \texttt{allocator->allocate(nbytes)} / \texttt{allocator->allocate(nbytes,device)}.
\item \textbf{Growth via \texttt{set\_nbytes}.} \texttt{StorageImpl::set\_nbytes} allocates a fresh \texttt{DataPtr} of the new size on the same device, copies \texttt{min(old,new)} bytes via \texttt{copyAllocationBytes}, and swaps. It throws when \texttt{!resizable || !allocator}. The no-op path \texttt{nbytes==new\_nbytes} returns early without allocation.
\end{itemize}

\subsubsection{Storage Handle}

 is a \texttt{shared\_ptr} wrapper:

\begin{lstlisting}[caption={ref-counted handle.}, label=lst:storagehandle]
class P10_API Storage {
 public:
  Storage() = default;
  explicit Storage(size_t nbytes, Allocator* allocator=nullptr){ // :14
    if(!allocator) allocator=getCPUAllocator();
    impl_=std::make_shared<StorageImpl>(nbytes, allocator);
  }
  Storage(size_t nbytes, Allocator* allocator, const Device& device){ // :19
    if(!allocator) allocator=getCPUAllocator();
    impl_=std::make_shared<StorageImpl>(nbytes, allocator, device);
  }
  Storage(DataPtr&& data_ptr, size_t nbytes, Allocator* allocator=nullptr){ // :25
    impl_=std::make_shared<StorageImpl>(std::move(data_ptr), nbytes, allocator, false);
  }
  void* data() const { return impl_? impl_->data() : nullptr; }
  template<typename T> T* data() const { return static_cast<T*>(data()); }
  size_t nbytes() const { return impl_? impl_->nbytes : 0; }
  Device device() const { return impl_? impl_->data_ptr.device_ : Device(DeviceType::CPU); }
  bool defined() const { return impl_!=nullptr; }
  bool is_same(const Storage& other) const { return impl_==other.impl_; } // :47 identity
  bool resizable() const { return impl_ && impl_->resizable; }
  void set_nbytes(size_t nn){ if(!impl_) impl_=std::make_shared<StorageImpl>(nn, getCPUAllocator()); else impl_->set_nbytes(nn); }
  Allocator* allocator() const { return impl_? impl_->allocator : nullptr; }
  long use_count() const { return impl_.use_count(); }
  const std::shared_ptr<StorageImpl>& unsafeGetStorageImpl() const { return impl_; } // :67 backend only
 private:
  std::shared_ptr<StorageImpl> impl_; // :76
};
\end{lstlisting}

Consequences that matter for views and clones:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{View identity is pointer identity.} \texttt{is\_same} compares \texttt{shared\_ptr} addresses, not byte contents. The Python test \texttt{a.untyped\_storage.data\_ptr==b.untyped\_storage.data\_ptr} for \texttt{b=a.view([3,2])} is true exactly because both \texttt{TensorImpl} objects share the same \texttt{Storage::impl\_}.
\item \textbf{Default allocator.} Every \texttt{Storage(size\_t, Allocator*)} constructor falls back to \texttt{getCPUAllocator} when passed null, so callers that omit the allocator still respect the bucket cache.
\item \textbf{Wrap is non-resizable.} \texttt{Storage(DataPtr\&\&,...)} forwards \texttt{resizable=false} to \texttt{StorageImpl}, matching the external-ownership contract of \texttt{DataPtr(DataPtr\&\&)}.
\end{itemize}

Selected accessors illustrate the layering:

\begin{itemize}[leftmargin=1.2em]
\item \texttt{storage} / \texttt{set\_storage} / \texttt{storage\_offset} expose the \texttt{Storage} handle and the element offset. adds \texttt{storage\_offset\_ * itemsize} to the base byte pointer and, on CUDA, calls \texttt{cuda::recordStream(base\_ptr, device\_)} before returning.
\item \texttt{sizes\_and\_strides}, \texttt{sizes}, \texttt{strides}, \texttt{dim}, \texttt{numel} forward to \texttt{SizesAndStrides}. computes the dispatch key on the fly, returning the vmap key alone when batched (see \S\ref{sec:vmap}).
\item \texttt{is\_contiguous}, \texttt{memory\_format}, \texttt{set\_memory\_format}, \texttt{is\_contiguous\_in(format)} maintain the layout tag.
\item \texttt{share\_version\_counter}, \texttt{bump\_version}, \texttt{reset\_version} connect aliasing to mutation tracking.
\end{itemize}

Consequences:

\begin{itemize}[leftmargin=1.2em]
\item Most tensors (rank $\le 5$) never allocate: both sizes and strides live in the two \texttt{[5]} inline arrays. The \texttt{heap\_sizes\_}/\texttt{heap\_strides\_} pair is null in this case, and \texttt{sizes\_data}/\texttt{strides\_data} branch on \texttt{is\_heap}.
\item Copy and move use \texttt{swap} so that a moved-from heap tensor cleanly transfers ownership of its arrays. The copy constructor copies either the inline arrays or the heap allocations depending on \texttt{is\_heap}.
\item Contiguous strides are \texttt{compute\_contiguous\_strides}: row-major with \texttt{strides.back=1} and \texttt{strides[i]=strides[i+1]*max(size[i+1],1)}, so shape \texttt{(2,0)} gets \texttt{(1,1)}. View strides use \texttt{compute\_view\_strides} which splits the old shape into contiguous chunks and requires the new shape to tile the same chunks; incompatible views return \texttt{std::nullopt}. Non-overlapping-dense check is used by \texttt{clone\_impl} to decide whether to preserve strides.
\end{itemize}

\subsection{Copy Constructor: What Is Shared, What Is Not}
\label{sec:copyctor}

      sparse_state_(other.sparse_state_),                    // shared sparse components
      transform_value_(other.transform_value_),              // shared batched wrapper

What is shared: \texttt{storage\_} so a copy is an alias until a write triggers copy-on-write in the caller; \texttt{shared\_state\_} so OneDNN descriptors are reused; \texttt{sparse\_state\_} so COO/CSR component tensors are not duplicated; \texttt{transform\_value\_} and \texttt{quantizer\_} (, \texttt{:92}) so batched and quantized views remain consistent. What is not shared: \texttt{autograd\_meta\_} is not mentioned in the initializer list and is therefore default-initialized to \texttt{nullptr}---copies start fresh without grad history, matching the explicit comment in. The same rule applies to \texttt{copy\_metadata\_from} which preserves the destination's \texttt{autograd\_meta\_} while overwriting storage, sizes, and layout.

\begin{tpinsight}[Insight: Views Share Storage, History Does Not]
The single most load-bearing omission in the codebase is the missing \texttt{autograd\_meta\_} in the \texttt{TensorImpl} copy constructor. Every other member is shared on copy---storage bytes, version counter, sparse components, batched wrappers---because those describe \emph{what the data is}. History is not shared because it describes \emph{how this particular value was produced}: if \texttt{b = a} (a copy, not a view) silently inherited \texttt{a}'s graph, then calling \texttt{b.backward} would flow gradients into \texttt{a}'s parents as if \texttt{a} itself had been consumed---an invisible correctness bug. The distinction is why \texttt{detach} is implemented as a copy-plus-null rather than a new view type: sharing the \texttt{TensorImpl} would share the very thing it must not.
\end{tpinsight}

\subsection{Views Are Zero-Copy: \texttt{as\_strided} is the Single Choke Point}
\label{sec:views}

Every aliasing operation---\texttt{view}, \texttt{transpose}, \texttt{select}, \texttt{slice}, \texttt{permute}, \texttt{view\_dtype}---funnels through \texttt{Tensor::as\_strided} at:

\begin{lstlisting}[caption={\texttt{as\_strided}: reuse storage, share counter.}, label=lst:asstrided]
Tensor Tensor::as_strided(const std::vector<int64_t>& size,
                          const std::vector<int64_t>& stride,
                          std::optional<int64_t> storage_offset) const {
  if(!impl_) TP_THROW(RuntimeError, "Tensor not defined");
  if(size.size()!=stride.size()) TP_THROW(ValueError,"as_strided(): sizes and strides must have same length");
  for(int64_t v: size) if(v<0) TP_THROW(ValueError,"as_strided(): sizes must be non-negative");
  const int64_t offset = storage_offset.value_or(static_cast<int64_t>(impl_->storage_offset())); // :658 keep base offset when absent
  if(offset<0) TP_THROW(ValueError,"as_strided(): storage_offset must be non-negative");
  if(impl_->device().is_vulkan()){ // :666 Vulkan has no stride addressing -> materialize via kernel
    static const OperatorHandle handle = Dispatcher::singleton().findHandle("as_strided");
    return DispatchStub<Tensor,const Tensor&,const std::vector<int64_t>&,const std::vector<int64_t>&,std::optional<int64_t>>::call(handle, DispatchKey::Vulkan, *this, size, stride, std::optional<int64_t>(offset));
  }
  Tensor out = Tensor(impl_->storage(), size, stride, impl_->dtype(), static_cast<size_t>(offset)); // :675 reuse same Storage
  out.unsafeGetTensorImpl()->share_version_counter(*impl_); // :677 alias counter
  if(impl_->has_quantizer()) out.unsafeGetTensorImpl()->set_quantizer(impl_->quantizer()); // :680 quantizer rides along
  return out;
}
\end{lstlisting}

The three post-construction steps are the view contract: reuse the base's \texttt{Storage}, alias the base's \texttt{VersionCounter}, and, if present, carry the \texttt{Quantizer} so the view stays a quantized tensor over the same codes. The \texttt{TensorImpl(Storage,...)} constructor used here sets \texttt{is\_contiguous\_} from the provided strides via \texttt{SizesAndStrides::is\_contiguous}, so \texttt{is\_contiguous} remains correct even for aliased tensors.

Callers illustrate how thin the wrappers are:

\begin{itemize}[leftmargin=1.2em]
\item \texttt{view} infers \texttt{-1} dims via \texttt{SizesAndStrides::infer\_size}, computes compatible strides via \texttt{compute\_view\_strides}, then calls \texttt{as\_strided(inferred,*stride)}.
\item \texttt{select} drops one dimension, computes \texttt{new\_offset = storage\_offset + index*stride[dim]}, erases that dim from \texttt{new\_strides}, and calls \texttt{as\_strided}.
\item \texttt{slice} clamps \texttt{step}, computes \texttt{step}, scales the sliced stride by \texttt{step}, advances the offset by \texttt{start*stride[dim]}, and calls \texttt{as\_strided}.
\item \texttt{view\_dtype} keeps storage and strides when element sizes match; when they differ it rescales \texttt{new\_sizes.back}, the leading strides, and the element offset by the ratio \texttt{dst\_esize}.
\end{itemize}

No allocation occurs in any of these paths. The Vulkan early-out is the only branch that materializes: because the Vulkan payload has no strided addressing, the view is lowered to a kernel rather than aliasing storage.

\subsection{Clone and Contiguous: Allocating a Fresh Storage and Resetting the Version}
\label{sec:clone}

 (\texttt{detail::clone\_impl}) is the allocating counterpart to \texttt{as\_strided}:

\begin{lstlisting}[caption={\texttt{clone\_impl}: fresh storage, reset version.}, label=lst:cloneimpl]
Tensor detail::clone_impl(const Tensor& self, std::optional<MemoryFormat> memory_format){
  if(!self.defined()) return Tensor();
  if(self.is_sparse()){ // :891 sparse clones component-wise
    if(memory_format.has_value()) TP_THROW(RuntimeError,"unsupported memory format option ",toString(*memory_format));
    return Tensor::make_sparse_coo_tensor(self._indices().clone(), self._values().clone(),
                                          static_cast<std::vector<int64_t>>(self.shape()), self.is_coalesced());
  }
  const auto format = memory_format.value_or(MemoryFormat::Preserve); // :900
  const auto sizes_v = static_cast<std::vector<int64_t>>(self.shape());
  std::vector<int64_t> strides; MemoryFormat result_format = Contiguous; // :902
  if(format==Preserve){ // :904 preserve non-overlapping dense layout (e.g. transpose)
    const auto strides_v = static_cast<std::vector<int64_t>>(self.strides());
    if(SizesAndStrides::is_non_overlapping_and_dense(sizes_v, strides_v)) strides=strides_v;
    else strides=SizesAndStrides::compute_contiguous_strides(sizes_v);
  } else if(format==ChannelsLast){ strides=get_channels_last_strides(sizes_v); result_format=ChannelsLast; }
  else if(format==ChannelsLast3d){ strides=get_channels_last_strides(sizes_v); result_format=ChannelsLast3d; }
  else strides=SizesAndStrides::compute_contiguous_strides(sizes_v);
  Storage storage(static_cast<size_t>(self.numel())*self.itemsize(), getAllocator(self.device().type()), self.device()); // :924 fresh bytes
  auto out_impl = std::make_shared<TensorImpl>(storage, sizes_v, strides, self.dtype(), 0); // :926
  if(format==Preserve && strides==get_channels_last_strides(sizes_v) && strides!=SizesAndStrides::compute_contiguous_strides(sizes_v))
    result_format = sizes_v.size()==5? ChannelsLast3d : ChannelsLast; // :930 tag channels-last when preserved
  out_impl->set_memory_format(result_format);
  if(self.unsafeGetTensorImpl()->has_quantizer()) out_impl->set_quantizer(self.unsafeGetTensorImpl()->quantizer()); // :939
  Tensor t(std::move(out_impl));
  const auto rm_strides = SizesAndStrides::compute_contiguous_strides(sizes_v);
  const bool row_major = strides==rm_strides && static_cast<std::vector<int64_t>>(self.strides())==rm_strides; // :950
  if(self.device().is_cpu() && row_major) std::memcpy(t.data_ptr(), self.data_ptr(), size_t(self.numel())*self.itemsize()); // :953 fast path
  else t.copy_(self); // :957 layout-aware copy (handles channels-last etc.)
  t.unsafeGetTensorImpl()->reset_version(); // :961 clone starts unmutated (undo copy_ bump)
  return t;
}
\end{lstlisting}

Key decisions:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{Preserve vs.\ explicit format.} With no/Preserve format the result keeps the input's exact strides when they are non-overlapping and dense (\texttt{SizesAndStrides::is\_non\_overlapping\_and\_dense} at)---so a transposed tensor clones into a transposed tensor---and falls back to row-major otherwise (expanded/overlapping inputs). Explicit \texttt{ChannelsLast}/\texttt{ChannelsLast3d} require rank 4 or 5 and use \texttt{get\_channels\_last\_strides}.
\item \textbf{Fresh allocation.} \texttt{Storage(size\_t(self.numel)*itemsize, getAllocator(self.device.type), self.device)} allocates exactly the dense byte extent; sparse clones instead build a new sparse tensor from cloned components.
\item \textbf{Byte copy with fast path.} When both source and destination are row-major CPU tensors the clone uses \texttt{std::memcpy}; otherwise it uses \texttt{copy\_}, which respects channels-last strides and cross-device copies. \texttt{contiguous\_clone} is the unconditional variant that forces \texttt{MemoryFormat::Contiguous}, used internally by kernels that require flat pointer arithmetic.
\item \textbf{Version reset.} The internal \texttt{copy\_} bumps the destination's counter; the clone is a fresh value and must start at zero, so \texttt{reset\_version} clears it. The source's counter is untouched.
\end{itemize}

\texttt{contiguous\_impl} shares the same structure: it returns \texttt{self} unchanged when already contiguous in the requested format, otherwise materializes a new contiguous tensor the canonical strides \texttt{get\_strides\_for(sizes,format)}, copies, and resets the version.

\subsection{MemoryFormat: Contiguous, ChannelsLast, ChannelsLast3d, and Contiguity Tests}
\label{sec:memoryformat}

 is the layout enum:

\begin{lstlisting}[caption={four tags, one sentinel.}, label=lst:memformat]
enum class MemoryFormat : int8_t { Contiguous=0, Preserve=1, ChannelsLast=2, ChannelsLast3d=3 };
// get_channels_last_strides: for [N,C,H,W] -> [C*H*W, 1, C*W, C]    // :26
//                   for [N,C,D,H,W] -> [C*D*H*W, 1, C*H*W, C*W, C]
inline std::vector<int64_t> get_channels_last_strides(const std::vector<int64_t>& sizes){ // :26
  const int64_t ndim=sizes.size(); std::vector<int64_t> strides(ndim);
  if(ndim<3){ int64_t prod=1; for(int64_t i=ndim-1;i>=0;--i){ strides[i]=prod; prod*=sizes[i]; } return strides; }
  strides[1]=1; strides[ndim-1]=sizes[1]; // :38 channel dim has stride 1
  for(int64_t i=ndim-2;i>=2;--i) strides[i]=strides[i+1]*sizes[i+1]; // :39 spatial dims
  strides[0]=strides[2]*sizes[2]; return strides; // :42 batch stride
}
inline std::vector<int64_t> get_strides_for(const std::vector<int64_t>& sizes, MemoryFormat f){ // :49
  switch(f){ case Contiguous: /* row-major */ case ChannelsLast: case ChannelsLast3d: return get_channels_last_strides(sizes); default: return {}; }
}
\end{lstlisting}

\texttt{Preserve} is a request-level sentinel that is never stored on a live \texttt{TensorImpl}---\texttt{memory\_format} maps it to \texttt{Contiguous}, and \texttt{set\_memory\_format(Preserve)} canonicalizes it to \texttt{Contiguous} before storing. Storage of a blocking format is the job of oneDNN, not the stride tag: the tag simply records which canonical stride set the tensor claims.

\texttt{TensorImpl::is\_contiguous\_in} is the predicate that matters for layout-sensitive kernels:

\begin{lstlisting}[caption={contiguity-in-format via exact stride compare.}, label=lst:iscontigin]
bool is_contiguous_in(MemoryFormat format) const {
  const auto sz = sizes_and_strides_.sizes().vec();
  const auto st = sizes_and_strides_.strides().vec();
  switch(format){
    case MemoryFormat::Preserve: return is_contiguous_;
    case MemoryFormat::ChannelsLast:
    case MemoryFormat::ChannelsLast3d: return st == get_channels_last_strides(sz);
    default: return is_contiguous_;
  }
}
\end{lstlisting}

Rank rules are enforced one level up in \texttt{Tensor::is\_contiguous(MemoryFormat)}: plain contiguous is always meaningful, \texttt{ChannelsLast} is only meaningful at rank~4 and \texttt{ChannelsLast3d} at rank~5, and \texttt{Preserve} returns true (it imposes no layout constraint). The mutating path is \texttt{TensorImpl::set\_sizes\_and\_strides}, which recomputes \texttt{is\_contiguous\_} from \texttt{compute\_contiguous\_strides} and promotes \texttt{memory\_format\_} to \texttt{ChannelsLast}/\texttt{ChannelsLast3d} when the provided strides exactly match \texttt{get\_channels\_last\_strides}.

\subsection{Autograd, Sparse, Vmap, and Quant Extensions on TensorImpl}
\label{sec:extensions}

The four trailing groups in Table~\ref{tab:tensorimplfields} are extension points that justify the flat struct rather than a deep hierarchy:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{Autograd}. \texttt{autograd\_meta\_:shared\_ptr<AutogradMetaBase>} is the per-tensor grad hook; \texttt{set\_autograd\_meta}/\texttt{autograd\_meta}/\texttt{has\_autograd\_meta} expose it, and \texttt{set\_requires\_grad} rejects inference tensors. Critically, every copy operation drops it (see \S\ref{sec:copyctor}), so copies start without history and only \texttt{autograd::make\_variable} re-attaches it.
\item \textbf{View flag}. \texttt{is\_view\_} marks that the tensor was created by a view op; \texttt{detach\_} consults it to reject mutation of a view. Views created by \texttt{as\_strided} do not set this flag in the base layer---it is set by higher-level view plumbing when a public view is materialized---so the aliasing itself stays in \texttt{as\_strided} while the identity bit is managed separately.
\item \textbf{OneDNN shared state}. Two opaque \texttt{shared\_ptr<void>} hold a oneDNN memory descriptor and a reordered memory cache; \texttt{has\_onednn\_md} / \texttt{has\_onednn\_memory\_cache} gate their use. Sharing is shallow (pointer copy) so copies of a dense tensor reuse the same descriptor.
\item \textbf{Sparse}. \texttt{SparseState} stores \texttt{layout} (\texttt{0=COO, 1=CSR}), \texttt{values} for COO and \texttt{values} for CSR, plus \texttt{sparse\_sizes} (logical sizes) and \texttt{coalesced}. Dense storage is cleared when sparse state is installed, so sparse tensors carry no dense blob for their logical shape. Sparse construction in allocates only logical metadata, avoiding a transient dense allocation for large embeddings.
\item \textbf{Vmap wrapper}. \texttt{transform\_value\_} is the physical tensor (with the batch dim), while \texttt{sizes\_and\_strides\_} is the logical shape (without it); \texttt{transform\_batch\_dim\_}/\texttt{transform\_level\_} record where the batch sits and which nesting level owns the wrapper. \texttt{is\_batched} is exactly \texttt{transform\_value\_!=nullptr}.
\item \textbf{Quantizer}. \texttt{quantizer\_:shared\_ptr<Quantizer>} is an immutable, shared affine mapping (per-tensor or per-channel scale/zero-point, see). Views and clones both propagate it: views via \texttt{as\_strided}, clones via \texttt{clone\_impl}, staying quantized over the same codes.
\end{itemize}

\subsection{Putting It Together: Allocation, View, and Clone Walkthrough}
\label{sec:walktogether}

Consider \texttt{a = tensorplay.ones([2,3])} followed by \texttt{b = a.view([3,2])} and \texttt{c = a.clone} on CPU:

\begin{enumerate}[leftmargin=1.2em]
\item \texttt{Tensor(\{2,3\}, Float32)} builds a \texttt{TensorImpl(\{2,3\}, Float32, CPU)} which allocates \texttt{Storage(2*3*4, getAllocator(CPU), CPU)} $\rightarrow$ \texttt{StorageImpl(24, CachingAllocator::instance)} $\rightarrow$ \texttt{CachingAllocator::allocate(24)} rounding to \texttt{(24+64)$\uparrow$64 = 128} total bytes, returning \texttt{DataPtr(ptr+64, deleter, CPU)}. \texttt{SizesAndStrides(\{2,3\})} sets \texttt{inline\_sizes=[2,3]} and \texttt{inline\_strides=[3,1]} via \texttt{compute\_contiguous\_strides}.
\item \texttt{b = a.view([3,2])} infers \texttt{[3,2]}, computes \texttt{compute\_view\_strides([2,3],[3,1],[3,2]) = [2,1]}, and calls \texttt{as\_strided([3,2],[2,1])} which constructs \texttt{Tensor(a.storage, [3,2], [2,1], Float32, offset=0)} reusing the same \texttt{Storage} handle and aliasing the counter. No allocator call occurs; \texttt{a.storage.is\_same(b.storage)} is true and \texttt{b.data\_ptr==a.data\_ptr + 0*itemsize} holds.
\item \texttt{c = a.clone} ( with \texttt{Preserve}) finds strides \texttt{[3,1]} non-overlapping dense, allocates a fresh \texttt{Storage(24, CachingAllocator::instance)} on the same device, builds a new \texttt{TensorImpl} at strides \texttt{[3,1]}, and copies 24 bytes via \texttt{memcpy} because both sides are row-major. The destination version is reset to zero while \texttt{a}'s counter is unchanged.
\end{enumerate}

A channels-last example at rank~4 exercises a different stride path: \texttt{x = tensorplay.randn([2,3,4,4])} with \texttt{x.contiguous(MemoryFormat.ChannelsLast)} reaches \texttt{contiguous\_impl} which allocates at \texttt{get\_channels\_last\_strides([2,3,4,4])=[48,1,12,3]} and copies through \texttt{copy\_}, preserving the tag via \texttt{set\_memory\_format(ChannelsLast)} so \texttt{x.is\_contiguous(ChannelsLast)} becomes true and \texttt{is\_contiguous} is false.

\subsection{Design Trade-offs}
\label{sec:mem:tradeoffs}

\textbf{Three layers vs.\ one fat buffer object.} Collapsing \texttt{DataPtr}/\texttt{Storage}/\texttt{TensorImpl} into a single object would remove two indirections per tensor access. Rejected: the three layers exist because they have different ownership semantics---\texttt{DataPtr} is move-only (unique OS responsibility), \texttt{Storage} is ref-counted bytes (aliasing unit), \texttt{TensorImpl} is metadata (identity unit). Views alias the storage layer ( pointer identity), which requires storage to be a separately shareable object. One fat object forces deep copies on every view.

\textbf{Bucketed cache vs.\ \texttt{malloc} direct.} Plain \texttt{malloc}/\texttt{free} per allocation would delete entirely. Rejected on the standard caching-allocator grounds: tensor workloads free and immediately reallocate the same rounded sizes, so the bucket stack at turns most frees into O(1) pushes and most allocations into O(1) pops, while \texttt{posix\_memalign} round-trips cost $\sim$100\,ns plus page faults on reuse. The 64-byte header and bucket rounding waste at most 63 bytes per allocation, bounded and deterministic.

\textbf{Inline \texttt{SizesAndStrides} for rank $\le$ 5 vs.\ always-heap.} Always-heap sizes would simplify the struct to one pointer. Rejected: rank $\le$ 5 covers virtually every real model tensor; the inline array at keeps sizes/strides in the same cache line as the rest of \texttt{TensorImpl} metadata, saving a pointer chase on every shape check in dispatch. The promotion path to heap for rank $>5$ is a single branch, not a separate type.
