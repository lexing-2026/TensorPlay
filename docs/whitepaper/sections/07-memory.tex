\section{Memory: DataPtr, Storage, TensorImpl, and Tensor}
\label{sec:memory}

Memory in TensorPlay is a strict three-layer stack: raw allocation (\texttt{DataPtr} plus per-device \texttt{Allocator}), byte container (\texttt{StorageImpl} / \texttt{Storage}), and typed view with shape and dispatch state (\texttt{TensorImpl} / \texttt{Tensor}). Each layer is physically isolated, cited below at \texttt{path:line}, and designed so that the cheapest operation---a view---touches no allocator at all. This section documents the mechanism field by field, constructor by constructor, with line-precise evidence.

\subsection{DataPtr: Move-Only Handle with Erased Deleter and Device}
\label{sec:dataptr}

\path{p10/include/DataPtr.h:29} defines \texttt{DataPtr} as a move-only handle over four words:

\begin{lstlisting}[caption={\path{DataPtr.h:29} --- move-only handle, 4 words.}, label=lst:dataptrfull]
class DataPtr {
 private:
  void* data_;          // typed data pointer returned to callers
  void* ctx_;           // context passed to deleter (not necessarily data_)
  DeleterFnPtr deleter_; // void(*)(void*)  --- capture-less, trivially copyable
 public:
  Device device_;        // Device{type,index} travels with the allocation
  DataPtr() : data_(nullptr), ctx_(nullptr), deleter_(nullptr),
              device_(DeviceType::Unknown) {}
  DataPtr(void* data, void* ctx, DeleterFnPtr ctx_deleter, Device device)
      : data_(data), ctx_(ctx), deleter_(ctx_deleter), device_(device) {}
  DataPtr(void* data, DeleterFnPtr deleter, Device device)  // ctx == data
      : data_(data), ctx_(data), deleter_(deleter), device_(device) {}
  DataPtr(DataPtr&& other) noexcept : DataPtr() { swap(other); }
  DataPtr& operator=(DataPtr&& other) noexcept { if(this!=&other){clear(); swap(other);} return *this; }
  DataPtr(const DataPtr&) = delete;             // no copy
  DataPtr& operator=(const DataPtr&) = delete;
  ~DataPtr(){ clear(); }
  void clear(){ if(deleter_) deleter_(ctx_); data_=ctx_=nullptr; deleter_=nullptr; }
  void swap(DataPtr& other) noexcept;           // swaps 4 words
  void* get(){ check_device(); return data_; }
  const void* get() const { check_device(); return data_; }
  void* get_context() const { return ctx_; }
  DeleterFnPtr get_deleter() const { return deleter_; }
  void* release(){ void* p=data_; data_=ctx_=nullptr; deleter_=nullptr; return p; }
  operator bool() const { return data_!=nullptr; }
};
\end{lstlisting}

Design points, each verifiable in \path{DataPtr.h:9--136}:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{Erased deleter via \texttt{ctx}.} The alias \path{DeleterFnPtr = void(*)(void*)} (\path{DataPtr.h:13}) is a plain function pointer, not \texttt{std::function}. Stateful cleanup is encoded by passing a separate \texttt{ctx\_} to \texttt{deleter\_(ctx\_)} in \path{clear():68}, mirroring the context-carrying design of the upstream framework without capturing. The alternative constructor \path{DataPtr(void*,DeleterFnPtr,Device)} (\path{DataPtr.h:43}) sets \texttt{ctx\_==data\_} for stateless cases such as \texttt{deleteCPP}.
\item \textbf{Device travels with the allocation.} The public field \texttt{Device device\_} (\path{DataPtr.h:125}) is initialized to \texttt{Unknown} for the null state and is swapped in \path{swap():77--82} alongside the pointers. Every \texttt{get():85} enforces a debug check in \path{check\_device():128} when \texttt{NDEBUG} is absent, warning on \texttt{Unknown} access. Higher layers (\texttt{StorageImpl}, \texttt{TensorImpl}) read \texttt{data\_ptr.device\_} to decide copy paths rather than caching a second copy of the type.
\item \textbf{Move-only, not copyable.} Both copy operations are \texttt{=delete} (\path{DataPtr.h:61}), and both move operations swap through a null default (\path{DataPtr.h:47}, \path{DataPtr.h:52}). Table~\ref{tab:dataptr} summarizes the deleter choices offered in the header.
\end{itemize}

\subsubsection{CachingAllocator Internals}

The CPU implementation lives entirely in an anonymous namespace in \path{p10/src/Allocator.cpp:26--127}. Its structure:

\begin{lstlisting}[caption={\path{Allocator.cpp:50} --- bucketed caching allocator.}, label=lst:cachingalloc]
class CachingAllocator : public Allocator {
  struct Header { size_t size; };                // raw allocation size incl. header
  static constexpr size_t HEADER_SIZE = 64;      // 64-byte alignment
  mutable std::mutex mutex_;
  mutable std::unordered_map<size_t, std::vector<void*>> free_blocks_; // bucket -> raw ptrs
 public:
  static CachingAllocator* instance(){ static CachingAllocator* inst=new CachingAllocator(); return inst; }
  static void deleter(void* ptr){ // ptr == data pointer (header+64)
    char* raw = static_cast<char*>(ptr) - HEADER_SIZE;
    Header* h = reinterpret_cast<Header*>(raw);
    size_t size = h->size;                       // rounded size, incl. header
    prof::mem_record_free(ptr, int64_t(size-HEADER_SIZE), false, -1, -1);
    instance()->free(raw, size);
  }
  void free(void* ptr, size_t size){ std::lock_guard<std::mutex> l(mutex_); free_blocks_[size].push_back(ptr); }
  DataPtr allocate(size_t nbytes) const override {
    size_t total_size = nbytes + HEADER_SIZE;    // data starts at raw+64
    total_size = (total_size + 63) & ~size_t(63); // bucket to 64 bytes
    void* ptr=nullptr;
    { std::lock_guard<std::mutex> l(mutex_);
      auto it=free_blocks_.find(total_size);
      if(it!=free_blocks_.end() && !it->second.empty()){ ptr=it->second.back(); it->second.pop_back(); }
    }
    if(!ptr) ptr = alloc_aligned(total_size);    // posix_memalign 64
    if(!ptr) TP_THROW(RuntimeError,"Out of memory");
    reinterpret_cast<Header*>(ptr)->size = total_size;
    void* data_ptr = static_cast<char*>(ptr) + HEADER_SIZE;
    prof::mem_record_alloc(data_ptr, int64_t(total_size-HEADER_SIZE), false, -1, -1);
    return DataPtr(data_ptr, deleter, Device(DeviceType::CPU));
  }
};
\end{lstlisting}

Concrete details:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{64-byte header and alignment.} \texttt{HEADER\_SIZE=64} (\path{Allocator.cpp:55}) guarantees that \texttt{data = raw+64} is 64-byte aligned whenever \texttt{raw} is, since 64 divides the alignment. The helper \texttt{alloc\_aligned} (\path{Allocator.cpp:29}) uses \path{posix\_memalign(\&ptr,64,nbytes)} on POSIX and \texttt{\_aligned\_malloc} on Windows (\path{Allocator.cpp:31--38}).
\item \textbf{Bucketing.} The total size \texttt{nbytes+64} is rounded up to the next multiple of 64: \path{(total\_size+63) \& \~{}63} (\path{Allocator.cpp:94}). Buckets are keyed by this rounded total (\path{free\_blocks\_.find(total\_size)} at \path{Allocator.cpp:99}), reducing fragmentation while keeping the reuse check O(1). The \texttt{Header::size} field (\path{Allocator.cpp:53}) stores the rounded size so \texttt{deleter} can return the block to the correct bucket without recomputing.
\item \textbf{Free list.} \path{free\_blocks\_: unordered\_map<size\_t, vector<void*>>} (\path{Allocator.cpp:58}) is a per-bucket stack; \texttt{free} pushes the raw pointer (\path{Allocator.cpp:84}), \texttt{allocate} pops it when present (\path{Allocator.cpp:101}). The map and vectors are guarded by \texttt{mutex\_} (\path{Allocator.cpp:57}) on both paths.
\item \textbf{Deleter path.} \texttt{deleter(void* ptr)} (\path{Allocator.cpp:66}) recovers the header via \texttt{ptr-64} (\path{Allocator.cpp:69}), reads \texttt{size}, records the free for the profiler, and re-inserts into the cache rather than calling \texttt{free}. Thus the \texttt{DataPtr} returned by \texttt{allocate} (\path{Allocator.cpp:125}) carries \path{deleter==CachingAllocator::deleter} and \texttt{ctx==data}, so destruction recycles instead of releasing to the OS.
\item \textbf{Profiler hook.} Both allocation and free call \path{prof::mem\_record\_alloc/free} (\path{Allocator.cpp:77}, \path{Allocator.cpp:121}) with the bucket-rounded user size \texttt{total\_size-64}, keeping the capture's alloc/free bytes consistent.
\end{itemize}

\subsubsection{Global Dispatch: \texttt{getCPUAllocator}, \texttt{getAllocator}, \texttt{copyAllocationBytes}}

\texttt{getCPUAllocator()} (\path{Allocator.cpp:131}) returns \path{CachingAllocator::instance()}, a leaked singleton so its destructor never races with late \texttt{DataPtr} destruction. \path{getAllocator(DeviceType)} (\path{Allocator.cpp:186--202}) switches on the type and throws \texttt{NotImplementedError} for unbuilt backends, with conditional compilation for \texttt{USE\_CUDA} and \texttt{USE\_VULKAN}.

\texttt{copyAllocationBytes} (\path{Allocator.cpp:135--177}) is the cross-device \texttt{memcpy} used by \path{StorageImpl::set\_nbytes}:

\begin{lstlisting}[caption={\path{Allocator.cpp:135} --- copy dispatch.}, label=lst:copybytes]
void copyAllocationBytes(void* dst, const Device& dst_dev,
                         const void* src, const Device& src_dev, size_t nbytes){
  if(!dst||!src||nbytes==0) return;
  if(dst_dev.is_cpu() && src_dev.is_cpu()){ std::memcpy(dst,src,nbytes); return; }
#ifdef USE_VULKAN
  if(dst_dev.is_vulkan()||src_dev.is_vulkan()){
    vulkan::copyHostVisibleBytes(const_cast<void*>(dst),dst_dev,
                                 const_cast<void*>(src),src_dev,nbytes); return;
  }
#endif
#ifdef USE_CUDA
  const Device cuda_dev = dst_dev.is_cuda()? dst_dev : src_dev;
  cuda::CUDAGuard guard(cuda_dev);
  auto stream = cuda::getCurrentCUDAStream(int(cuda_dev.index()));
  cudaMemcpyKind kind = cudaMemcpyDefault;
  if(dst_dev.is_cuda() && src_dev.is_cuda()) kind=cudaMemcpyDeviceToDevice;
  else if(dst_dev.is_cuda()) kind=cudaMemcpyHostToDevice;
  else kind=cudaMemcpyDeviceToHost;
  cuda::checkCuda(cudaMemcpyAsync(dst,src,nbytes,kind,stream.stream()),"cudaMemcpyAsync (storage resize)");
  if(dst_dev.is_cuda()) cuda::recordStream(dst,stream);
  if(src_dev.is_cuda()) cuda::recordStream(const_cast<void*>(src),stream);
  if(dst_dev.is_cpu()||src_dev.is_cpu()) stream.synchronize();
  return;
#else
  if(dst_dev.is_cuda()||src_dev.is_cuda()) TP_THROW(RuntimeError,"cannot copy CUDA storage in CPU-only build");
#endif
  TP_THROW(RuntimeError,"cannot copy storage between these devices");
}
\end{lstlisting}

The three branches are concrete: CPU--CPU uses \texttt{std::memcpy} (\path{Allocator.cpp:140}), Vulkan host-visible bytes use a dedicated path (\path{Allocator.cpp:145}), and CUDA uses \texttt{cudaMemcpyAsync} on the current stream (\path{Allocator.cpp:165}) with stream recording and a host-visible synchronize when either side is CPU (\path{Allocator.cpp:169}). This is the only place where CPU vs.\ accelerator copies diverge; higher layers call it blindly.

\subsection{StorageImpl: Bytes plus \texttt{resizable}, and \texttt{Storage}: \texttt{shared\_ptr} Wrapper}
\label{sec:storage}

\subsubsection{StorageImpl}

\path{p10/include/StorageImpl.h:13} is the byte container:

\begin{lstlisting}[caption={\path{StorageImpl.h:13} --- bytes, allocator, resizable.}, label=lst:storageimplfull]
struct P10_API StorageImpl {
  DataPtr data_ptr;       // owns the allocation, carries Device
  size_t nbytes;          // logical byte extent (may be < bucket size)
  Allocator* allocator;   // non-owning; used for growth
  bool resizable;         // false for wrapped external memory
  StorageImpl(size_t size, Allocator* alloc, bool resizable=true) // :19
      : nbytes(size), allocator(alloc), resizable(resizable) {
    if(allocator) data_ptr = allocator->allocate(nbytes);
  }
  StorageImpl(size_t size, Allocator* alloc, const Device& device, bool resizable=true) // :26
      : nbytes(size), allocator(alloc), resizable(resizable) {
    if(allocator) data_ptr = allocator->allocate(nbytes, device);
  }
  StorageImpl(DataPtr&& ptr, size_t size, Allocator* alloc, bool resizable=false) // :33
      : data_ptr(std::move(ptr)), nbytes(size), allocator(alloc), resizable(resizable) {}
  void* data(){ return data_ptr.get(); }
  const void* data() const { return data_ptr.get(); }
  void set_nbytes(size_t new_nbytes){ // :44
    if(nbytes==new_nbytes) return;
    if(!resizable || !allocator) TP_THROW(RuntimeError,"Storage is not resizable");
    DataPtr new_data = allocator->allocate(new_nbytes, data_ptr.device_); // :50
    size_t copy_size = std::min(nbytes, new_nbytes);                        // :52
    if(data_ptr.get() && new_data.get())
      copyAllocationBytes(new_data.get(), new_data.device_,                 // :54
                          data_ptr.get(), data_ptr.device_, copy_size);
    data_ptr = std::move(new_data); nbytes = new_nbytes;                    // :58
  }
};
\end{lstlisting}

Key semantics:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{Four fields, no shape.} \texttt{data\_ptr} (\path{StorageImpl.h:14}), \texttt{nbytes} (\path{StorageImpl.h:15}), \texttt{allocator*} (\path{StorageImpl.h:16}), \texttt{resizable} (\path{StorageImpl.h:17}) are the entire state. Interpretation as \texttt{float32} vs.\ \texttt{int64} is the job of \texttt{TensorImpl::dtype\_}, not storage.
\item \textbf{Three constructors.} Allocate-via-allocator (\path{StorageImpl.h:19}), allocate-on-device (\path{StorageImpl.h:26}), and wrap-existing-\texttt{DataPtr} (\path{StorageImpl.h:33}). The wrapping form defaults to \texttt{resizable=false} because an externally owned deleter cannot be regrown by the allocator. Both allocating constructors guard \texttt{if(allocator)} before calling \path{allocator->allocate(nbytes)} / \path{allocator->allocate(nbytes,device)}.
\item \textbf{Growth via \texttt{set\_nbytes}.} \path{StorageImpl::set\_nbytes} (\path{StorageImpl.h:44--60}) allocates a fresh \texttt{DataPtr} of the new size on the same device (\path{StorageImpl.h:50}), copies \texttt{min(old,new)} bytes via \texttt{copyAllocationBytes} (\path{StorageImpl.h:54}), and swaps. It throws when \path{!resizable || !allocator} (\path{StorageImpl.h:46}). The no-op path \texttt{nbytes==new\_nbytes} returns early without allocation.
\end{itemize}

Consequences that matter for views and clones:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{View identity is pointer identity.} \texttt{is\_same} (\path{Storage.h:47}) compares \texttt{shared\_ptr} addresses, not byte contents. The Python test \path{a.untyped\_storage().data\_ptr()==b.untyped\_storage().data\_ptr()} for \texttt{b=a.view([3,2])} is true exactly because both \texttt{TensorImpl} objects share the same \texttt{Storage::impl\_}.
\item \textbf{Default allocator.} Every \path{Storage(size\_t, Allocator*)} constructor falls back to \texttt{getCPUAllocator()} when passed null (\path{Storage.h:15}, \path{Storage.h:20}), so callers that omit the allocator still respect the bucket cache.
\item \textbf{Wrap is non-resizable.} \path{Storage(DataPtr\&\&, ...)} (\path{Storage.h:25}) forwards \texttt{resizable=false} to \texttt{StorageImpl}, matching the external-ownership contract of \path{DataPtr(DataPtr\&\&)}.
\end{itemize}

\begin{lstlisting}[caption={\path{Tensor.cpp:645} --- \texttt{as\_strided}: reuse storage, share counter.}, label=lst:asstrided]

                          const std::vector<int64_t>& stride,
                          std::optional<int64_t> storage_offset) const {

\subsection{Clone and Contiguous: Allocating a Fresh Storage and Resetting the Version}
\label{sec:clone}

\begin{lstlisting}[caption={\path{Tensor.cpp:889} --- \texttt{clone\_impl}: fresh storage, reset version.}, label=lst:cloneimpl]

  if(self.is_sparse()){ // :891 sparse clones component-wise

  const bool row_major = strides==rm_strides && static_cast<std::vector<int64_t>>(self.strides())==rm_strides; // :950

\end{lstlisting}

Key decisions:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{Preserve vs.\ explicit format.} With no/Preserve format (\path{Tensor.cpp:904}) the result keeps the input's exact strides when they are non-overlapping and dense (\path{SizesAndStrides::is\_non\_overlapping\_and\_dense} at \path{SizesAndStrides.cpp:304})---so a transposed tensor clones into a transposed tensor---and falls back to row-major otherwise (expanded/overlapping inputs). Explicit \texttt{ChannelsLast}/\texttt{ChannelsLast3d} (\path{Tensor.cpp:911}) require rank 4 or 5 and use \path{get\_channels\_last\_strides} (\path{MemoryFormat.h:26}).
\item \textbf{Fresh allocation.} \path{Storage(size\_t(self.numel())*itemsize(), getAllocator(self.device().type()), self.device())} (\path{Tensor.cpp:924}) allocates exactly the dense byte extent; sparse clones instead build a new sparse tensor from cloned components (\path{Tensor.cpp:896}).
\item \textbf{Byte copy with fast path.} When both source and destination are row-major CPU tensors the clone uses \texttt{std::memcpy} (\path{Tensor.cpp:954}); otherwise it uses \texttt{copy\_}, which respects channels-last strides and cross-device copies. \texttt{contiguous\_clone} (\path{Tensor.cpp:965}) is the unconditional variant that forces \path{MemoryFormat::Contiguous}, used internally by kernels that require flat pointer arithmetic.
\item \textbf{Version reset.} The internal \texttt{copy\_} bumps the destination's counter; the clone is a fresh value and must start at zero, so \texttt{reset\_version()} (\path{Tensor.cpp:961}) clears it. The source's counter is untouched.
\end{itemize}

\texttt{contiguous\_impl} (\path{Tensor.cpp:971}) shares the same structure: it returns \texttt{self} unchanged when already contiguous in the requested format, otherwise materializes a new contiguous tensor at the canonical strides \path{get\_strides\_for(sizes,format)} (\path{MemoryFormat.h:49}), copies, and resets the version.

\subsection{MemoryFormat: Contiguous, ChannelsLast, ChannelsLast3d, and Contiguity Tests}
\label{sec:memoryformat}

\path{p10/include/MemoryFormat.h:14} is the layout enum:

\begin{lstlisting}[caption={\path{MemoryFormat.h:14} --- four tags, one sentinel.}, label=lst:memformat]

// get_channels_last_strides: for [N,C,H,W] -> [C*H*W, 1, C*W, C]    // :26
//                   for [N,C,D,H,W] -> [C*D*H*W, 1, C*H*W, C*W, C]
inline std::vector<int64_t> get_channels_last_strides(const std::vector<int64_t>& sizes){ // :26
  const int64_t ndim=sizes.size(); std::vector<int64_t> strides(ndim);
  if(ndim<3){ int64_t prod=1; for(int64_t i=ndim-1;i>=0;--i){ strides[i]=prod; prod*=sizes[i]; } return strides; }
  strides[1]=1; strides[ndim-1]=sizes[1]; // :38 channel dim has stride 1
  for(int64_t i=ndim-2;i>=2;--i) strides[i]=strides[i+1]*sizes[i+1]; // :39 spatial dims
  strides[0]=strides[2]*sizes[2]; return strides; // :42 batch stride
}
inline std::vector<int64_t> get_strides_for(const std::vector<int64_t>& sizes, MemoryFormat f){ // :49
  switch(f){ case Contiguous: /* row-major */ case ChannelsLast: case ChannelsLast3d: return get_channels_last_strides(sizes); default: return {}; }
}
\end{lstlisting}

\texttt{Preserve} is a request-level sentinel that is never stored on a live \texttt{TensorImpl}---\texttt{memory\_format()} (\path{TensorImpl.h:174}) maps it to \texttt{Contiguous}, and \path{set\_memory\_format(Preserve)} (\path{TensorImpl.h:178}) canonicalizes it to \texttt{Contiguous} before storing. Storage of a blocking format is the job of oneDNN, not the stride tag: the tag simply records which canonical stride set the tensor claims.

\path{TensorImpl::is\_contiguous\_in} (\path{TensorImpl.h:193--205}) is the predicate that matters for layout-sensitive kernels:

\begin{lstlisting}[caption={\path{TensorImpl.h:193} --- contiguity-in-format via exact stride compare.}, label=lst:iscontigin]
bool is_contiguous_in(MemoryFormat format) const {
  const auto sz = sizes_and_strides_.sizes().vec();
  const auto st = sizes_and_strides_.strides().vec();
  switch(format){
    case MemoryFormat::Preserve: return is_contiguous_;
    case MemoryFormat::ChannelsLast:
    case MemoryFormat::ChannelsLast3d: return st == get_channels_last_strides(sz);
    default: return is_contiguous_;
  }
}
\end{lstlisting}

Rank rules are enforced one level up in \path{Tensor::is\_contiguous(MemoryFormat)} (\path{Tensor.cpp:1082}): plain contiguous is always meaningful, \texttt{ChannelsLast} is only meaningful at rank~4 and \texttt{ChannelsLast3d} at rank~5, and \texttt{Preserve} returns true (it imposes no layout constraint). The mutating path is \path{TensorImpl::set\_sizes\_and\_strides} (\path{TensorImpl.h:366}), which recomputes \texttt{is\_contiguous\_} from \path{compute\_contiguous\_strides} and promotes \texttt{memory\_format\_} to \texttt{ChannelsLast}/\texttt{ChannelsLast3d} when the provided strides exactly match \path{get\_channels\_last\_strides}.

\subsection{Autograd, Sparse, Vmap, and Quant Extensions on TensorImpl}
\label{sec:extensions}

The four trailing groups in Table~\ref{tab:tensorimplfields} are extension points that justify the flat struct rather than a deep hierarchy:

\begin{itemize}[leftmargin=1.2em]
\item \textbf{Autograd} (\path{TensorImpl.h:43--45}, \path{TensorImpl.h:343--348}). \path{autograd\_meta\_:shared\_ptr<AutogradMetaBase>} is the per-tensor grad hook; \texttt{set\_autograd\_meta}/\texttt{autograd\_meta()}/\path{has\_autograd\_meta()} expose it, and \texttt{set\_requires\_grad} (\path{TensorImpl.cpp:97}) rejects inference tensors. Critically, every copy operation drops it (see \S\ref{sec:copyctor}), so copies start without history and only \path{autograd::make\_variable} re-attaches it.
\item \textbf{View flag} (\path{TensorImpl.h:49}, \path{TensorImpl.h:188}). \texttt{is\_view\_} marks that the tensor was created by a view op; \texttt{detach\_()} consults it to reject mutation of a view. Views created by \texttt{as\_strided} do not set this flag in the base layer---it is set by higher-level view plumbing when a public view is materialized---so the aliasing itself stays in \texttt{as\_strided} while the identity bit is managed separately.
\item \textbf{OneDNN shared state} (\path{TensorImpl.h:56--60}, \path{TensorImpl.h:321--341}). Two opaque \texttt{shared\_ptr<void>} hold a oneDNN memory descriptor and a reordered memory cache; \texttt{has\_onednn\_md()} / \path{has\_onednn\_memory\_cache()} gate their use. Sharing is shallow (pointer copy) so copies of a dense tensor reuse the same descriptor.
\item \textbf{Sparse} (\path{TensorImpl.h:68--77}, \path{TensorImpl.h:207--262}). \texttt{SparseState} stores \texttt{layout} (\texttt{0=COO, 1=CSR}), \path{indices/values} for COO and \path{crow/col/values} for CSR, plus \texttt{sparse\_sizes} (logical sizes) and \texttt{coalesced}. Dense storage is cleared when sparse state is installed (\path{TensorImpl.h:241}, \path{TensorImpl.h:261}), so sparse tensors carry no dense blob for their logical shape. Sparse construction in \path{Tensor.cpp:88} allocates only logical metadata, avoiding a transient dense allocation for large embeddings.
\item \textbf{Vmap wrapper} (\path{TensorImpl.h:82--84}, \path{TensorImpl.h:151--169}). \texttt{transform\_value\_} is the physical tensor (with the batch dim), while \path{sizes\_and\_strides\_} is the logical shape (without it); \path{transform\_batch\_dim\_}/\texttt{transform\_level\_} record where the batch sits and which nesting level owns the wrapper. \texttt{is\_batched()} is exactly \path{transform\_value\_!=nullptr} (\path{TensorImpl.h:151}).
\item \textbf{Quantizer} (\path{TensorImpl.h:89}, \path{TensorImpl.h:351--353}). \path{quantizer\_:shared\_ptr<Quantizer>} is an immutable, shared affine mapping (per-tensor or per-channel scale/zero-point, see \path{p10/include/Quantizer.h:33--86}). Views and clones both propagate it: views via \texttt{as\_strided} (\path{Tensor.cpp:680}), clones via \texttt{clone\_impl} (\path{Tensor.cpp:939}), staying quantized over the same codes.
\end{itemize}

\subsection{Putting It Together: Allocation, View, and Clone Walkthrough}
\label{sec:walktogether}

Consider \path{a = tensorplay.ones([2,3])} followed by \texttt{b = a.view([3,2])} and \texttt{c = a.clone()} on CPU:

\begin{enumerate}[leftmargin=1.2em]
\item \texttt{Tensor(\{2,3\}, Float32)} (\path{Tensor.h:71}) builds a \path{TensorImpl(\{2,3\}, Float32, CPU)} (\path{TensorImpl.cpp:26}) which allocates \path{Storage(2*3*4, getAllocator(CPU), CPU)} (\path{TensorImpl.cpp:34}) $\rightarrow$ \path{StorageImpl(24, CachingAllocator::instance())} (\path{StorageImpl.h:19}) $\rightarrow$ \path{CachingAllocator::allocate(24)} (\path{Allocator.cpp:87}) rounding to \path{(24+64)$\uparrow$64 = 128} total bytes, returning \path{DataPtr(ptr+64, deleter, CPU)} (\path{Allocator.cpp:125}). \texttt{SizesAndStrides(\{2,3\})} (\path{SizesAndStrides.cpp:8}) sets \texttt{inline\_sizes=[2,3]} and \path{inline\_strides=[3,1]} via \path{compute\_contiguous\_strides}.
\item \texttt{b = a.view([3,2])} (\path{Tensor.cpp:686}) infers \texttt{[3,2]}, computes \path{compute\_view\_strides([2,3],[3,1],[3,2]) = [2,1]}, and calls \path{as\_strided([3,2],[2,1])} (\path{Tensor.cpp:696}) which constructs \path{Tensor(a.storage(), [3,2], [2,1], Float32, offset=0)} reusing the same \texttt{Storage} handle (\path{Tensor.cpp:675}) and aliasing the counter (\path{Tensor.cpp:677}). No allocator call occurs; \path{a.storage().is\_same(b.storage())} is true and \path{b.data\_ptr()==a.data\_ptr() + 0*itemsize} holds.
\item \texttt{c = a.clone()} (\path{Tensor.cpp:889} with \texttt{Preserve}) finds strides \texttt{[3,1]} non-overlapping dense (\path{SizesAndStrides.cpp:304}), allocates a fresh \path{Storage(24, CachingAllocator::instance())} on the same device (\path{Tensor.cpp:924}), builds a new \texttt{TensorImpl} at strides \texttt{[3,1]}, and copies 24 bytes via \texttt{memcpy} (\path{Tensor.cpp:954}) because both sides are row-major. The destination version is reset to zero (\path{Tensor.cpp:961}) while \texttt{a}'s counter is unchanged.
\end{enumerate}

A channels-last example at rank~4 exercises a different stride path: \path{x = tensorplay.randn([2,3,4,4])} with \path{x.contiguous(MemoryFormat.ChannelsLast)} reaches \texttt{contiguous\_impl} (\path{Tensor.cpp:971}) which allocates at \path{get\_channels\_last\_strides([2,3,4,4])=[48,1,12,3]} (\path{MemoryFormat.h:26}) and copies through \texttt{copy\_}, preserving the tag via \path{set\_memory\_format(ChannelsLast)} (\path{TensorImpl.h:178}) so \path{x.is\_contiguous(ChannelsLast)} becomes true and \texttt{is\_contiguous()} is false.
