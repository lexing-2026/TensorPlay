# 亮点 Highlights

- **omni_attention 可编程注意力**：`score_mod` / `mask_mod` 编程接口 + `BlockMask`
  块稀疏编译；CPU 融合 flash 内核（分块 + 线程池）与 CUDA fp32 3xTF32 融合前向/反向
  原生实现，eager 未融合回退与编译降级路径齐备。
- **图编译管线全面收口**：注意力调用自动降级为生成内核；AOT 编译产出 C++ wrapper
  并在运行时构建加载；CuteDSL 后端自研化（移除上游依赖）；单次编译耗时从
  **11.3s 降至 1.3s**。
- **CUDA graphs 编译器后端**：`tensorplay.compile` 新增 `mode="reduce-overhead"`，
  编译产物经 CUDA graphs 回放；GEMM 走 TunableOp 调优上下文，结果持久化。
- **前向模式 AD 原生引擎**：dual-tensor 引擎单趟传播切向，`autograd.functional.jvp`
  默认改走前向模式，`jacfwd` 随之可用。
- **API 面大幅扩展**：新增 `audio`、`vision`、`hub`、`onnx`、`package`、`ao` 量化、
  `masked`、`signal`、`nested`、`monitor`、`func` 控制流算子、`meta` 设备、稀疏分发键等
  一大批公开面。
- **随机数工厂接入 Generator**：`randint`、`poisson`、`multinomial` 与多种就地采样
  把调用方 generator 从 Python 层一路传到内核。
- **CUDA 内核性能批量刷新**：`unique`/一维排序/三角掩码/外层维归约/直方图/嵌入梯度
  等重写，多组负载从落后数十倍收敛到持平或领先。
- **构建与发布增强**：cutlass / flash-attention 收为 git 子模块，wheel 携带 JIT
  运行时头文件，CPU 轮子恢复 PyPI 发布。
- **白皮书新增图编译管线章节**：补上 08b 编译前端、08c stax 降级、08d 原生图运行时
  三章，以 `path:line` 援引具体机制。
- **现代解码栈进入模块面**：`RotaryEmbedding` / `apply_rotary_emb`、`GroupedQueryAttention`、
  `MultiheadLatentAttention`、`GatedDeltaNet` / `KimiDeltaAttention`（含 chunked 与
  recurrent 两套规则）、`CompressedSparseAttention`、`CrossAttention` / `CausalEncoderDecoder`、
  `SwiGLUMLP` / `TransformerBlock`；KV 缓存补齐 `StaticCache` / `SlidingWindowCache` /
  `PagedCache` / `QuantizedCache`，配套 `tensorplay.nn.generation.generate` 自回归循环
  （top-k / top-p 过滤 + 重复惩罚）。
- **高阶梯度大面积补齐**：`config/derivatives.yaml` 新增 **172** 条可微条目（净增 161），
  覆盖卷积 / 池化 / 分数池化 / ROI / 填充 / 上采样 / 嵌入 / FFT / STFT / 线性代数 /
  特殊函数 / 损失 / 激活 / 稀疏 softmax / CTC 的反向再可微；`_segment_reduce`、
  稀疏 `sum` 与稀疏 softmax 的 COO 分支同样可再求导。
- **每个可微算子都有前向模式切向**：原先只声明反向公式的算子补上 `result:` 切向；
  `gradcheck` 新增前向模式、批处理与 fast 模式校验（双引擎 Jacobian 对中心差分，
  批模式经 vmap 校验 Jacobian-向量积与向量-Jacobian 积）。
- **频域与线性代数补全**：原生多维 FFT 原语（`_fft_c2c` / `_fft_r2c` / `_fft_c2r`）与
  Hermitian 族 API，`fft` / `stft` 全部可再求导；`linalg` 的 `qr` / `lstsq`（CUDA 侧
  `gels` 走 QR 驱动，高、瘦、宽三种形态）、`lu_factor` / `cholesky` / `solve` / `pinv`
  及其伴随均已可微。
- **编译器原生下沉成规模**：`op_lowerings.py` 新增约 5.5k 行，norm / softmax / 激活 /
  视图 / 池化 / 上采样 / 散射 / `searchsorted` / `bucketize` / `ldexp` / `unfold` /
  `prelu` 从"库调用"改写为"区域内生成"，新增 `tensorplay._decomp` 分解表（618 条分解，
  每条同时注册函数式与就地两种拼写）供后端沿分解路径下沉。
- **CPU 指令集分层向量化**：AVX2 与 AVX512 双路径并行铺开（广播算术、dot 归约、
  `clamp` / `lerp` / `power`、三角行拆分、标量算术旁路），channels-last 池化 /
  上采样 / grid sampling / bicubic 走 tier-compiled 专用通道。
- **CUDA 归约 / softmax / 排序重写**：非对齐输入头尾分离 + 连续输出 vec4/vec2/标量
  分派、`hash_tensor` XOR 归约、min/max 合并为单趟打包键归约、Welford 分块、空间维
  softmax 与宽行尾部、half→float 前向、大张量中位数走基数排序、超大排序分块、
  `cummax` 网格按设备上限封顶。
- **导出（export）按符号尺寸推导**：捕获期在克隆的样例值上跑一遍每个记录调用，按逐算子
  形状规则经符号输入维度推导**计算值**的维度范围（与样例具体形状交叉校验），规则在符号
  范围上做的决定变成读输入形状的运行时守卫；声明为 dynamic 的维度在捕获期是符号本身，
  读它得到图值而不是被样例尺寸定死。导出从此知道程序内部算出来的形状（两项不兼容变更）。
- **ONNX 导出的动态轴打通**：`dynamic_axes` 进入捕获（成为 `Dim.DYNAMIC` 捕获规格），
  `dynamic_shapes` 按可调用对象签名映射回 ONNX 输入；计算值上的 `.shape` / `.size()` /
  `.dim()` / `.numel()` / `.ndim` / `.T` / `.dtype` 读取降到 `Shape` / `Gather` 运行时
  读数，`b, n, c = x.shape` 这类解包不再把样例 batch 烤进图里。
- **`tensorplay._assert`**：把 Python `assert` 作为可调用算子暴露（随包的 `vit_b_16` /
  `maxvit` 一直在调它）。符号跟踪会记录它，编译捕获把张量值上的断言转成程序实际执行的
  `_assert_async.msg` 检查，导出按"尺寸断言"与"数值检查"分别处理；检查类算子登记为
  side-effectful，死代码消除不再把它们删掉（此前编译后的 `_assert_async` 从不执行）。
- **profile 表格补齐捕获列**：`profile.table()` 逐 span 渲染，`record_shapes`、
  `with_stack`、输出显存、输入形状、FLOPs、源码位置等此前采集后即丢弃的列都能出表；
  `header` / `time_unit` / `top_level_events_only` 生效，嵌套 span 的设备时间与显存不再
  汇总成 0。

# 不兼容变更 Backwards Incompatible Changes

## 注意力

### 注意力入口统一为 `omni_attention`

注意力编程入口的公开命名全部收口为 `omni_attention`：模块路径、配置项与钩子统一到该
命名；上下文并行集合算子注册为 `cplib::omni_cp_allgather` /
`cplib::omni_cp_allgather_backward`，命名旧注册名的已存图需重新编译。

```python
from tensorplay.nn.attention import omni_attention
```

## 自动微分

### `layer_norm` 反向改为保存统计量

`layer_norm` 现组合自 `native_layer_norm`（输出 + 每行 mean / rstd），autograd 节点保存
这两份统计量并由 `native_layer_norm_backward` 消费，反向不再从输入重算矩。六参
`layer_norm_backward` 算子保留但不再位于 autograd 路径上。

### `functional.jvp` 默认前向模式

`jvp(func, inputs, v)` 的 `mode` 默认值由 `"reversed"` 改为 `"forward"`：默认经
dual-tensor 引擎逐算子传播切向，不再依赖 double-backward 技巧；`mode="reversed"`
仍可用，`create_graph=True` 仍走反向路径。

## 导出

### 声明为 dynamic 的维度在捕获期保持符号

捕获过去把每个输入维度都按样例定死，于是 `dynamic_shapes={'x': {0: Dim('batch')}}`
下读 `x.shape[0]` 的程序被录成 `x + 2`，在任何非样例 batch 上都是错的；对该维度的分支
也只判一次就忘了条件。现在声明为 dynamic 的维度代表一个符号（ShapeEnv 区间，SymInt
携带样例作为提示），读它得到图值 `getitem(getattr(x, 'shape'), axis)`，其上的算术保持
符号；对符号做 Python 决定（分支、`int()`、`len()`、`range()`）按提示作答并留下守卫。
捕获后逐条校验守卫：区间蕴含的丢弃、只排除小于 2 的（如 `x.shape[0] != 1`）转成运行时
断言、落在具名 `Dim` 上的拒绝并给出 `refine_dynamic_shapes_from_suggested_shapes` 能
应用的修复、把 `Dim.DYNAMIC` 固定成一个尺寸的拒绝、其余（dim 提示）收窄并断言。
`dynamic_shapes` 现在先按可调用对象自己的参数归一化——模块带参数时，序列规格过去会
绑到第一个被提升的权重而不是第一个入参。

行为变化：`export(..., dynamic_shapes=...)` 在程序收窄或固定一个具名 `Dim`、或固定一个
`Dim.DYNAMIC` 维度时抛 `ConstraintsExceededError`，不再静默特化到样例尺寸。照提示改用
`refine_dynamic_shapes_from_suggested_fixes`、把该维度声明为 static，或用 `Dim.AUTO`
让导出自行特化。

### 计算值的形状按逐算子规则推导并落守卫

导出过去只知输入的维度范围，程序内部算出来的每个值都回读固定的样例形状，于是在动态
程序里对 `h.shape[0]` 分支、或据此 reshape 的地方把样例尺寸静默烤死。捕获现在在克隆
的样例值（克隆输入、缓冲区与常量；共享参数在就地写前克隆；随机生成器 fork）上跑每个
记录调用，经逐算子形状规则跨符号输入维度推导每个结果的范围，并与样例具体形状交叉校验；
规则在符号范围上做的决定成为守卫，导出为读输入形状的运行时断言；广播与 slice 钳位对
尺寸无关，不额外加守卫。没有规则、或尺寸由张量数据决定的算子给出程序可读但不可据以
分支的范围，并报出它来自哪里。

溯源记录程序从哪些输入读了固定范围；ONNX 导出器对这些轴上的 `dynamic_axes` 直接拒绝，
而不是导出一张在任何其他尺寸上都错的图，并在降级期间跳过运行时检查。

行为变化：

- 形状规则开始记录守卫：合并具名维度不同的输入（例如相加）抛
  `ConstraintsExceededError` 并给出建议修复；`Dim.AUTO` 程序为其假设的关系带上运行时
  断言。
- 以固定尺寸捕获后再做 ONNX 导出，若 `dynamic_axes` 标记的轴正是程序读过的轴，抛
  `ValueError`；请传模块本身（或声明 `dynamic_shapes`）而不是预导出的静态程序。
- 在前导维度固定的张量上迭代会展开；由动态维度定尺寸的则抛错。

```python
from tensorplay.export import export
from tensorplay.export.dynamic_shapes import Dim, refine_dynamic_shapes_from_suggested_fixes
```

## 内核契约

### 索引类算子契约与 ABI 对齐

- `index_put` / `index_put_` 的索引参数改为 `Tensor?[]`（可含 None）；C++ 调用方需传
  `std::vector<std::optional<Tensor>>`。
- `rrelu_with_noise` 的 noise 缓冲改为可变入参并接受 generator；`rrelu` / `rrelu_`
  接受 generator；`rrelu_with_noise_` 增加导数。
- 默认 `slice` 重载删除，统一走 `slice.Tensor`。
- stub 签名中拥有型参数（`Scalar`、`Tensor?`、`str`、列表）改为 const 引用传递；
  自定义算子内核声明随之更新。
- `out=` 变体统一经 `write_out`（resize + dtype/device 校验）写目标，不再重绑定目标。

## CUDA

### cuDNN benchmark 默认关闭

cuDNN benchmark 开关的默认值改为 `False`：默认取启发式首选配置，
避免每个新形状先实测多份候选计划（实测落到的引擎可能比启发式首选慢近两倍）。张量
描述符对齐度改为按存储地址计算（1..32 字节），不再写死 16。

### `unique` / 一维排序 / 三角掩码重写

- `unique` 按需计算逆映射与段长（此前 Python 层写死请求后丢弃）；不需要逆映射时只排键，
  不需要段长时走无游程表路径。
- 一维排序改走全局基数排序；`unique` 改为一趟 `UniqueByKey`，段表只随输出大小增长。
- `tril` / `triu` 三角掩码按列铺开到块内，窄行回退一行一线程。
- 数值保持逐位一致（76 组 unique 用例、119 组 sort 用例核验）。

### 跨维 softmax 竞态修复

dim 非最后一维的分块核在读出行最大值后缺少屏障，慢线程会在部分和写入后误读
`tile[0]`，导致整行被错误缩放（bf16 (512, 8192) dim=0 log_softmax 曾观测到单列误差
2.0）。现已在读最大值后补屏障；同时修复寄存器驻留核空 lane 的 `exp(-inf - -inf)`
产生 NaN 的问题，并把波形核行长上限调低。

## 前端

### 卷积 padding 改用模式词

`conv1d` / `conv2d` / `conv3d` 的 padding 参数接受 `'valid'`（不填充）与 `'same'`
（保留每个输出位置）。`'same'` 只在步长为 1 时存在，请求覆盖卷积核的触及范围，
奇数格留在尾部一侧；因逐轴计数对两侧对称，尾部多出的量预先补到输入前部，卷积
保留前部计数。其余取值仍按边界词解释并被拒绝。

### `block_diag` 落到原生内核

`block_diag` 的 Python 组合实现被原生内核取代（分块放置与周边零的分配都在操作数
所在设备上完成）；Python 结果 dtype 辅助函数改按 C++ 侧的次序排序操作数
（带维张量 > 0 维张量 > 普通数字，数字按其包装数类型计）；`meshgrid` 导出到包根。

# 新特性 New Features

## 注意力（omni_attention）

- `omni_attention` 可编程注意力入口：`score_mod`（五元坐标 `(score, b, h, q_idx, kv_idx)`
  任意表达式）与 `mask_mod` 谓词编程，`BlockMask` 块稀疏编译形态。
- 掩码工具：`create_block_mask` / `create_mask` / `and_masks` / `or_masks` / `noop_mask`。
- 输出选项：`return_lse`（对数求和指数）与 `return_aux`（反向复用辅助输出 `AuxOutput`）。
- eager 未融合回退实现（显式物化完整分数矩阵，运行时给出融合指引），`tp.compile`
  捕获后降级为融合内核。
- CPU 融合 flash 内核：查询轴分块 + BLAS gemm 分片、向量化行 softmax、跨 intra-op
  线程池并行，前向/反向均支持；query head 数可为 key head 的倍数，mask 可广播。
- CUDA 融合内核：fp32 flash 前向（3xTF32 tensor core，head 64）、混合精度 SDPA
  反向、宽 tile 双缓冲、按 query 长度选 tile、因果对角直接声明（非方形因果不再走
  组合路径）。
- 上下文并行（context parallel）集合算子与反向梯度规则，配套 `cplib::omni_cp_*`
  注册名。

## 现代解码栈（tensorplay.nn）

- **位置编码**：`RotaryEmbedding` 模块与函数式 `apply_rotary_emb`。
- **注意力模块**：`GroupedQueryAttention`（GQA）、`MultiheadLatentAttention`（MLA）。
- **线性注意力混合器**：`GatedDeltaNet` / `GatedRMSNorm`（gated delta rule）与
  `KimiDeltaAttention`，两者都提供 chunked 与 recurrent 两套规则函数
  （`chunk_gated_delta_rule` / `recurrent_gated_delta_rule`、
  `chunk_kimi_delta_rule` / `recurrent_kimi_delta_rule`）。
- **压缩稀疏注意力**：`CompressedSparseAttention`（窗口压缩器 + 闪电索引器）。
- **编解码器与块**：`CrossAttention` / `CausalEncoderDecoder`（CED 脚手架）、
  `SwiGLUMLP` / `TransformerBlock`。
- **KV 缓存**：`StaticCache`（预留定长）、`SlidingWindowCache`（滑窗 + 窗口长度查询）、
  `PagedCache`（分块分配、按需扩容）、`QuantizedCache`（int8 分组量化存取），
  与既有的 `DynamicCache` 共用 `Cache` 协议。
- **自回归生成**：`tensorplay.nn.generation.generate`，含 top-k / top-p 过滤
  （`top_k_top_p_filtering`）与重复惩罚。

## 频域与线性代数

- 原生多维 FFT 原语：`_fft_c2c` / `_fft_r2c` / `_fft_c2r`（不带归一化的多轴变换），
  `fft` / `ifft` / `rfft` / `irfft` 及其 `n` 维变体（`fftn` / `rfftn` / `irfftn`）与
  Hermitian 族（`hfft` / `ihfft` 及其 2 维 / n 维变体）直接建立在这三个原语上，
  不再由 Python 层递归分解。
- `fft` / `ifft` / `rfft` / `irfft` / `fft2` 系列与 `stft` 的反向全部可再求导。
- `linalg` 因子分解与求解器可微：`qr`、`lu_factor` / `lu_factor_ex` / `lu_solve`、
  `cholesky` / `cholesky_ex` / `cholesky_solve` / `cholesky_inverse`、`solve` /
  `solve_ex`、`solve_triangular`、`det`、`inv_ex`、`pinv`（含 atol/rtol 张量变体）。
- CUDA `lstsq` 走 `gels` 驱动（QR 分解，高 / 瘦 / 宽三种系统形态分别取路），残差从
  列主序工作缓冲读取。

## 编译器（tensorplay.compile / Stax）

- 注意力图→核降级：从捕获的注意力调用中识别 score/mask 语义，选择 flash 或逐位置
  生成的 CPU/CUDA 内核；`var` 走单趟 Welford 归约。
- AOT 收口：`partition_default` / `partition_min_cut` 分割后生成 C++ wrapper 并在
  运行时构建加载；`build` 产物可命名导出二进制位置与 launch 自述信息。
- CuteDSL 后端自研化：模板依赖替换为自有后端；`cutedsl` 内核编写、lane 分析、注意力
  模板覆盖。
- 调优体系：候选内核跨进程测量、决策持久化、`TUNING_VERSION` 决策盐、`bench_candidates`
  交错轮询抗噪；tunable 上下文经 `tensorplay.cuda.tunable` 暴露。

# 性能 Performance

测量方法均为静默机器 min-of-window；硬件标注于各条目。

- **CPU flash 注意力**（64×4×49×32 float32，20 线程）：前向 **0.24 ms**，前向+反向约
  **1.0 ms**（分块 + 线程池路径）。
- **编译耗时**：单次编译从 **11.3s 降至 1.3s**（图构建 O(n²) → O(n)）。
- **CUDA unique**：1M 元素 `0.60ms → 0.31ms`（按需计算逆映射/段长）；配合一维基数
  排序，unique 1M 由落后 **49.5x 收敛到 2.4x**；一维 sort 0.43ms。
- **三角掩码**（tril/triu）：2048×2048 由 **11.1x → 1.21x**，100000×8 由 **12.8x → 2.3x**。
- **外层维归约**：100000×256 沿 dim0 标准差 **4.1ms → 0.33ms**（多 CTA 拆分放开）。
- **直方图**：1M 元素 64 桶负载全局原子串行化 12.8x → 共享内存暂存后块尾发布。
- **cummax**：2048×2048 由 1.10x → **0.97x**（比较方向改编译期常量）。
- **嵌入梯度**：524288×64 落后 1.27x → 排序分段累加并双路径择优后领先。
- **融合优化器检查**：Adam/Adagrad 融合路径的 Python 指纹重建（约 0.4 ms/步）改为
  单次原生遍历检查布局。
- **fp32 注意力分数驻留片上**：32 batch × 32 head × 4096 token 调用省去分数矩阵三次
  片外往返（约 20 ms）。
- **非方形因果注意力**：此前落后 17x–183x 的调用改走融合路径。
- **cuDNN benchmark 模式**：同候选列表内择优比启发式首选快约 11%。
- **CUDA 归约引擎修订 14**（RTX 3090，CUDA event 测 7 组 × 100 次 C++ 归约启动的中位
  时间，单位微秒；完整测量记录见 `docs/cuda_reduction_optimizations.md`）：
  非对齐输入 float32 64M 元素 `318.657 → 309.954`（-2.7%）、half→float32 64M 元素
  `172.993 → 157.727`（-8.8%）；连续输出分组 float32 1048576×16
  `93.060 → 85.699`（-7.9%）、half→float32 `66.787 → 48.946`（-26.7%）。短归约
  half→float32 16384×128 从 `10.568 → 11.817`（+11.8%），非对齐路径的 1M 元素
  float32 测试无收益（`6.646 → 7.158`）——该轮数字只代表这些 dtype 与布局。
- **CPU 向量化与 channels-last 铺开**：AVX2 / AVX512 双层路径、tier-compiled 的
  channels-last 池化 / 上采样 / grid sampling 通道、max-pool 扫描致密化，
  以逐算子基准为准（未在本轮重测全表）。
- **排序与扫描**：超大排序分块并去掉小排序暂存、大张量平坦中位数走基数排序、
  `topk` 多块路径 tile 超 uint32 时回退、`cummax` 网格按设备 `maxGridSize` 封顶。

  toolkit 拿 CUDA 库的安装会在 libnvjpeg 上失败且不重试；现在按 nvrtc 一样预载它（可选，

  在导入之后被调用时预载会坏掉。
- **arm64 轮子**：修复 trunk CI 的 linux-arm64 与 macos-arm64 构建——`FindMKLDNN.cmake`

  的平台上直接中止 CMake generate），其无条件 `USE_MKL` 定义本会让 oneDNN 去拉不存在的
  MKL 头；`ReduceMomentsKernels.cpp` 无条件包含 `<immintrin.h>`；
  `ReductionKernelsImpl.cpp` 在无守卫的 dispatch 处调用 x86-only 的 leading-rows 帮助函数。
- **ISA 分层链接顺序**：AVX2/AVX512（VSX、ZVECTOR、SVE、RVV）的分发内核副本此前是对象库，
  CMake 会把它们排在 p10 自身对象之前（链接行与静态归档都是）。这类副本发射到线外的每个
  inline 函数或模板实例化都是弱定义、用该 tier 的 ISA 标志编译，而链接器保留它先遇到的那
  一个——在没有 AVX512 的 CPU 上，`dot()` 因此死在归约内核 AVX512 tier 里带出的
  `std::vector<float>` fill 构造的 AVX512 副本上（SIGILL）。改为把 ISA 副本作为 p10 自身
  的源（单行包装器）编译，并追加在所有其他 p10 源之后（含 tpx），从要求最低的 tier 起排；
  DEFAULT 副本是基线代码，保留其对象库。
- **轮子泄漏检查**：新增 `tools/check_isa_tier_leaks.py`，列出一个库里执行 AVX / AVX512
  指令却不属于 `CPU_CAPABILITY` tier 命名空间、也不在名字里标出 ISA 的弱函数——这种函数
  是赢下链接、绕过分发器直接跑的 tier 副本。在 `b460137e` 构建的轮子主干上它正好报出
  拖垮 nn-utils lane（SIGILL）的那个构造；现在每个 x86-64 Linux 轮子的 `libp10` 都跑它。
- **CI 稳定性**：托管 Linux CUDA 构建加 24 GB swap（16 GB 内存 / 3 GB swap 的 runner 上，
