# 亮点 Highlights

- **MetaX（MACA）后端首次发布轮子**：C500 上的 `tensorplay-1.3.0a0+maca330`
  走手动发布通道，独立于 CPU / CUDA / ROCm / MPS 矩阵。后端本身仍是树内实现
  （`-DUSE_METAX=ON` 复用 CUDA 源码），轮子只解决"拿到就能装"的问题，
  MACA SDK 由使用环境提供。
- **MetaX 后端量化收口**：逐算子性能矩阵从 9 个用例扩展到六个算子族，
  数值一致性、反向与量化回退全部补上可复现脚本与对照数据（见性能一节）。
  首次实测暴露一处前端缺陷：`relu` 带 `out=` 时多付一次整块拷贝。

# 新特性 New Features

### 内核 / 设备

- **MetaX 轮子变体**：新增 `+maca330` 本地版本标签，安装后
  `tensorplay.cuda` 直接指向 C500，设备名为 `MetaX C500`。
  与 CUDA/ROCm 轮子一样保持 `linux_x86_64` 裸平台标签——它依赖 MACA 运行时，
  不进 PyPI。

# 改进 Improvements

### 构建

- **Linux 轮子安装时剥离符号**：`libp10.so` 去掉 `.symtab` / `.strtab`
  后小 27.8 MB，设备镜像 `.mc_fatbin` 不受影响。Windows 的 DLL 维持不剥离。
- **版本文件每次构建重新生成**：此前规则以文件时间戳为依赖，同一棵树在两次
  构建之间切换检出点时不会触发，轮子会带上上一次构建写下的身份。

### 基准与验收

- `benchmark/bench_metax_ops.py` 覆盖逐元素、归约、激活、BLAS、卷积、
  attention 六个族，每个用例带族标签与派生速率；新增 `--device cpu`
  的主机计时，一个脚本即可给出设备/主机两侧数字。
- 新增 `benchmark/validate_metax_backend.py`：设备结果对 CPU float64 参考，
  覆盖 fp32/fp16/bf16/整型前向、conv2d/conv3d、融合 attention 与组合数学路径、
  逐元素/卷积/attention 反向、int8 量化回退，逐项给判定并以退出码汇总。

# 问题修复 Bug fixes

### 内核

- 协同张量编译器缺席时回退到通用路径，不再让该族算子整体不可用。
- GEMM 的 K 维分块改用 MPP 动态长度标记，避免固定长度假设在小 K 形状上越界。
- Metal 4 下协同张量内核的编译错误。
- ROCm 构建跳过扩展张量描述符，修复该路径的编译失败。
- 生成的 kernel 签名以全局命名空间为根，避免被外层命名空间捕获。

### 构建 / CI

- ROCm 兼容层补齐扩展批归一化的入口，并匹配非 const 的批归一化指针。
- ROCm 兼容层映射旧版卷积算法默认值。
- 版本生成器按发布标签匹配（`v1.2.0` / `v1.2.0-rc1`）。
- macOS 发布轮子固定到 macOS 26；各 macOS lane 迁出已退役的 `macos-14` 镜像。
- 恢复 trunk 的发布窗口闸门；修正设备验收 lane 的名称。
- 定时 nightly 对每个 main 提交只尝试一次。
- 关闭自动依赖升级。

# 性能 Performance

### CPU

- **窄头注意力路由**（#51）：`heads <= 4` 且 `head_dim <= 64` 时，阻塞式融合
  内核的可调度 tile 数不足以喂满线程池，改为物化后走组合路径；更宽的头布局
  保持融合内核。ViT-tiny/16 @384 的完整 attention block 从 **1.27x 慢** 变为
  **1.06x**。绑 8 个 P 核、8 线程实测，波动 <1%。

### MetaX C500

实测环境：MACA 3.3.0，fp32，50 次均值。完整数据见
`devdoc/analysis/metax-gap.md` 第七节。

| 族 | 用例 | ms | 派生速率 |
| --- | --- | ---: | ---: |
| 逐元素 | add / mul 16M | 0.144 / 0.143 | 1395 / 1405 GB/s |
| 逐元素 | exp / log 16M | 0.102 / 0.103 | 1313 / 1304 GB/s |
| 逐元素 | relu 16M（`out=`） | 0.270 | 498 GB/s |
| 归约 | sum / max 16M | 0.074 / 0.076 | 905 / 878 GB/s |
| 归约 | softmax 4096² | 0.113 | 1185 GB/s |
| 激活 | sigmoid / tanh / gelu / silu 16M | 0.102–0.105 | 1284–1315 GB/s |
| BLAS | mm f32 4096 | 4.691 | 29.30 TFLOP/s |
| BLAS | mm f16 4096 | 0.691 | 199.03 TFLOP/s |
| BLAS | bmm f32 8×1024×1024 | 0.720 | 23.85 TFLOP/s |
| 卷积 | conv2d 8×64×56×56 k3 | 0.122 | 15.21 TFLOP/s |
| attention | sdpa 2×8×1024×64 | 0.786 | 5.46 TFLOP/s |

逐元素与激活族都停在约 1.3 TB/s，已到该卡访存上限。`relu` 带 `out=` 只有
498 GB/s 是前端缺陷：`relu_kernel_cuda` 只有单参重载，`out=` 走
"算到临时张量再整块拷贝"，多付一次 64 MB 读 + 64 MB 写；不带 `out=` 时
是 0.103 ms，原地版 0.098 ms。

**数值一致性**（设备 vs CPU float64，按参考幅度归一）：fp32 全部 3.0–5.0e-08
（半个 ulp），fp16 4.1e-04、bf16 4.1e-03（各自半个 ulp），int32 精确，
conv2d/conv3d 5.0e-08/3.0e-08，融合 attention 与组合数学路径 4.2e-08。

**反向**：逐元素 3.9e-08、conv2d 中心差分 1.2e-03（受差分步长限制）、
sdpa 4.0e-08。

**量化回退**：int8 往返与 `quantized_matmul` 都落在半个量化步长，
设备输入走主机回退后语义不变。

**体积**：`libp10.so` 2.24 GB，其中设备镜像 `.mc_fatbin` 占 93.7%；
`-O2` 与 `-O3` 的产物只差 80 字节，压缩与降优化级别都不是杠杆，
真实杠杆是削减 dtype × 算子的实例矩阵。

# 开发者 Developers

- `benchmark/validate_metax_backend.py` 可在任何设备后端运行
  （`--device cuda|cpu`），逐项打印误差、容差与判定，退出码即结果。
- MetaX 手动发布流程：C500 上 `SKBUILD_BUILD_DIR=<既有构建目录>`
  复用已编译产物，`TENSORPLAY_BUILD_VERSION=<版本>+maca330` 打标签，
  `python -m build --wheel --no-isolation` 出包后 `gh release upload`。

# 安装 Installation

CPU / CUDA / ROCm / MPS 的安装方式不变。MetaX 轮子只在发布页提供，
需要自备 MACA SDK（3.3.0 验证）与 C500 驱动：

```bash
pip install tensorplay-1.3.0a0+maca330-cp312-cp312-linux_x86_64.whl
```

Python 3.10–3.13 中的 3.12 已验证；其余版本需在 C500 上重新构建。
